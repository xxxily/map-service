# KML 大规模容量与浏览器渲染基准（2026-08-27）

## 目的

验证 KML 点位聚合、文件解析、管理列表、浏览器首次渲染、连续缩放和隐藏分享文件按需加载的容量边界，并记录本轮密度阈值的默认参数。测试不改变 Leaflet 连续缩放、瓦片动画或 KML 功能完整性。

## 环境与方法

- 环境：macOS 本地工作站，Node.js `v24.18.1`；浏览器场景使用 Chrome `152.0.7977.64` 无头模式和真实 Leaflet 页面。
- Node 数据：规则分布的 Point，规模为 10、100、1,000、1 万、5 万、10 万和 20 万；另测 5,000 个混合点线面要素，以及 1、10、50、100 个 KML 文件。
- 浏览器数据：100 个 KML、共 10,000 个同时可见的混合点线面要素；分享页 40 个文件，其中 8 个默认显示、32 个默认隐藏；瓦片请求固定延迟 250 ms。
- 配置：`zoom=10`、`gridSize=64`、`minClusterPoints=250`、`maxMembersPerCluster=5000`。
- 指标：Node 场景各运行 3 次并记录最小值和中位数；浏览器场景记录管理列表就绪、首次完整图层渲染、连续滚轮缩放和快速跨级缩放的帧耗时、JS Heap 峰值、网络请求数和懒加载请求变化。
- 范围：Node 基准用于发现算法和解析数量级回退；浏览器基准用于暴露主线程与页面资源瓶颈。结果受工作站和浏览器版本影响，不作为所有设备的绝对性能承诺。

## 结果

### 点位聚合

| 点位数 | 聚合输出数 | 聚合中位耗时 |
| ---: | ---: | ---: |
| 10,000 | 3 | 3.03 ms |
| 50,000 | 3 | 17.08 ms |
| 100,000 | 6 | 21.43 ms |
| 200,000 | 12 | 53.71 ms |

10、100 和 1,000 点场景也纳入脚本回归，用于确认小规模数据不会因聚合策略引入异常固定开销。

### 混合要素与多文件

| 场景 | 数据量 | 生成中位耗时 | 解析中位耗时 |
| --- | ---: | ---: | ---: |
| 混合点线面 | 5,000 要素 / 1.60 MB | 10.11 ms | 54.46 ms |
| 1 个文件 | 100 要素 / 0.03 MB | 0.16 ms | 1.09 ms |
| 10 个文件 | 1,000 要素 / 0.33 MB | 1.60 ms | 10.19 ms |
| 50 个文件 | 5,000 要素 / 1.67 MB | 8.29 ms | 52.84 ms |
| 100 个文件 | 10,000 要素 / 3.34 MB | 16.48 ms | 105.27 ms |

- Node 完整基准进程最大常驻内存约 357.5 MiB；该值包含 20 万点、混合要素和多文件数据在同一进程中的累计驻留，不等同于单个浏览器页面峰值。
- 隐藏文件懒加载的请求模型为 1 次列表请求加当前可见文件的详情请求。同一文件的并发触发合并为 1 次详情请求；例如 100 个文件中 80 个隐藏时，首屏从 100 次详情请求降为 20 次，另外 80 次延迟到用户显示、展开、导出或批量操作时发生。
- 目录显示和批量选择采用最多 4 路详情加载；只有目录内全部文件成功后才统一修改显隐或选择状态，单文件失败不会造成部分提交。

### 真实浏览器容量

| 指标 | 实测结果 |
| --- | ---: |
| 100 文件管理列表就绪 | 2,784.80 ms |
| 10,000 个 KML 图层首次完整渲染 | 2,785.70 ms |
| 连续滚轮缩放 p95 / 最大帧耗时 | 650.10 ms / 1,000.00 ms |
| 快速跨级缩放 p95 / 最大帧耗时 | 383.40 ms / 383.40 ms |
| JS Heap 峰值 | 346.84 MiB |
| 本地页总请求 / 瓦片请求 | 404 / 279 |
| 分享首屏详情请求 | 8 |
| 展开 1 个隐藏文件后的详情请求 | 9 |
| 再显示 1 个隐藏文件后的详情请求 | 10 |

- 40 个分享文件只有 8 个默认显示，因此首屏仅请求 8 份详情；展开隐藏文件时增加 1 次详情请求但仍保持隐藏，随后显示另一个隐藏文件再增加 1 次请求。
- 100 个文件与 10,000 个要素均完整可达、完整渲染，没有通过固定数量窗口省略文件或要素。
- `zoomAnimation`、`fadeAnimation`、`markerZoomAnimation` 三项最终生效配置均为开启；慢瓦片下仍保留旧层级画面过渡。
- 浏览器门槛用于阻断灾难性回退：连续与快速缩放 p95 均不得超过 750 ms，JS Heap 峰值不得超过 900 MiB。这个门槛是回归报警线，不代表当前体验已经流畅。

## 结论与边界

- 纯聚合计算在 20 万点规模的中位耗时约 54 ms；100 文件解析约 105 ms，算法和解析不是当前首要瓶颈。
- 10,000 个未聚合且同时可见的 Leaflet 图层已经暴露明显主线程瓶颈：首次完整渲染约 2.79 秒，连续滚轮缩放 p95 约 650 ms、最大单帧约 1 秒。该规模可完整加载和操作，但不能认定为流畅；当前本地未聚合容量上限应保守控制在明显低于 10,000 个同时可见图层。
- 隐藏分享文件首屏不再下载详情；显示、展开、聚焦、下载或目录批量显示时才加载，从网络与解析阶段减少无效工作。
- 管理员强制策略默认在缩放级别 12 及以下、单网格达到 250 个点时生效；稀疏区域仍保留独立点位，不裁剪任何要素。
- 分享场景的大规模点位应优先依赖用户开关或管理员强制聚合策略降低同时挂载图层数；线段和面仍完整保留，不参与点位聚合，也不静默裁剪。
- 当前自动门槛为：20 万点聚合、5,000 混合要素生成/解析、100 文件生成/解析中位耗时均低于 1,500 ms，其中聚合单独要求低于 750 ms；浏览器连续/快速缩放 p95 低于 750 ms、JS Heap 峰值低于 900 MiB，并保持三项 Leaflet 动画开启。门槛用于发现数量级回退，不代表目标耗时。
- 161 内测继续重点覆盖低性能移动设备、多个大文件按需加载、点线混合渲染和连续滚轮缩放；后续优化仍须以完整功能、准确总数和连续缩放画面为硬约束。

## 复现

```bash
npm run perf:kml
```

该命令依次执行 Node 容量基准、真实 Chrome/CDP 浏览器基准和相关回归测试；不新增浏览器自动化依赖。
