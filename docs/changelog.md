- canvas 聚焦时支持方向键平移与 `+`/`-` 缩放；`VITE_MAP3D_CAMERA_PROFILE=compatibility` 可独立关闭增强绕点/倾角并保留稳定平移/缩放，不影响地形、KML 或辅助线。

## 1.4.46 - 2026-07-12

### 优化轨迹视口重渲染性能，消除移动地图时的顿挫感

- **问题背景**：1.4.45 扩大预渲染范围至 3x 后，视口变化时重渲染的数据量增大，导致移动地图时出现明显顿挫感。
- **根因分析**：
  1. **无缓存机制**：每次 `moveend` 都执行完整的 removeKmlLayers + 重新创建所有图层，即使在已渲染的缓冲区域内也重复渲染。
  2. **3D 事件过于频繁**：使用 `camera.changed` 事件，该事件在相机移动过程中持续触发（而非移动结束后），导致 debounce 计时器不断重置，最终在移动过程中触发重渲染。
  3. **requestAnimationFrame 阻塞绘制**：重渲染在 rAF 回调中执行同步重活，阻塞了浏览器绘制下一帧。
  4. **面板 UI 不必要更新**：每次视口重渲染都调用 `updateKmlPanelUI`，触发 DOM 重建。
  5. **debounce 实际仍为 200ms**：上一版只改了注释未改代码值。
- **优化方案**：
  - **视口缓存跳过**：新增 `lastRenderedViewportBounds` / `lastRenderedCamLat3d` 等缓存变量，记录上次渲染时的视口范围。若当前视口仍在上次渲染的 3x 缓冲范围内且缩放级别变化不超过 1 级，直接跳过重渲染。大部分小幅平移不再触发任何工作。
  - **3D 改用 `camera.moveEnd`**：从 `camera.changed`（移动中持续触发）切换到 `camera.moveEnd`（移动结束后触发），与 2D 的 `moveend` 行为一致，彻底消除移动过程中的不必要回调。
  - **`setTimeout(0)` 替代 `requestAnimationFrame`**：让浏览器先完成当前帧绘制，再在下一个事件循环中执行重渲染，避免阻塞绘制导致掉帧。
  - **跳过面板 UI 更新**：视口触发的重渲染不再调用 `updateKmlPanelUI`，避免不必要的 DOM 操作。面板 UI 在其他交互路径（开关、编辑等）中仍正常更新。
  - **debounce 调整为 150ms**：配合缓存跳过机制，150ms 足以合并连续事件，且不会在缓存未命中时造成明显延迟。
- **效果**：小幅平移完全不触发渲染（缓存命中跳过）；大幅平移在移动停止后 150ms 内异步渲染，不阻塞绘制。

## 1.4.45 - 2026-07-12

### 优化轨迹视口动态渲染的预渲染范围和响应速度

- **优化背景**：用户反馈移动视口时能明显感知到点位和线的渲染过程，体验不够流畅。
- **优化方案**：
  - **扩大渲染缓冲区**：`VIEWPORT_BUFFER_RATIO` 从 1.5 提升到 3.0，即渲染范围为当前视口的 3 倍，预渲染视口外 1 倍的区域，用户在正常平移时不会触发新的渲染。
  - **缩短 debounce 时间**：KML 图层视口变化重渲染的 debounce 从 200ms 降低到 80ms，让重渲染更及时。
  - 两项优化配合，使用户在平移视口时几乎无感知：缓冲区足够大，平移后新进入视口的数据已在缓冲区内提前渲染好；即使触发重渲染，80ms 的延迟也几乎不可察觉。

## 1.4.44 - 2026-07-12

### 修复持续定位时历史记录只剩最近一次的问题

- **问题根因**：1.4.41 版本将视口过滤 + LOD 应用到了 `renderHistoryPoints`（直接 circleMarker 渲染），导致持续定位时 `map.setView` 将地图居中到当前位置后，之前的历史点全部落在视口外被过滤掉，用户只能看到 1 个点，误以为历史记录丢失。
- **修复方案**：
  - `renderHistoryPoints` / `renderHistoryPoints3d` 恢复为 `slice(-N)` 策略（上限 500），不再应用视口过滤和 LOD。
  - 视口过滤 + LOD 仅保留在 KML 图层（`renderKmlLayers`）中，因为 KML 图层包含大量 LineString 和 Point 要素，是性能瓶颈所在。
  - 移除了 `location.js` / `map3d/location.js` 中冗余的视口变化监听器（`scheduleViewportRerender2d/3d`），因为直接 circleMarker 不需要按视口重渲染。
  - KML 图层的视口动态重渲染由 `kml.js` / `map3d/kml.js` 自身的监听器独立处理（1.4.43 已修复）。
- **影响范围**：2D（Leaflet）和 3D（Cesium）均修复。

## 1.4.43 - 2026-07-12

### 彻底修复视口移动后轨迹不动态渲染

- **问题根因**：1.4.42 版本的修复未生效，因为视口变化监听器只在 `startIntervalLocation` 期间注册、`stopIntervalLocation` 时注销，且有 `intervalLocationState.active` 前置条件。查看已保存轨迹时（非活跃定位期间）**根本没有监听器**，所以平移/缩放后 KML 图层不会重渲染。
- **正确修复方案**：将视口变化监听器从定位模块移至 KML 模块自身：
  - `kml.js` 的 `initKmlSupport(map)` 中注册 `map.on('moveend zoomend', scheduleKmlViewportRerender)`，在页面初始化时即生效，不依赖定位生命周期。
  - `map3d/kml.js` 的 `initKmlSupport3d(viewer)` 中注册 `viewer.camera.changed.addEventListener(scheduleKmlViewportRerender3d)`。
  - 新增 `scheduleKmlViewportRerender` / `scheduleKmlViewportRerender3d` 函数，debounce 200ms + rAF，仅重渲染 `isLiveTrack && enabled` 的 KML 文件。
  - 从 `location.js` / `map3d/location.js` 的视口 handler 中移除冗余的 KML 重渲染调用，避免双重渲染。
  - 移除不再需要的 `rerenderTrackKml2d` / `rerenderTrackKml3d` 导出函数。

## 1.4.42 - 2026-07-12

### 修复视口移动后轨迹线和点不动态渲染

- **问题背景**：1.4.41 版本实现视口过滤 + LOD 后，视口变化时仅重渲染了直接历史定位点（circleMarker / billboard），未重渲染 KML 图层（轨迹 LineString 和点要素），导致平移/缩放后视口内的线和点需要刷新页面才出现。
- **修复方案**：
  - 在 `kml.js` / `map3d/kml.js` 中新增 `rerenderTrackKml2d` / `rerenderTrackKml3d` 轻量级函数，仅按当前视口重新过滤和渲染已有 KML features，不重新生成数据。
  - 在 `scheduleViewportRerender2d` / `scheduleViewportRerender3d` 的 rAF 回调中，除调用 `renderHistoryPoints` 外，同时调用 `rerenderTrackKml2d` / `rerenderTrackKml3d`，确保视口变化时 KML 图层（线 + 点）也按需重渲染。
  - 面板 UI 同步更新显示过滤后的要素数量。
- **影响范围**：2D（Leaflet）和 3D（Cesium）均修复。

## 1.4.41 - 2026-07-12

### 轨迹渲染视口过滤与 LOD 分级优化

- **问题背景**：持续定位轨迹渲染原采用固定截断策略（120 点 + 2000 线顶点），长途行驶 30 分钟即超限，旧轨迹点从地图消失，轨迹线被大幅抽稀失真。
- **优化方案**：将固定截断替换为视口过滤 + LOD 分级 + 硬上限三重控制：
  - **视口过滤**：只渲染当前可见范围（含 1.5x 缓冲区）内的轨迹点，视口外不创建图层。
  - **LOD 分级**：根据缩放级别动态调整渲染密度——低缩放（0-7）仅显示线轮廓不显示点；中缩放（8-12）稀疏点 + 中等线密度；高缩放（16+）全密度渲染。
  - **硬上限**：视口内最多渲染 500 个点 + 5000 个线顶点，防止 GPS 密集抖动时性能崩溃。
- **视口变化按需重渲染**：2D 监听 `moveend/zoomend`，3D 监听 `camera.changed`，200ms debounce + rAF 节流，平移和缩放时自动重渲染可见区域。
- **数据完整性**：存储层、KML 导出和面板列表的数据不受影响，导出仍包含全部记录。
- **向后兼容**：`getTrackDisplayFeatures` 不带视口参数时退化为旧逻辑。
- **测试覆盖**：新增 30 个自动化测试覆盖 LOD 配置、视口过滤、线顶点抽稀、硬上限和向后兼容性。
- **需求文档**：详见 `docs/requirements/track-rendering-viewport-lod.md`。

## 1.4.40 - 2026-07-12

### 修复搜索与路线规划输入提示失效

- **问题现象**：在 2D 和 3D 地图中输入搜索关键字或路线起终点时，高德 AutoComplete 联想提示完全无响应；路线规划、逆地理编码等依赖高德 REST API 的功能均受影响。
- **根因**：提交 `50a2037`（1.4.34）为防止地图 URL 中的坐标状态通过 Referer 泄露，在服务端中间件和 HTML meta 标签中同时设置了 `Referrer-Policy: no-referrer`。该策略导致浏览器对所有跨域请求（包括高德 `restapi.amap.com`）均不发送 Referer 头，而高德 JSAPI 的 `inputtips` 等接口依赖 Referer 做域名白名单校验，未收到 Referer 时返回 `INVALID_USER_DOMAIN`（infocode: 10006），直接拒绝服务。
- **修复方案**：将 `no-referrer` 调整为 `strict-origin`。`strict-origin` 仅发送 origin（协议+域名+端口），不发送完整路径和查询参数，既满足高德域名校验需求，又不会泄露 URL 中的坐标等敏感状态信息。
- **改动范围**：`service/index.js` 服务端中间件响应头、`index.html` / `3d.html` 的 `<meta name="referrer">` 标签，以及对应构建产物。

## 1.4.33 - 2026-07-11

### 持续定位可靠性

- **修复长途高速移动后永久断更**：原 2D/3D 实现把相对最后一个已接受点超过 200 米的位置一律判为漂移。默认 15 秒间隔下，该阈值只允许约 48 km/h；高速行驶、出隧道或后台恢复后会持续拿旧锚点拒绝所有新位置，手动重启清空锚点后才恢复。现改为结合采样时间、定位精度和最高 500 km/h 的动态阈值，并通过两个相互一致的新样本安全重定基准。

- **定位源超时与降级**：高德和浏览器单次定位增加应用层硬 deadline，防止 SDK 不回调造成 Promise 永久悬空；高德失败或无效坐标会降级浏览器定位，连续失败进入有限 cooldown，所有回调保留原始时间戳和错误码。

- **保活竞态修复**：2D/3D 共用幂等保活控制器，处理 Wake Lock 申请中停止、系统自动释放、前台重取和音视频资源清理，避免停止后迟到的 Wake Lock 继续保持屏幕常亮。

## 1.4.4 - 2026-07-08

### 前端

- **引入标准 Screen Wake Lock API 阻止屏幕变暗/自动休眠**：
  - **背景**：原先的静音 WAV 音频机制能够有效防止 JS 线程后台挂起挂起，但在多数移动端浏览器（Safari/Chrome）上，音频播放无法直接阻止屏幕暗屏或由于系统超时引起的自动锁定休眠。
