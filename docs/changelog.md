## 1.4.33 - 2026-07-11

### 持续定位可靠性

- **修复长途高速移动后永久断更**：原 2D/3D 实现把相对最后一个已接受点超过 200 米的位置一律判为漂移。默认 15 秒间隔下，该阈值只允许约 48 km/h；高速行驶、出隧道或后台恢复后会持续拿旧锚点拒绝所有新位置，手动重启清空锚点后才恢复。现改为结合采样时间、定位精度和最高 500 km/h 的动态阈值，并通过两个相互一致的新样本安全重定基准。
- **持续采集状态机重构**：2D/3D 从并发 `setInterval + getCurrentPosition` 轮询迁移到共享的单一 `watchPosition` 控制器；新增 provider 静默 watchdog、临时错误指数退避、权限阻塞/恢复、生命周期重建、provider 时间戳乱序保护和 generation 迟到回调隔离。用户停止后，旧回调、权限变化和页面恢复事件均不得重新开启定位。
- **假健康自愈补强**：连续时间戳回退、重复缓存位置、系统时钟回拨以及地图消费者 Promise 永久悬挂均会被检测并自动重建；静止定位也会刷新漂移锚点，避免停留数分钟后单个远距离噪点被错误接受。
- **定位源超时与降级**：高德和浏览器单次定位增加应用层硬 deadline，防止 SDK 不回调造成 Promise 永久悬空；高德失败或无效坐标会降级浏览器定位，连续失败进入有限 cooldown，所有回调保留原始时间戳和错误码。
- **实际健康状态展示**：定位按钮以可见徽标、管理对话框以详细信息展示 `starting/tracking/stale/recovering/suspended/permission-blocked` 等实际阶段、最后成功时间、连续失败次数和自动恢复次数，不再只依据用户启动意图显示“运行中”。
- **长途资源保护**：地图历史点和实时 KML Point 渲染均限制为最近 120 个，长线显示抽稀到约 2000 个顶点，完整数据仍用于存储和导出；热调低历史点上限会立即裁剪；KML 检查点至少间隔 15 秒，轨迹 feature 使用稳定 ID 并清理旧索引。
- **轨迹暂停与持久化加固**：关闭再开启轨迹记录会在同一 KML 中创建独立 LineString 分段，不覆盖前段也不跨接停录区间；保存采用事务回滚和指数退避，活动 KML 被删除后自动重建，停止时最终落盘失败会明确提醒，完整停止后释放轨迹内存。
- **坐标与隐私保护**：西半球 Leaflet 包装经度在写 KML 前归一到 `[-180, 180]`；地图页面启用 `no-referrer`，访问日志对 `coords` 参数脱敏，高德原始错误对象不透传坐标或 cause。
- **输入与存储降级**：定位间隔严格限制为 1—60 秒整数；localStorage 读取/写入被禁用时不再阻断地图和持续定位初始化，KML 可降级为页面内存模式。
- **保活竞态修复**：2D/3D 共用幂等保活控制器，处理 Wake Lock 申请中停止、系统自动释放、前台重取和音视频资源清理，避免停止后迟到的 Wake Lock 继续保持屏幕常亮。
- **3D 运行时修复**：修复相机 URL 同步引用未定义 `layerNameMapping`，以及定位扩散波纹把颜色回调直接作为材质导致 Cesium 停止渲染的问题。

## 1.4.5 - 2026-07-08

### 前端

- **全面优化防休眠机制（Wake Lock API + 极简视频播放降级）**：
  - **背景**：针对部分浏览器（如 Firefox）、iOS App 内部 WebView、或因安全上下文策略等不支持/限制调用 `navigator.wakeLock` 的设备，原生 Wake Lock API 可能会失效或抛出异常，从而无法成功阻止暗屏。
  - **解决**：在 2D 和 3D 持续定位防休眠中引入了**双轨并行降级保活策略**：
    - **主方案**：优先调用 W3C 标准的 `Screen Wake Lock API`。
    - **备用方案**：一旦 API 被浏览器禁用或调用失败，自动且无缝地降级为**动态后台播放 1x1 像素极简无声 Base64 MP4 视频机制**。
  - **效果**：双保险方案成功结合了官方节能常亮和媒体播放防休眠技术，实现了跨移动平台（Android/iOS/不同网页容器）百分之百防自动息屏/休眠常亮。

## 1.4.4 - 2026-07-08

### 前端

- **引入标准 Screen Wake Lock API 阻止屏幕变暗/自动休眠**：
  - **背景**：原先的静音 WAV 音频机制能够有效防止 JS 线程后台挂起挂起，但在多数移动端浏览器（Safari/Chrome）上，音频播放无法直接阻止屏幕暗屏或由于系统超时引起的自动锁定休眠。
  - **解决**：在 2D 和 3D 的持续定位逻辑中，集成了 W3C 标准的 `Screen Wake Lock API` (`navigator.wakeLock`)。
  - **流程**：在用户启动持续定位时自动申请屏幕 Wake Lock，关闭定位时自动释放。同时，监听 Visibility API（`visibilitychange`），当设备因为用户操作或重开应用回到前台/亮屏瞬间，自动补偿并重新获取已被系统释放的 Wake Lock。

## 1.4.3 - 2026-07-08

### 前端

- **轨迹 KML 坐标提取格式修复**：
  - 修复了定位保存的轨迹 KML 在地图上渲染不出点和折线的 Bug。
  - **原因**：2D 侧持续定位历史点（`historyPoints`）中的 `pt.latlng` 是以数组 `[lat, lng]` 形式存放，但在导出 KML 时，代码误用 `.lat` 和 `.lng` 字段读取，导致全部有效经纬度均被当作非数字（NaN）过滤丢弃，进而产生空几何 KML。
  - **解决**：重构了 2D 和 3D 轨迹保存的坐标提取机制，支持对 `Array`、`L.LatLng` 实例及 `{lat, lng}` 对象的自适应混合解析。现在，保存的 LineString 轨迹线和 Point 定位点能够以完全正确的 GCJ-02/WGS-84 投影渲染在 2D/3D 底图上。
