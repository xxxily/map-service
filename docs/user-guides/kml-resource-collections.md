# KML 资源集合使用说明

资源集合有两种管理方式：内嵌集合继续跟随 KML 保存；独立集合在个人空间维护，点位只保存集合 ID 或外部数据接口地址。独立集合采用实时（`live`）读取，集合内容更新后，所有引用点位下次打开即生效。

## 个人空间管理

登录后打开个人空间的“资源集合”Tab。列表显示名称、公开状态、活动/回收站状态、项数、更新时间和引用数量，支持搜索、状态筛选、排序和分页。打开列表项可编辑基本信息、默认列表/卡片视图、资源项标题、地址、类型、封面和顺序。

集合默认是“私有”。开启“允许公开读取”后，持有集合 ID 或通过已授权分享访问的用户可以读取名称、项标题、媒体地址和当前内容；关闭公开、移入回收站或恢复集合后会立即重新判定权限，恢复默认回到私有。永久删除前必须先移入回收站并通过密码二次验证；只要 KML/分享来源仍保留引用，即使引用索引处于回收或待修复状态也会被阻止。

集合项按页加载，默认每页 40 项；批量新增、更新、删除在服务端整批事务中执行。保存集合基本信息使用 `revision`，项编辑和排序使用 `itemsRevision`；发生版本冲突时应重新加载后再提交，不会静默覆盖其他设备的修改。

## 在点位中绑定

1. 新增或编辑 Point，将点位类型切换为“资源集合”。
2. 选择来源：
   - “内嵌数据”：使用原有编辑器，最多 300 项、512 KiB，内容写入 KML。
   - “个人资源集合”：从个人集合列表中选择，点位保存 `resourceCollectionRef.collectionId`，不复制集合项。
   - “外部数据接口”：填写 HTTPS `dataUrl`，保存安全引用，数据由第三方系统维护。
3. 可设置引用显示名称和列表/卡片视图。选择后可打开集合管理、替换集合或解除绑定。

个人集合 ID 引用只授予当前账号的管理能力；“公开”只代表读取权限，不自动授予编辑权限。外部地址不得包含账号、密码、Token 或敏感查询参数，不允许 localhost、内网主机和非默认端口。浏览器读取外部接口时不发送 Cookie、Authorization 或其他凭证，是否允许跨域由外部系统的 CORS 策略决定。

## 查看与分页

地图、3D、SidePanel 和分享页加载 KML 时只读取点位和引用摘要。点击点位并打开集合面板后，才读取元数据和当前页项；面板显示当前页、准确总数或“数量未知”，提供上一页/下一页、重试和空状态。切换点位或页码会取消旧请求，旧响应不会覆盖新页面。图片按可见区域懒加载，视频、音频和页面在打开预览时才创建播放器。

个人来源读取失败时会显示“集合未公开”或“集合不存在/已删除”；分享访客不会看到私有集合的名称、项数、ID 或地址。外部接口的 401/403、CORS 拒绝、超时、重定向、非法 JSON 和超大响应分别显示无权限、超时、格式错误或超限状态，地图其他点位仍可用。

## 分享、导入与导出

分享 KML 时只发布 `resourceCollectionRef`，不复制独立集合项，也不冻结集合版本。公开个人集合在分享作用域内按页读取最新数据；私有、回收或缺失集合显示不可用状态。外部引用继续由访客浏览器直读，分享系统不代替外部权限控制。

标准 KML 使用 `map-service:resource-collection-ref` 扩展保存独立引用，使用 `map-service:resource-collection` 保存内嵌集合。导出不会写入集合项快照、所有者信息或凭证。导入未知版本或非法引用时保留 Point 几何并在 warning 中说明；同账号且未修改引用时可保留 unresolved 状态，用户可重新选择本地集合、转为内嵌（需满足 300 项/512 KiB）或移除引用。

## 常见状态

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| `ready` | 已取得当前页 | 浏览、翻页或预览 |
| `private` | 个人集合未公开 | 所有者可调整公开设置；访客无法读取 |
| `missing` | 集合不存在、回收或分享引用失效 | 检查集合状态或替换引用 |
| `unauthorized` / `forbidden` | 外部接口或分享授权不足 | 检查外部权限、CORS 或分享访问 |
| `invalid_schema` | 外部响应不是版本 1 JSON | 修正第三方接口结构 |
| `too_large` | 单页或完整数组超过安全上限 | 使用分页接口并降低响应大小 |
| `timeout` / `server_error` | 外部接口暂时不可用 | 稍后重试，不会修改 KML |

相关接口详见 [API 参考](../api.md) 和 [用户体系与多 KML 分享 API](../api-user-system.md) 中的资源集合章节。
