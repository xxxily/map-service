# 两步路导入助手用户操作手册

> 适用版本：map-service 两步路导入助手 `0.4.0` 及以上
> 更新时间：2026-08-30

## 1. 使用条件

- 使用 Chrome 或兼容 Manifest V3 的 Chromium 浏览器。
- 已按扩展 README 加载 `extensions/two-bulu-helper/`，并在扩展选项页授权当前 map-service 完整 origin。
- 已登录 map-service，账号具备个人 KML 写权限。
- 待导入链接是两步路官方 HTTPS 公开轨迹分享页。

未登录、账号只有查看权限、扩展未安装或当前站点未授权时，“从两步路导入”入口不会显示。普通本地 KML 导入不受影响。

## 2. 首次安装或更新

1. 打开 `chrome://extensions/`，开启“开发者模式”。
2. 首次安装时点击“加载已解压的扩展程序”，选择项目中的 `extensions/two-bulu-helper/`。
3. 已安装旧版本时，在“map-service 两步路导入助手”卡片点击“重新加载”，确认版本为 `0.4.0`；新版卡片和工具栏会显示青绿色“轨迹双节点 + 导入箭头”图标。
4. 打开扩展“详情”中的“扩展程序选项”，确认当前 map-service origin 已授权。
5. 刷新 map-service。若两步路页面已打开，也一并刷新，确保新内容脚本生效。

## 3. 从地图页导入

1. 登录 map-service，打开 2D 地图的“KML 数据管理”面板。
2. 点击“从两步路导入”，粘贴公开分享链接。
3. 根据需要选择坐标纠偏和数据不完整策略，点击“读取并导入”。
4. 扩展会打开或复用一个由扩展管理的可见两步路标签页，并显示导入状态卡片。
5. 页面已正常显示轨迹、点位和媒体时，无需手工切换标签页；扩展会读取页面数据，map-service 会在后台完成安全校验和保存。
6. 保存成功后，浏览器会自动返回原地图标签页，并关闭扩展管理的未固定两步路临时页。地图会展开新 KML，并自动适配轨迹和点位范围。包含多条线段时会全部显示；未命名点位默认不显示名称，只显示图标。

导入完成后，助手会尝试读取分享页右侧的“总里程”“运动耗时”和“原作者”。已读取到的字段会写入 KML 文件级信息介绍；在地图 KML 面板展开文件后，查看“KML 详情”区块即可看到介绍和要素统计。两步路页面缺少某个字段时只显示其余字段，不会阻断轨迹导入。

旧版助手已经导入的 KML 不会自动补齐统计信息或缺失的轨迹线；需要重新加载 `0.3.8` 扩展并再次导入对应分享链接。

## 4. 从“我的 KML”导入

1. 打开账号中心的“我的 KML”。
2. 点击“从两步路导入”，完成与地图页相同的链接和策略选择。导入会合并页面上的全部独立线段，并忽略地图图层生成的序号或系统标题；只有原始用户命名才会保存为点位名称。
3. 保存成功后自动返回原账号中心标签页，列表刷新后可继续编辑、导出或创建分享。

## 5. 从两步路用户轨迹列表批量导入

1. 在“我的 KML”或地图页 KML 面板选择“从两步路批量导入”。
2. 粘贴用户公开轨迹列表链接，例如 `https://www.2bulu.com/spaceindex/my_track.htm?userId=...`，填写需要的点位数量、发布时间、里程、点赞和收藏筛选条件，并选择排序字段和方向。
3. 助手会在可见的两步路页面读取公开轨迹链接和页面已展示的统计字段，网站显示识别数量、筛选后的数量和逐条摘要。字段缺失只会显示警告，不会伪造统计值。
4. 确认后按预览顺序逐条导入。文件默认放入以列表页用户昵称命名的 KML 目录；已有同名目录会复用。
5. 普通单条轨迹失败不会删除已成功文件；权限、配额、登录/验证码/WAF、助手不可用或用户关闭两步路标签页等批次级错误会停止剩余条目，完成后显示成功、失败和取消数量。

## 6. 遇到登录、人机验证或页面未加载完成

扩展不会自动登录、处理验证码或绕过 SafeLine/WAF。出现这些情况时：

1. 在当前两步路页面自行登录或完成人机验证。
2. 等待地图、轨迹线、点位和媒体全部显示。
3. 点击状态卡片中的“返回 map-service”。
4. 在原入口使用相同链接重新发起导入。站内业务 `requestId` 会在成功确认前复用，避免响应丢失时重复创建文件。

如果页面只能确认轨迹线，默认策略会拒绝导入。确认可以接受缺少点位或媒体后，可重新选择“允许仅导入公开轨迹线”。

## 7. 标签页和结果反馈规则

- 导入成功：优先激活原 map-service 标签页，再关闭扩展管理的临时两步路页。
- 保存失败：不自动关闭两步路页，状态卡片显示失败摘要，可选择“返回 map-service”“关闭此页”或“收起提示”。
- 原 map-service 页已关闭：不会强制关闭两步路页，卡片会提示无法自动返回。
- 两步路页已固定：固定页不会自动关闭，但仍会返回原 map-service 页；需要时可在卡片中手工关闭。
- 用户自行打开的两步路页：扩展不会搜索、接管或关闭。只有扩展自己创建或登记管理、且标签页归属校验通过的页面可被自动关闭。
- 用户在读取过程中主动关闭两步路页：本次导入取消，不创建空 KML。

## 8. 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 看不到“两步路导入”按钮 | 检查登录状态、个人 KML 写权限、扩展是否启用、当前 origin 是否授权，并刷新页面 |
| 一直停留在“正在读取” | 等待轨迹完整显示；检查是否存在登录、验证码或 SafeLine 提示 |
| 提示未识别页面数据 | 刷新两步路页并等待线、点和媒体加载完成，再返回 map-service 重试 |
| 导入成功但临时页没关闭 | 检查标签页是否固定、原 map-service 页是否仍存在；可使用状态卡片“关闭此页” |
| 点击“返回 map-service”失败 | 原发起标签页可能已关闭，请手动重新打开 map-service |
| 更新后行为仍是旧版 | 在 `chrome://extensions/` 重新加载扩展，并刷新 map-service 与两步路页面 |
| 轨迹只有线没有点位 | 默认拒绝；确认接受后选择“允许仅导入公开轨迹线”重新导入 |
| 导入结果只有点位没有路线 | 在 `chrome://extensions/` 重新加载并确认助手为 `0.4.0`，刷新两步路页面后重新导入；新版不会保存缺少有效轨迹线的结果 |
| KML 详情没有某项统计 | 两步路分享页可能未公开该字段；刷新并等待右侧基本信息完整显示后重试，已读取到的其他字段仍会保留 |

## 9. 隐私与安全说明

扩展不会把两步路 Cookie、账号、密码、Token、验证码或 Authorization 发送给 map-service。它只在用户浏览器内读取当前公开分享页已经展示的轨迹、点位和公开媒体元数据，组装为标准 KML；map-service 服务端仍会重新执行登录、CSRF、权限、URL、XML、坐标、大小、配额和幂等校验。
