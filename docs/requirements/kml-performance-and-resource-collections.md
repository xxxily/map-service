# KML 性能优化与资源集合点位

> 本文是 v1“内嵌资源集合”的实施基线。独立个人集合、Point 引用、外部数据接口和按需分享扩展见[独立资源集合、引用绑定与按需加载需求](./kml-resource-collection-references.md)；本文中的 `resourceCollection`、300 项和 512 KiB 约束继续有效。

状态：v1.5.58 已实现，待 161 内测验收

## 1. 背景与目标

`177.kml` 约包含 110 个点位、1 条含 1,034 个坐标的线段和 90 余个媒体链接。当前在 2D 地图连续缩放、从 KML 管理列表定位点位、打开媒体详情时会出现明显延迟。目标是在不降低既有 KML 编辑、分享、只读浏览和 3D 兼容性的前提下：

1. 降低普通 KML 的首屏和交互热路径开销，支持同时加载 2～3 个同量级文件。
2. 取消由固定动画等待、重复媒体解析和无界 DOM 导致的交互阻塞。
3. 增加“资源集合点位”，让一个空间点按列表或卡片管理大量相关资源，并复用统一媒体预览器。
4. 在资源数量增长时采用按需加载、窗口化渲染和明确的卸载策略，避免集合内容影响地图整体性能。

## 2. 范围与非目标

### 2.1 本期范围

- 2D Leaflet KML 点位、线段渲染与缩放/平移性能优化。
- KML 列表点击后的快速定位和即时弹窗。
- 点位媒体解析、媒体图标、弹窗和媒体画廊缓存。
- 资源集合点位的数据模型、编辑入口、导入导出、账号保存、分享快照和只读查看。
- 集合内容的列表/卡片模式、分页或窗口化渲染、全屏媒体预览和关闭后的资源卸载。
- 3D 端至少能够读取、显示、编辑和导出资源集合，不能因未知扩展字段而丢失数据。
- 文档、接口契约和自动化测试。

### 2.2 非目标

- 本期不引入任意 URL 服务端代理、远程抓取缩略图、媒体转码或对象存储。
- 不改变标准 KML 的几何语义，不新增必须由第三方解析器支持的几何类型。
- 不在地图上同时挂载所有集合资源的媒体 DOM；媒体只在用户打开集合或预览器时加载。

## 3. 性能验收指标

以 `177.kml` 和 3 份内容相同的 KML 联合加载为基准，在开发机 Chrome、2D 页面、默认地图样式下验收：

| 场景 | 目标 |
| --- | --- |
| KML 导入解析 | 解析和规范化不超过现有基线的 1.5 倍；不得在主线程重复解析同一 feature 描述 |
| 管理列表点击点位 | 列表点击到地图选中/弹窗可见 p95 < 250ms；不得使用固定 800ms 以上等待 |
| 连续滚轮缩放 | 连续 6 次滚轮输入均可合并处理，不能因等待上一次动画而吞掉后续输入；单次交互响应 p95 < 100ms |
| 地图点位渲染 | 地图视口外的重型详情、媒体播放器和 iframe DOM 数量为 0；点位图标复用缓存 |
| 集合列表 | 首次只渲染首屏窗口（默认最多 40 项），其余按滚动/分页追加；单集合 300 项不会一次创建 300 个媒体节点 |
| 媒体轨道 | 全部可预览项都能在缩略轨道中滚动和直接选择；图片进入邻近可视区后才加载，关闭后释放缩略资源和 DOM |
| 多文件场景 | 3 个同量级 KML 同时打开时，缩放、平移、列表点击仍可操作，不发生长任务超过 200ms 的连续阻塞 |

性能测试允许受控误差，但必须记录浏览器、视口、文件规模和 p50/p95；不能只以主观体感判定。

## 4. 资源集合数据契约

### 4.1 Feature 扩展字段

资源集合仍使用 `type: "Point"`，以兼容现有空间索引、分享范围计算、移动/复制和 3D 点位代码。集合由可选的 `resourceCollection` 字段识别：

```json
{
  "type": "Point",
  "id": "feat-...",
  "name": "北坡观景台",
  "coordinates": [121.1, 31.2],
  "description": "",
  "markerIcon": "collection",
  "resourceCollection": {
    "version": 1,
    "viewMode": "grid",
    "items": [
      {
        "id": "res-...",
        "title": "2024 秋季全景",
        "url": "https://example.com/pano",
        "type": "auto",
        "coverUrl": "https://example.com/pano-cover.jpg"
      }
    ]
  }
}
```

字段规则：

- `version` 当前固定为 `1`。导入或读取到未知版本、非法 JSON 或超限集合时，保留 Point 几何并忽略该扩展，同时返回 warning；服务端直接写入未知/非法集合返回 `400 VALIDATION_FAILED`，不会把未知结构写入持久化数据。
- `viewMode` 只能为 `list` 或 `grid`，缺省为 `grid`。
- `items` 保持用户排序；单集合最多 300 项，单项 `title` 最多 200 个字符，`url` 最多 4,096 个字符。
- `coverUrl` 为可选封面地址，使用与 `url` 相同的 HTTPS、凭据和敏感查询参数校验，最多 4,096 个字符；未设置时不写入字段，展示层按图片缩略图、provider logo、类型图标顺序回退。
- `type` 只能为 `auto`、`image`、`video`、`audio`、`iframe`；`auto` 由现有受控内容识别器决定。
- 每个集合序列化后的大小不超过 512 KiB；超出时服务端拒绝并返回字段级中文错误。
- 集合项 `id` 在集合内唯一；缺失时服务端生成稳定随机 ID，更新时不得因排序变化而重建已有 ID。
- 集合不强制要求点位名称。名称为空时地图只显示集合图标，详情标题使用“资源集合”作为界面兜底，不写回 KML 名称。

### 4.2 KML 交换格式

标准 KML 中使用受控 `ExtendedData` 保存集合 JSON，不改变 `Point` 坐标：

```xml
<ExtendedData>
  <Data name="map-service:marker-icon"><value>collection</value></Data>
  <Data name="map-service:resource-collection"><value>{&quot;version&quot;:1,...}</value></Data>
</ExtendedData>
```

导入时必须做 JSON 解析、大小限制和字段规范化；非法或超限集合不得阻断整个 KML 文件导入，降级为普通 Point 并记录可读错误。导出时仅输出规范化后的公开字段，不输出账号、Token、管理备注和服务端内部字段。未知扩展不会原样回写，避免旧客户端误把不兼容结构再次公开。

## 5. 功能需求

### F1. 性能优化

1. 媒体识别结果按 feature 对象和描述/集合签名缓存；feature 内容变化时自动失效。
2. 点位 popup 使用延迟内容回调，创建 Marker 时不构造完整 HTML、媒体画廊或 iframe；资源集合点位的媒体能力判断只读取项数，不扫描集合 URL。
3. 相同媒体图标 descriptor 共享 `L.divIcon`/SVG 结果，避免每个点位重复解析和创建。
4. 列表定位前停止旧动画；目标已在视口内时直接选中，视口外使用短时或无动画定位，定位完成后立即打开 popup，不使用固定定时器等待。
5. 2D 地图启用适合大量矢量点位的 Canvas 与视口虚拟化配置，滚轮缩放采用可合并的短动画策略，不阻塞后续输入；Leaflet 的缩放、瓦片生命周期和标记层过渡必须保持启用，任何性能优化都不得造成旧画面提前清空、白屏等待瓦片或缩放画面撕裂。
6. 普通和分享只读 KML 都不在每次 `zoomend` 重新构造全部媒体内容；仅在视口或数据签名变化时增量挂载必要图层，列表定位通过目标 ID 强制挂载目标要素。
7. 资源集合采用分页，媒体预览采用全量可达的缩略轨道与图片懒加载；视频、音频和 iframe 只为当前预览项设置真实源。不得用固定邻近窗口删除其余缩略项。
8. 点位名称只处理当前视口及缓冲区内的图层，并在浏览器空闲时分批挂载全部可见名称；不得设置“超过固定数量永久不显示”的总量上限。地图继续移动、缩放或卸载时必须取消旧批次。

### F2. 集合创建与编辑

- 新增或编辑 Point 时可切换“普通点位/资源集合”。
- 集合编辑器支持集合标题、默认列表/卡片模式、批量粘贴 URL、单项标题/类型、删除和排序。
- 保存前统一调用 normalize/validate；错误定位到具体集合项，不使用原生 `alert/confirm/prompt`。
- 编辑器必须将标题、地址和类型放在独立字段容器内，卡片/列表模式对编辑布局有可见差异；批量输入、分页和重绘不得丢失尚未提交的文本。
- 点击新增资源后应聚焦地址字段；完全空白的占位项可在保存时忽略，其他缺少地址或格式非法的项必须标记到具体字段并自动滚动定位。
- 批量地址添加应去重并在成功后清空输入；达到集合上限时保留已添加项并明确提示被跳过的数量。
- 普通点位可转换为集合；集合也可转换为普通点位，但转换前必须明确处理资源项（保留在描述、导出备份或删除）。
- 编辑和新增时保持当前地图缩放和中心，不因集合内容或全部标注范围自动 fitBounds。

### F3. 集合浏览

- 点击集合点位显示轻量摘要（资源数量、集合名称），再进入集合内容面板；移动端遵循现有媒体点位首击/长按规则。
- 面板提供列表/卡片切换，默认使用集合的 `viewMode`；切换只影响当前会话，除非用户保存设置。
- 每项显示标题、受控类型图标和可用状态；不在列表阶段加载 iframe、视频或音频播放器。
- 点击资源项复用统一媒体预览器，支持上一项/下一项、缩略轨道、标题和原链接兜底。
- 关闭预览或集合面板后清空非活动媒体的 `src/srcObject`、销毁 HLS/Panzoom/观察器并移除事件监听，避免内存和网络请求累积。
- Leaflet marker 根节点的悬停反馈不得修改定位用的 `transform`、`scale` 或 `transform-origin`；集合点位悬停前后锚点必须保持稳定。

### F4. 分享、只读与兼容

- 现有分享快照直接保存规范化 `resourceCollection`，分享权限沿用 KML 文件权限；只读访问禁止编辑、删除和集合结构修改。
- 分享链接打开集合时只加载当前集合元数据和用户请求的资源，不扫描同一 KML 的所有媒体。
- 旧客户端或未知字段读取集合时至少显示普通 Point 和集合数量，不能导致整个文件解析失败。
- 3D 端支持集合图标、读取、编辑和导出；若暂未提供完整集合面板，必须提供只读列表和进入统一预览器的入口。

## 6. 安全与边界

- 资源 URL 只能使用现有受控 HTTPS/provider 白名单规则；不新增任意 URL 代理。
- 集合 URL 必须为 HTTPS，禁止 URL 用户名/密码及 `token`、`access_token`、`password`、`signature`、`api_key`、`authorization` 等认证或签名查询参数；普通视图参数（如 720 云 `scene_id`、`view`）完整保留。
- 服务端不得请求或记录资源 URL 的敏感查询参数；公开分享快照读取时会再次校验并剔除历史脏数据中的非法集合，响应不得泄露密码、Token、代理认证信息。
- iframe 继续使用既有 allowlist、sandbox 和 referrer policy；不绕过目标站点 CSP/X-Frame-Options。
- 所有长度、数量、JSON 深度和 URL 协议校验在服务端和浏览器端各执行一次。

## 7. 接口与持久化要求

本期不新增必须由前端本地状态补齐的接口。现有 KML 创建、更新、导入、导出、分享快照接口的 `features` 字段统一接受上述扩展字段，并在 `docs/api.md` 或用户内容专题中补充请求/响应示例、错误码和兼容策略。数据库无需新增表；资源集合随 KML feature JSON 持久化，分享快照沿用现有快照结构。

## 8. 测试与验收

- 模型测试：合法/非法集合、数量/长度/体积边界、未知版本 warning、ID 稳定性、敏感字段剔除。
- KML 往返测试：浏览器解析、服务端解析、导出再导入后集合字段等价。
- 交互测试：集合创建/编辑、列表/卡片切换、只读分享、预览打开/关闭和媒体卸载。
- 性能测试：`177.kml` 单文件与三文件场景；定位 p95、缩放输入合并、DOM 数量和长任务统计。
- 完整性测试：超过 120 个可见命名点位时名称最终全部挂载；超过 100 项媒体时缩略轨道总数、顺序、直接选择和大屏浏览均与实际资源一致。
- 回归测试：普通点位、线段、旧 KML、收藏、分享范围、2D/3D 构建和现有媒体预览测试全部通过。

验收只有在性能评估命令、`npm run check`、`npm test` 和 `npm run build` 均通过后完成；浏览器还需记录 `177.kml` 单文件和三文件场景的 DOM、连续缩放输入、列表定位响应和长任务结果。
