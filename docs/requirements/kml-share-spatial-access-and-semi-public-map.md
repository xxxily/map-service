# KML 分享空间访问控制与半公开地图需求

> 状态：已实施（v1.5.28 后续修订）
> 版本：v1.2
> 日期：2026-08-21
> 适用范围：个人 KML 分享、匿名分享页、公开分享底图目录与瓦片接口、用户中心、管理后台
> 关联文档：[用户体系、角色权限、个人空间与多 KML 分享需求](./user-system-rbac-and-multi-kml-sharing.md)、[用户体系 API](../api-user-system.md)、[图源管理与图层配置重构需求](./tile-source-and-layer-management.md)

## 1. 文档目的

本文将“KML 分享仅允许查看 KML 最外层坐标形成的矩形范围”“空间受限分享可使用长期密码授权”“在管理员允许下提供半公开地图服务”细化为可实施、可测试、可审计的产品与系统需求。

本需求在现有多 KML 分享、分享密码、站点访问密码、公开分享底图目录和分享专用瓦片接口基础上扩展，不另建一套平行分享体系。

## 实施说明

实现已覆盖外包矩形范围计算、分享预检与保存校验、管理员控制的无密码分享、有限/不限密码授权、策略变更影响预览、分享专用 catalog、瓦片范围校验、2D 相机约束、自动降级、会话撤销、后台治理展示和审计。边界瓦片按权威外包矩形执行服务端 Alpha 遮罩；空间受限分享的 3D 入口强制回退到 2D，待 3D 全部资源链路具备独立空间校验后再开放。

## 2. 可行性结论

该能力可行，但不能只通过前端限制地图拖动范围实现。浏览器端限制只能改善交互，访问者仍可能直接构造瓦片 URL、修改前端状态或调用接口查看范围外地图。

完整实现必须同时具备：

1. 服务端根据分享包内全部 KML 坐标计算权威外包矩形。
2. 2D 和 3D 客户端限制相机、缩放、搜索、定位等越界行为。
3. 分享专用 catalog 只返回当前分享可用的受控图源和空间能力。
4. 分享专用瓦片、影像、地形及其他地图资源接口逐请求校验空间范围。
5. 长期授权使用可撤销、仅作用于单个分享的服务端会话，不使用不可撤销的永久 Token。
6. KML 内容、管理员策略或分享状态变化后，空间范围和长期授权资格立即重新评估。

因此，本需求中的“只能查看 KML 区域”是服务端访问控制能力，不是一个仅用于隐藏界面或限制拖动的展示选项。

## 3. 背景与现状

### 3.1 当前能力

- 一个分享包可以包含多个 KML，并生成不可枚举的稳定分享链接。
- 分享链接可设置独立密码、链接过期时间、允许下载和默认地图视图。
- 分享密码验证成功后，服务端创建仅作用于当前 `publicId` 的授权会话，并写入 HttpOnly Cookie。
- 超级管理员可设置分享是否继承站点访问密码，以及分享密码授权的有限有效期。
- 当前密码授权默认 12 小时，服务端允许配置 5 分钟至 7 天。
- 分享页通过专用 catalog 和专用瓦片路径访问受控公开栅格图源。
- 2D 和 3D 分享页在 URL 没有合法 `coords` 时可以根据多个 KML 坐标形成的外包矩形完成首屏适配；若 URL 带有合法 `coords`，必须优先恢复 URL 视图，`layer` 参数独立优先恢复底图，空间受限模式实际强制使用 2D。

### 3.2 当前问题

- 分享页虽然会自动定位到 KML，但访问者仍可平移、缩放或直接请求范围外瓦片。
- 分享密码授权只能设置有限时长，面向长期、低风险的小范围地图分享时需要反复输入密码。
- 无密码分享虽然可以直接访问，但会获得与普通公开分享相同的底图浏览范围，缺少“只开放某一小片区域”的安全边界。
- 分享链接有效期、分享密码、密码授权有效期和地图空间范围容易被混为一个概念，现有界面不足以表达真实访问效果。
- KML 后续编辑可能扩大范围，当前没有长期授权资格的动态复核和自动失效机制。

## 4. 目标

### 4.1 产品目标

- 分享所有者可选择将地图访问限制在分享包内全部有效 KML 坐标形成的外包矩形内。
- 空间范围包含由管理员统一控制的合理边界余量，避免内容紧贴地图边缘。
- 超级管理员可决定是否允许所有者创建或保留无密码分享。
- 超级管理员可决定是否允许空间受限分享使用“不限有效期”的分享密码授权。
- KML 范围超过管理员阈值时，不允许启用不限授权。
- 支持“无分享密码、空间受限、持有链接即可查看”的半公开地图模式。
- 访问者在受限区域内继续获得完整的 KML 点、线、面、详情和媒体浏览体验。

### 4.2 安全目标

- 前端、公开清单、瓦片接口和地图资源接口使用同一份服务端空间范围事实来源。
- 分享授权不能访问普通地图 catalog、其他分享、私有 KML 或范围外地图资源。
- 不限授权仍可因分享暂停、撤销、封禁、过期、轮换链接、密码变更或策略变化立即失效。
- 空间范围无法计算、失效或超出策略时，不得自动回退为不受限访问。
- 任何新增能力不得形成任意 URL 代理、任意图源选择或站点访问密码绕过。

### 4.3 运维目标

- 超级管理员可配置范围阈值、边界余量和长期授权开关。
- 管理后台能识别长期授权分享、范围异常分享和自动降级事件。
- 关键策略变更、长期授权启用和自动撤销均有审计记录。

## 5. 非目标

本阶段不包含：

- 将用户分享自动加入全站公共 KML 目录或搜索索引。
- 为匿名访问者开放个人收藏、编辑、上传、导入或重新分享权限。
- 为分享页开放任意搜索、路线规划、地理编码、逆地理编码或任意 URL 代理。
- 通过空间限制提供数字版权保护；浏览器已获得的 KML 内容仍可能被截图或人工记录。
- 允许分享所有者自行提交或篡改服务端计算的空间边界。
- 将“不限有效期”解释为永远不可撤销或跨浏览器、跨设备自动共享授权。
- 首期支持任意复杂的地理围栏编辑器；空间范围由 KML 最外层坐标自动生成矩形。

## 6. 核心概念

以下四个概念必须在数据模型、接口、界面文案和审计中明确分离。

### 6.1 分享链接有效期

由 `KmlShare.expiresAt` 表示。到期后整个分享不可访问，无论是否设置密码、是否已经通过密码验证、是否启用了不限授权。

`expiresAt=null` 表示分享链接没有固定到期时间，但分享仍可能被暂停、撤销、封禁或轮换。

### 6.2 分享密码

分享密码决定访问者是否需要先完成一次口令验证。未设置分享密码时，不创建分享密码授权会话。

分享密码不替代站点访问密码。若分享策略为 `inherit_site_access`，访问者仍需先满足站点访问控制。

无密码分享只在管理员开启 `passwordlessSharingEnabled` 时可创建或保存。该开关与链接有效期独立：允许无密码分享时，`expiresAt` 仍可为 `null`；未设置密码时不能选择 `passwordAccess.ttlMode=unlimited`，因为此时不存在密码授权会话。

### 6.3 分享密码授权有效期

分享密码验证成功后创建的单分享授权会话支持：

| 模式 | 说明 |
| --- | --- |
| `finite` | 使用管理员配置的 `accessTtlMs`，到期后需重新输入分享密码 |
| `unlimited` | 不设置固定的密码授权到期时间，但仍受分享生命周期、浏览器 Cookie、策略复核和服务端撤销控制 |
| `not_applicable` | 分享未设置密码，不存在密码授权有效期 |

界面中的“不限有效期”应表达为“不设固定授权期限，分享失效时同步失效”，不得使用“永久有效”或“永不失效”等不可撤销语义。

### 6.4 地图空间访问范围

空间访问范围决定当前分享可以读取和呈现哪些地图区域。首期支持：

| 模式 | 说明 |
| --- | --- |
| `unrestricted` | 维持现有分享行为，可在分享专用受控图源范围内浏览地图 |
| `kml_bounds` | 只能访问分享包内全部有效 KML 坐标形成的轴对齐外包矩形；矩形外侧按管理员余量扩展 |

空间范围限制的是分享页可用的底图、影像、地形和相关地图读取能力，不裁剪或修改 KML 自身的合法几何内容。

### 6.5 半公开地图

本需求中的“半公开”是产品语义，不是新的 RBAC 角色或分享状态。满足以下条件时，分享表现为半公开地图：

- `share.publicAccessPolicy=independent`；
- 分享状态为 `active`；
- 未设置分享密码；
- `spatialAccess.mode=kml_bounds`；
- 分享链接没有被公开目录枚举，只有持有高熵链接的人可访问；
- 访问者只能读取当前分享的 KML 内容和受限区域内的分享专用地图资源。

半公开链接降低了访问门槛，但不提供身份确认。链接泄露后，任何获得链接的人都可在受限范围内查看，因此仍需支持轮换、暂停、撤销和管理员封禁。

## 7. 用户与角色

### 7.1 分享所有者

具备 `share.own.manage` 的登录用户可以：

- 为自己的分享启用或关闭空间范围限制。
- 查看服务端计算的面积、对角线距离、边界余量和长期授权资格。
- 在管理员允许且范围合规时，为设置了密码的分享选择不限授权。
- 创建无密码、空间受限的半公开链接。
- 仅在管理员开放时选择“不设置密码”或移除已有分享密码。
- 在范围或策略变化导致降级时查看原因并调整 KML 或分享设置。

分享所有者不能：

- 修改管理员设置的边界余量和最大范围阈值。
- 提交自定义经纬度边界替代服务端计算结果。
- 绕过范围超限、空几何或无效坐标校验。

### 7.2 匿名或普通访问者

访问者可以：

- 在授权完成后查看分享内 KML 点、线、面、详情和受控媒体内容。
- 在允许区域内平移、缩放、切换分享 catalog 中可用的底图。
- 点击 KML 要素定位并查看详情。

访问者不能：

- 将相机或地图请求移动到允许区域之外。
- 使用分享授权访问普通地图 catalog、个人接口、后台接口或其他分享。
- 通过搜索、定位、历史记录、URL 参数或手工瓦片请求绕过空间范围。

### 7.3 管理员

具备 `admin.share.moderate` 的管理员可以查看分享是否启用空间限制、范围摘要、授权模式和异常状态，并可按现有规则封禁分享。

普通管理员默认不能修改全局范围阈值、允许不限授权或代替所有者关闭空间限制，除非另有明确的安全管理权限。

### 7.4 超级管理员

超级管理员可以：

- 启停无密码分享能力。
- 启停空间受限分享能力。
- 设置边界余量、空间限制最大面积和最大对角线距离。
- 决定是否允许不限密码授权，并设置更严格的不限授权面积和对角线阈值。
- 调整有限授权有效期。
- 查看策略变更影响预览，并撤销不再合规的长期授权会话。

超级管理员操作仍需最近再验证、字段校验和审计，不得直接读取分享密码或授权 Token。

## 8. 总体业务规则

### 8.0 无密码分享启用条件

- 创建分享未提交密码，或编辑分享明确移除密码时，`passwordlessSharingEnabled` 必须为 `true`。
- 管理员关闭该能力后，新的无密码分享、移除密码，以及继续保存、同步内容或轮换无密码分享链接均返回 `SHARE_PASSWORDLESS_DISABLED`。
- 无密码分享可以设置固定链接到期时间，也可以使用 `expiresAt=null`；这不等于 `passwordAccess.ttlMode=unlimited`。
- 无密码分享的 `passwordAccess.ttlMode` 对外返回 `not_applicable`，不得创建密码授权会话。

### 8.1 空间限制启用条件

分享启用 `kml_bounds` 必须同时满足：

1. 管理员已开放空间受限分享能力。
2. 分享包至少包含一个处于 active 状态的 KML。
3. 全部分享项合并后至少存在一个有效 Point、LineString、Polygon 或受支持的组合几何。
4. 服务端能够将几何规范化为 WGS84 并计算允许区域。
5. 允许区域未超过管理员配置的空间限制最大面积和最大对角线距离。

任一条件不满足时，创建或编辑请求返回明确错误，不得保存为一个表面启用但实际不执行限制的状态。

### 8.2 不限授权启用条件

分享密码授权选择 `unlimited` 必须同时满足：

1. 分享已经设置密码，未设置密码时该选项不适用。
2. 超级管理员已开启 `unlimitedAccessEnabled`。
3. `spatialAccess.mode=kml_bounds`。
4. 空间范围计算成功。
5. 面积不超过 `unlimitedAccessMaxAreaKm2`。
6. 对角线距离不超过 `unlimitedAccessMaxDiagonalKm`。
7. 分享未处于 `blocked`、`revoked`、`expired` 或空内容状态。

面积和对角线必须同时满足。只校验面积会漏掉狭长跨区域轨迹，只校验对角线会错误限制形状紧凑但面积较大的区域。

### 8.3 分享链接与不限授权的关系

- `expiresAt` 仍是分享链接的最高时间边界。
- 若分享链接设置了到期时间，不限授权也在分享链接到期时失效。
- 若分享链接没有固定到期时间，不限授权仍会在暂停、撤销、封禁、轮换链接、修改密码、关闭空间限制或策略不再合规时失效。
- 清除浏览器 Cookie、更换浏览器或更换设备后，需要重新验证密码。

### 8.4 站点访问密码的关系

| 站点策略 | 分享密码 | 空间限制 | 实际访问行为 |
| --- | --- | --- | --- |
| `independent` | 无 | `kml_bounds` | 持有链接即可查看受限区域，属于半公开模式 |
| `independent` | 有 | `kml_bounds` | 首次验证分享密码，之后按有限或不限授权访问受限区域 |
| `independent` | 任意 | `unrestricted` | 维持现有独立公开分享行为，不允许选择不限授权 |
| `inherit_site_access` | 无 | `kml_bounds` | 仍需站点访问授权，不能借空间限制绕过站点密码 |
| `inherit_site_access` | 有 | `kml_bounds` | 需同时满足站点访问和分享密码授权，两种授权有效期互不延长 |

空间受限分享的不限授权只影响分享密码会话，不修改站点访问 Cookie 的有效期。

### 8.5 不自动扩大权限

以下情况均不得自动切换为 `unrestricted`：

- KML 被删除或全部移入回收站。
- KML 几何变为空或无法解析。
- 管理员关闭空间受限分享能力。
- 范围超过新策略阈值。
- 服务端空间计算异常。
- 当前图源无法执行空间校验。

系统应暂停分享、拒绝相关地图资源或降级密码授权模式，但不能静默放宽地图范围。

## 9. 分享所有者交互

### 9.1 创建分享

创建分享流程在现有标题、说明、KML 列表、下载、链接有效期和分享密码基础上增加：

- `限制地图范围`：开关，默认关闭以保持现有分享行为。
- `分享密码`：管理员开放无密码分享时可选择“不设置”；未开放时创建分享必须设置密码。
- `密码授权`：仅在设置分享密码后显示，支持“按后台有效期”和“不限”。
- `范围摘要`：显示服务端计算的面积、对角线距离和边界余量。

用户选择 KML 或切换空间限制后，前端调用服务端预检接口。预检完成前，不允许提交不限授权。

推荐界面顺序：

1. 选择分享 KML。
2. 设置访问方式和空间限制。
3. 设置链接有效期、分享密码和密码授权。
4. 查看最终访问摘要并生成链接。

最终访问摘要至少表达：

- 是否需要站点访问验证。
- 是否需要分享密码。
- 密码授权是有限还是不限。
- 地图是否限制在 KML 区域。
- 分享链接是否有固定到期时间。

### 9.2 编辑分享

- 编辑 KML 列表后重新计算空间范围和长期授权资格。
- 关闭空间限制时，如果当前为不限授权，必须同时改为有限授权并撤销已有不限会话。
- 将有限授权改为不限授权时，服务端必须再次校验当前范围，不信任先前预检结果。
- 修改分享密码、移除密码或轮换链接时，继续撤销该分享已有密码授权会话。
- 管理员关闭无密码分享后，新建无密码分享、移除密码、继续保存、同步内容或轮换无密码分享链接均被拒绝；不保留旧分享绕过开关的兼容分支。
- 修改空间限制、KML 列表或影响范围的 KML 内容后，原链接保持不变，但范围版本递增。

### 9.3 禁用状态

不限授权不可用时，界面保留选项位置并显示简短原因，例如：

- 后台未开放。
- 需先限制地图范围。
- 当前范围过大。
- 当前 KML 没有有效几何。

界面不得用长段辅助文案枚举全部规则，详细限制通过范围详情或错误反馈展示。

### 9.4 我的分享列表与详情

分享列表和详情增加：

- 地图范围：`不限制` / `限制在 KML 区域`。
- 范围面积和对角线距离。
- 密码授权：`不适用` / `有限` / `不限`。
- 范围状态：`正常` / `重新计算中` / `超出策略` / `无有效几何`。
- 自动降级或授权撤销原因。

列表默认只显示简短状态，完整指标放在分享详情中，避免信息过载。

## 10. 管理后台公开分享策略

### 10.1 设置项

在现有“公开分享策略”中增加以下设置。数值为建议初始值，实施前应使用生产典型 KML 复核，但字段和约束语义应保持稳定。

| 设置 | 建议默认值 | 校验范围 | 说明 |
| --- | ---: | ---: | --- |
| `passwordlessSharingEnabled` | `false` | 布尔值 | 是否允许所有者创建、保存或移除密码后形成无密码分享 |
| `spatialAccessEnabled` | `true` | 布尔值 | 是否允许所有者创建空间受限分享；不改变已有不受限分享 |
| `spatialPaddingMeters` | `1000` | 50～10000 米 | KML 几何外侧统一边界余量，由服务端使用 |
| `spatialMaxAreaKm2` | `10000` | 1～500000 平方公里 | 启用空间限制允许的最大面积 |
| `spatialMaxDiagonalKm` | `300` | 1～5000 公里 | 启用空间限制允许的最大对角线距离 |
| `spatialUnrestrictedTileMaxZoom` | `14` | 0～24 的整数 | 分享所有者可配置的范围外底图放宽最大级别；单个分享值不得超过此管理员上限，可高于该分享计算出的 `minZoom` |
| `unlimitedAccessEnabled` | `false` | 布尔值 | 是否允许合规空间受限分享使用不限密码授权 |
| `unlimitedAccessMaxAreaKm2` | `2000` | 1～`spatialMaxAreaKm2` | 不限授权允许的最大面积 |
| `unlimitedAccessMaxDiagonalKm` | `100` | 1～`spatialMaxDiagonalKm` | 不限授权允许的最大对角线距离 |
| `accessTtlMs` | 保持现有值 | 5 分钟～7 天 | 有限分享密码授权有效期 |

`unlimitedAccessMaxAreaKm2` 和 `unlimitedAccessMaxDiagonalKm` 不得大于对应的空间限制总体阈值。

### 10.2 后台交互

- 仅超级管理员或具备等价安全策略权限的账号可以修改。
- 保存前要求最近再验证。
- 缩小阈值或关闭不限授权前，显示受影响分享数量和将被撤销的不限会话数量。
- 下调 `spatialUnrestrictedTileMaxZoom` 时，存量分享已保存的 `unrestrictedTileMaxZoom` 自动收敛到新上限，不将分享标记为不可用。
- 保存成功后立即提升空间策略版本，并安排存量分享重新评估。
- 禁止使用浏览器原生 `alert`、`confirm`、`prompt`，继续复用统一 Dialog。

### 10.3 策略变更规则

- 关闭 `unlimitedAccessEnabled`：所有不限授权会话立即撤销，相关分享自动改为 `finite`，空间限制保持不变。
- 缩小不限授权阈值：超限分享自动改为 `finite` 并撤销不限会话。
- 关闭 `passwordlessSharingEnabled`：立即禁止创建无密码分享、移除密码、继续保存、同步内容和轮换无密码分享链接；访问已存在的测试链接不作为兼容目标，可直接删除后按新策略重建。
- 关闭 `spatialAccessEnabled`：禁止新建、继续保存和重新计算空间受限分享；不提供存量兼容分支，测试分享可删除后重建。
- 缩小空间限制总体阈值：超限分享不得回退为不受限，应进入 `out_of_policy` 并暂停地图资源访问，等待所有者缩小范围或明确关闭空间限制。
- 增大阈值：不会自动把已降级分享恢复为不限授权，由所有者重新确认。

## 11. 空间范围计算

### 11.1 权威数据源

空间范围由服务端读取分享包内所有处于 active 状态的 KML 当前版本计算。计算包括默认隐藏的分享项，因为访问者仍可在分享页手动显示它们。服务端收集所有 Point、LineString、Polygon 坐标，取投影后的最小/最大 X、Y 形成一个轴对齐外包矩形，再向外扩展管理员配置的边界余量；矩形内部全部属于可查看区域，与坐标之间是否存在实际线段或面无关。

客户端提交的 `bbox`、面积、对角线或展示几何只能用于展示预览，不能作为授权依据。

### 11.2 坐标基线

- 原始空间坐标统一按 WGS84 计算。
- `coordCorrection` 只属于渲染层，不参与服务端权威范围计算。
- 海拔不影响水平访问范围，但可用于 3D 相机高度辅助计算。
- 非有限数值、越界坐标和不受支持的几何必须被排除并记录计数。
- 若排除非法坐标后没有有效几何，空间限制不可启用。

### 11.3 坐标外包矩形

首期应覆盖：

- Point、LineString、Polygon：递归提取全部有效坐标；Polygon 按标准 GeoJSON/KML 形式支持外环及嵌套环数组，不得因为多一层环数组而将有效面判为空。
- 多 KML 和多要素：将所有坐标放入同一局部投影后计算最小 X、最小 Y、最大 X、最大 Y。
- 边界余量：在矩形四边统一向外扩展 `spatialPaddingMeters`。
- 面、线的内部空洞、断裂和多段之间的空白不再单独切分权限区域。

服务端权威允许区域就是该外包矩形，不再使用点/线/面缓冲联合或只对点位周边生成圆形区域。用户选择“限制在 KML 区域”后，最外层坐标围闭形成的四方形范围内均可查看。

旋转后的 2D 分享视口以当前视口四角在投影坐标中的轴对齐包络计算可移动中心区。若旋转视口包络大于授权矩形，中心仍可在授权矩形内部移动以访问边缘 KML 内容；旋转、缩放结束或窗口尺寸变化后重新计算，不复用旧拖拽状态。拖到边缘时保留阻尼反馈，松手后由 Leaflet 原生 `maxBounds` 动画回弹，服务端瓦片授权矩形不因此扩大。

### 11.4 边界余量

- 边界余量由 `spatialPaddingMeters` 统一控制。
- 分享所有者首期只选择是否限制范围，不直接填写任意余量。
- 修改管理员余量后，存量分享需要提升范围版本并重新计算。
- 余量应在地理测地或适当的局部投影空间中按米计算，不能直接把米数当作固定经纬度差值。

### 11.5 面积和对角线

- 面积使用外包矩形面积。
- 对角线使用外包矩形两条对角线中的最大投影距离。
- 返回给用户的数值可适度四舍五入，服务端判定使用未舍入值。
- 阈值比较需采用稳定的小数容差，避免恰好位于阈值的分享在重复计算时来回切换状态。

### 11.6 跨 180 度经线与世界环绕

- 跨越 180 度经线的轨迹不得被错误计算为接近全球范围。
- 服务端应使用可分段的经度区间或等价的反经线处理算法。
- 公开响应可返回多个经度包络或规范化 MultiPolygon。
- 2D 分享页在空间限制模式下关闭世界副本和无限横向环绕。
- 接近极区且无法稳定生成允许区域时，应拒绝空间限制并返回明确错误，不得按全球范围放行。

### 11.7 计算缓存与版本

- 计算结果按分享 ID、分享项集合、各 KML revision 和管理员空间策略版本缓存。
- 任一 KML revision、分享项、余量或阈值变化后缓存失效。
- 瓦片请求不得每次重新解析全部 KML；应读取已验证的版本化空间范围或空间索引。
- 公开请求发现范围版本过期时，必须先完成安全重算或拒绝访问，不能临时按旧的更大范围继续放行。

## 12. 地图与瓦片服务约束

### 12.1 分享专用 catalog

`GET /api/v1/public/kml-shares/:publicId/map/catalog` 在空间限制模式下必须：

- 继续只返回后台已发布、前台可见且允许分享使用的受控图源。
- 返回公开展示所需的 `spatialAccess` 摘要、相机包络和支持能力。
- 不返回普通地图 catalog 的原始 URL、代理凭据、管理备注或不受控图源。
- 排除无法执行空间范围校验的图源、影像、地形或派生服务。

### 12.2 瓦片请求校验

每个分享专用瓦片请求必须执行：

1. 分享状态、站点策略和可选分享密码授权校验。
2. `sourceId` 是否属于当前分享 catalog 的校验。
3. `z/x/y` 合法性、世界环绕规范化和请求频率校验。
4. 瓦片地理覆盖范围与服务端权威允许区域的空间校验。
5. 空间策略版本和分享范围版本校验。

范围外瓦片默认不得回源，也不得从共享缓存直接返回；12.4 明确的低缩放 `allow_unrestricted` 例外仍必须经过分享鉴权、图源校验和限流。

### 12.3 边界瓦片

地图瓦片通常覆盖一个矩形，边界瓦片可能同时包含允许区域和范围外区域。实现必须采用以下任一安全方式：

- 对边界瓦片执行服务端遮罩，只返回允许区域内像素，范围外像素透明或使用统一中性色；或
- 仅返回完全位于允许区域内的瓦片，边界瓦片返回空白占位。

不得为了视觉完整直接返回包含大面积范围外地图的原始边界瓦片。若某种图源格式无法遮罩且完全包含策略导致无法使用，应从空间受限分享 catalog 中排除该图源。

v1.5.28 起采用边界瓦片服务端遮罩：`allow` 原样返回受控图源瓦片，`boundary` 回源后按权威外包矩形生成保守 Alpha 遮罩，范围外像素透明；`outside` 和未配置放宽时的 `below_min_zoom` 不回源并返回合法透明 PNG；配置放宽后，`allow_unrestricted` 按 12.4 直接回源。遮罩结果不得写入普通瓦片缓存，只允许使用有界内存缓存和并发合并；边界请求与完整允许瓦片一样计入分享瓦片限流。

### 12.4 低缩放级别

- 服务端根据完整相机包络计算空间受限分享可用的最低缩放级别；该层级允许通过边界遮罩显示矩形内像素，不要求整张原始瓦片完全落入外包矩形。
- 分享所有者可选填 `unrestrictedTileMaxZoom`（基础取值为整数 `0～24`，且不得高于管理员配置的 `spatialUnrestrictedTileMaxZoom`，默认 `14`）。该值可以高于当前分享计算出的 `minZoom`。设置后，`z <= unrestrictedTileMaxZoom` 的范围外瓦片允许通过受控图源直接回源；`z > unrestrictedTileMaxZoom` 仍按 KML 外包矩形执行 `allow`、`boundary` 或 `outside` 判定。
- 未设置 `unrestrictedTileMaxZoom` 时保持严格模式：低于 `minZoom` 的瓦片请求返回范围拒绝，不回源；设置放宽阈值后，所有 `z <= unrestrictedTileMaxZoom` 的范围外瓦片均使用 `allow_unrestricted` 直接回源，`z > unrestrictedTileMaxZoom` 才重新执行外包矩形判定。
- 放宽只改变服务端瓦片请求能力，不改变 KML 内容、文件、媒体或相机授权边界；所有请求仍需通过分享授权、图源 catalog、坐标校验和分享瓦片限流。
- 公开清单或 catalog 返回 `minZoom` 和 `unrestrictedTileMaxZoom`。前端相机有效最低缩放为 `minZoom` 与放宽阈值（如有）中的较小值，未设置阈值时使用 `minZoom`；`maxBounds` 继续固定为 KML 外包矩形，用户不能拖动到 KML 不可视范围。
- 低缩放放宽瓦片使用 `allow_unrestricted` 判定，直接回源且不进入边界 Alpha 遮罩；仍返回 `Cache-Control: private, no-store`。
- 该设置用于低缩放周边底图体验和减少不必要的高清瓦片请求，不允许借此放大后查看 KML 范围外高清地图。

### 12.5 缓存隔离

- 原始上游瓦片可复用现有服务端缓存，但返回前仍必须执行当前分享空间校验。
- 分享瓦片对浏览器和中间代理统一返回 `Cache-Control: private, no-store`，包括正常回源和透明占位响应。
- 经遮罩的边界瓦片缓存键必须包含分享 ID 或不可碰撞的范围摘要、空间范围版本、图源 ID 和瓦片坐标。
- 不得把某个分享遮罩后的瓦片写入普通瓦片缓存命名空间。
- CDN 或反向代理不得绕过应用层空间校验直接公开分享瓦片缓存。

## 13. 2D 分享页行为

- URL 不含合法 `coords` 时，首屏自动适配全部有效分享 KML 坐标形成的外包矩形，并包含管理员配置的边界余量；URL 含合法 `coords` 时恢复参数中的中心、缩放和旋转，不得被自动适配覆盖。空间受限分享的有效最低缩放为 `minZoom` 与放宽阈值中的较小值。`layer` 参数独立按 URL → 分享配置 → 默认图层优先恢复；非法或越界状态安全回退。
- 地图中心、拖动惯性、键盘移动、缩放、旋转和 URL 参数恢复后均需校验允许区域。
- 空间受限分享启用地图旋转时，允许中心区域必须按当前 bearing 下屏幕视口四角的轴对齐包络重新计算：`halfX=(|cosθ|×视口宽+|sinθ|×视口高)/2`、`halfY=(|sinθ|×视口宽+|cosθ|×视口高)/2`。不得继续使用归北状态缓存的宽高或只取旋转后的 NW/SE 两点；旋转、归北、缩放、窗口尺寸变化后都要立即重新校正中心、拖动黏滞、惯性和键盘平移边界。窄视口下 Leaflet 的超大非动画平移也必须先将屏幕偏移按 bearing 转回投影中心，不能直接把屏幕偏移当作未旋转投影偏移。
- 尝试越界时将相机限制在最近合法位置，使用非阻塞短反馈，不产生持续遮挡地图的横幅。
- 关闭世界环绕和重复世界副本。
- 点击 KML 点、线、面仍可定位、打开 popup、查看详情和媒体预览。
- KML 管理面板只提供分享浏览所需能力，不提供编辑、导入、上传、收藏到他人空间或重新分享。
- 首期不在空间受限匿名分享页开放通用搜索、历史搜索、路线规划和“定位到我的位置”。后续若开放，服务端结果和目标坐标必须同样受空间范围约束。
- 客户端限制失效时，服务端瓦片校验仍必须独立阻止越界读取。

## 14. 3D 分享页行为

3D 的相机位置在允许区域内并不代表视野只覆盖允许区域，因此必须额外控制：

- 相机目标点和地表交点必须位于允许区域。
- 最大相机高度根据允许区域对角线和策略计算，防止从高空观察远超范围的地表。
- 影像、地形和其他 3D 资源请求必须通过分享专用、空间校验后的接口。
- 飞行、旋转、俯仰、缩放和 URL 恢复均不得把视野带离允许区域。
- 无法安全限制的全球地形、影像或第三方 3D 资源不得在空间受限分享中加载。

在 3D 服务端资源和相机约束未完成前，空间受限分享必须强制使用 2D，或明确隐藏 3D 入口。不得仅限制 3D 相机中心后继续请求不受限的全球资源。

首期采用强制回退 2D：分享清单仍保留兼容的视图配置，但空间受限分享加载时忽略 3D 模式，避免通过 Cesium 全球资源链路绕过服务端范围校验。

## 15. 授权会话

### 15.1 会话作用域

分享密码授权会话必须继续满足：

- 仅绑定一个内部分享 ID。
- Cookie 路径仅覆盖该 `publicId` 的公开分享 API。
- Token 使用密码学安全随机数，数据库只保存哈希。
- Cookie 使用 HttpOnly、SameSite 和生产环境 Secure。
- 不在 URL、公开响应、日志或前端存储中返回 Token。

### 15.2 有限授权

- `finite` 使用管理员当前配置的 `accessTtlMs` 创建固定到期时间。
- 已创建会话不因管理员后续延长有限 TTL 自动延长。
- 管理员缩短 TTL 时，可选择只影响新会话；若安全策略要求立即收紧，应提升策略版本并撤销超出新上限的会话。

### 15.3 不限授权

- 数据库会话不设置固定 `expiresAt`，使用明确的 `ttlMode=unlimited`，不能用一个超大毫秒值模拟。
- 浏览器使用持久 Cookie，并在有效访问期间按受控周期滚动续期；Cookie `Max-Age` 不得设置为超出浏览器支持范围的虚假永久值。
- 浏览器 Cookie 的实际保存仍受浏览器政策、用户清理数据、长期未访问和隐私模式影响，这些情况可要求重新验证密码。
- 服务端每次请求继续检查分享状态、当前空间模式、范围资格、密码版本和策略版本。
- 可在访问时轮换 Cookie 对应 Token，降低长期固定 Token 泄露风险。
- 服务端必须提供按分享撤销和全局批量撤销能力。

### 15.4 必须撤销会话的事件

以下事件立即撤销该分享全部密码授权会话，或至少撤销所有不限会话：

| 事件 | 有限会话 | 不限会话 |
| --- | --- | --- |
| 修改或移除分享密码 | 全部撤销 | 全部撤销 |
| 轮换公开链接 | 全部撤销 | 全部撤销 |
| 撤销、封禁、链接过期 | 访问立即失效 | 访问立即失效 |
| 关闭空间限制 | 可按现有 TTL 保留或统一撤销 | 必须撤销并改为有限模式 |
| 范围超过不限阈值 | 可保留 | 必须撤销并改为有限模式 |
| 空间范围无效或超出总体阈值 | 地图资源拒绝 | 必须撤销，地图资源拒绝 |
| 管理员关闭不限授权 | 可保留 | 全部撤销并改为有限模式 |

暂停分享时可以保留数据库会话记录以支持恢复，但恢复后仍需验证密码版本、空间范围版本和策略版本；不满足时必须要求重新验证。

## 16. KML 内容变化与自动降级

### 16.1 范围重新计算

以下变更使空间范围缓存失效：

- 向分享增加或移除 KML。
- 共享 KML 的点、线、面坐标变化。
- KML 被移入回收站、恢复或永久删除。
- 管理员修改边界余量或空间阈值。
- 坐标规范化规则升级。

### 16.2 范围扩大但仍合规

- 更新空间范围和范围版本。
- 后续公开请求立即使用新范围。
- 客户端已打开页面在下一次 manifest 刷新或资源请求时收到版本变化，并重新限制相机。
- 授权会话可继续使用，因为服务端每次请求都绑定当前范围，不把旧范围写死在客户端 Token 中。

### 16.3 超过不限授权阈值

若分享原先使用不限授权，KML 后续扩大后超过不限阈值但仍未超过空间限制总体阈值：

- 空间限制继续生效。
- 分享的密码授权模式自动改为 `finite`。
- 立即撤销已有不限会话。
- 分享保持 active，访问者下次访问需重新验证密码。
- 所有者收到站内状态提示，审计记录自动降级原因和范围指标。

### 16.4 超过空间限制总体阈值

若范围超过 `spatialMaxAreaKm2` 或 `spatialMaxDiagonalKm`：

- 分享进入 `out_of_policy` 空间状态。
- 分享 KML 和地图资源公开读取应暂停或返回明确不可用状态。
- 不得自动关闭空间限制并恢复为不受限访问。
- 所有者可缩小 KML、移除跨区域 KML，或明确改为不受限分享；改为不受限时不限授权必须同步关闭。

### 16.5 无有效几何

空间受限分享失去全部有效几何时，应暂停公开访问并返回 `SHARE_SPATIAL_BOUNDS_EMPTY`。恢复 KML 后重新计算成功，仍由所有者确认恢复分享，避免意外重新公开。

## 17. 数据模型

### 17.1 `KmlShare`

建议新增明确字段，不把授权边界混入纯展示用途的 `viewConfig`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `spatialAccessMode` | 枚举 | `unrestricted` / `kml_bounds` |
| `passwordAccessTtlMode` | 枚举 | `finite` / `unlimited`；无密码时公开视图返回 `not_applicable` |
| `spatialScope` | JSON | 服务端生成的版本化允许区域、bbox、指标和计算摘要 |
| `spatialScopeRevision` | 整数 | 每次范围或策略变化递增 |
| `spatialStatus` | 枚举 | `ready` / `recalculating` / `out_of_policy` / `empty` / `error` |

`spatialScope` 至少包含：

```json
{
  "version": 2,
  "geometryType": "BoundingBox",
  "displayGeometry": {},
  "bbox": [113.12, 22.95, 113.48, 23.31],
  "crossesAntimeridian": false,
  "paddingMeters": 1000,
  "areaKm2": 428.6,
  "diagonalKm": 54.2,
  "minZoom": 11,
  "unrestrictedTileMaxZoom": 8,
  "sourceRevisionHash": "sha256:...",
  "policyRevision": 3,
  "computedAt": "2026-08-15T08:00:00.000Z"
}
```

公开接口不必返回完整内部计算摘要、revision hash 或管理员阈值，只返回客户端限制相机和展示状态所需字段。

### 17.2 `ShareAccessSession`

建议调整：

| 字段 | 说明 |
| --- | --- |
| `ttlMode` | `finite` / `unlimited` |
| `expiresAt` | `finite` 必填；`unlimited` 为 null |
| `passwordVersion` | 分享密码版本，修改密码后失效 |
| `policyRevision` | 创建或刷新会话时的分享策略版本 |
| `createdAt` / `lastAccessedAt` | 创建和最近使用时间 |
| `revokedAt` / `revokeReason` | 撤销时间和机器原因码 |

查询有效会话时不能继续只使用 `expires_at > now`，需按 `ttlMode`、撤销状态、分享状态和策略版本统一判定。

### 17.3 管理设置

`user_system_settings.share` 扩展示例：

```json
{

  "maxFilesPerShare": 20,
  "accessTtlMs": 43200000,
  "passwordlessSharingEnabled": false,
  "spatialAccessEnabled": true,
  "spatialPaddingMeters": 1000,
  "spatialMaxAreaKm2": 10000,
  "spatialMaxDiagonalKm": 300,
  "unlimitedAccessEnabled": false,
  "unlimitedAccessMaxAreaKm2": 2000,
  "unlimitedAccessMaxDiagonalKm": 100,

```

`spatialPolicyRevision` 由服务端维护，不接受前端直接指定。

| 方法 | 路径 | 鉴权 | 用途 |

| `POST` | `/api/v1/admin/user-system/settings/impact-preview` | `admin.security.manage`，空间字段还需超级管理员 | 保存前计算受影响分享、自动降级分享和待撤销不限授权会话数量；不写入设置 |

请求体与 `PUT /admin/user-system/settings` 的 `share` 分区一致。响应包含 `preview=true`、规范化后的设置和：

```json
{

    "affectedShares": 3,
    "downgradedShares": 1,
    "revokedUnlimitedSessions": 2,
    "recalculatedShares": 8
```

前端在收紧阈值、关闭空间能力或关闭不限授权时使用统一确认 Dialog 展示上述数量；取消确认不会写入设置。

### 18.2 创建或更新分享

现有创建、更新请求增加：

```json
{
  "spatialAccess": {
    "mode": "kml_bounds"
  },
  "passwordAccess": {
    "ttlMode": "unlimited"
  }
}
```

规则：

- `spatialAccess.mode` 省略时，创建默认 `unrestricted`，更新保持现状。
- `spatialAccess.unrestrictedTileMaxZoom` 可选，基础取值为 `0～24` 的整数，且不得高于管理员配置的 `share.spatialUnrestrictedTileMaxZoom`（默认 `14`）；该值可以高于当前分享计算出的 `minZoom`。`z <=` 该值时范围外底图瓦片允许受控回源，`z >` 该值时继续执行外包矩形限制。省略或为 `null` 表示严格模式。
- `passwordAccess.ttlMode` 省略时，创建默认 `finite`，更新保持现状。
- 未设置分享密码时提交 `unlimited` 返回校验错误，不静默忽略。
- 客户端提交的 `geometry`、`bbox`、面积和对角线字段一律拒绝或忽略，不能写入权威范围。

所有者详情响应增加：

```json
{
  "spatialAccess": {
    "version": 2,
    "geometryType": "BoundingBox",
    "mode": "kml_bounds",
    "status": "ready",
    "bbox": [113.12, 22.95, 113.48, 23.31],
    "paddingMeters": 1000,
    "areaKm2": 428.6,
    "diagonalKm": 54.2,
    "unlimitedAccessEligible": true,
    "reasonCode": null,
    "revision": 4
  },
  "passwordAccess": {
    "ttlMode": "unlimited",
    "effectiveTtlMs": null
  }
}
```

### 18.3 密码验证

`POST /api/v1/public/kml-shares/:publicId/access` 成功响应增加授权模式：

有限授权：

```json
{
  "passwordRequired": true,
  "ttlMode": "finite",
  "expiresAt": "2026-08-15T20:00:00.000Z"
}
```

不限授权：

```json
{
  "passwordRequired": true,
  "ttlMode": "unlimited",
  "expiresAt": null
}
```

响应仍不返回 Token。服务端写入 Cookie 前必须再次校验空间范围和当前策略，避免预检后 KML 或策略已变化。

### 18.4 公开清单

`GET /api/v1/public/kml-shares/:publicId` 增加脱敏空间能力：

```json
{
  "spatialAccess": {
    "version": 2,
    "geometryType": "BoundingBox",
    "mode": "kml_bounds",
    "bbox": [113.12, 22.95, 113.48, 23.31],
    "displayGeometry": {},
    "paddingMeters": 1000,
    "minZoom": 11,
    "unrestrictedTileMaxZoom": 8,
    "maxCameraHeight": 18000,
    "revision": 4
  },
  "passwordAccess": {
    "ttlMode": "unlimited"
  }
}
```

`displayGeometry` 是用于客户端遮罩和相机限制的简化几何，不是服务端授权事实来源。服务端不得返回内部 KML ID、范围计算缓存键、管理员阈值或源 revision hash。

### 18.5 管理设置

`GET/PUT /api/v1/admin/user-system/settings` 的 `share` 分区增加第 10.1 节字段。

更新响应应返回：

- 新的 `spatialPolicyRevision`。
- 受影响分享数量。
- 自动降级分享数量。
- 已撤销不限会话数量。
- 需要异步重新计算的分享数量。

若重新计算采用异步任务，设置保存成功不代表所有存量分享已完成重算；后台必须展示任务状态，重算期间继续使用更严格的旧范围或暂停资源访问。

| HTTP | 错误码 | 场景 |
| ---: | --- | --- |
| 400 | `SHARE_SPATIAL_MODE_INVALID` | 空间模式不受支持 |
| 400 | `SHARE_PASSWORD_ACCESS_MODE_INVALID` | 密码授权模式不受支持 |
| 403 | `SHARE_SPATIAL_SCOPE_DENIED` | 请求的地图资源位于允许区域外 |
| 409 | `SHARE_SPATIAL_RECALCULATING` | 当前范围正在重新计算，暂不能安全访问 |
| 422 | `SHARE_SPATIAL_DISABLED` | 后台未开放空间受限分享 |
| 422 | `SHARE_SPATIAL_BOUNDS_EMPTY` | 分享内没有可计算范围的有效几何 |
| 422 | `SHARE_SPATIAL_RANGE_TOO_LARGE` | 超过空间限制总体面积或对角线阈值 |
| 422 | `SHARE_UNLIMITED_ACCESS_DISABLED` | 后台未开放不限授权 |

## 19. 安全与隐私

### 19.1 服务端最终授权

- 前端相机边界不是安全控制的事实来源。
- 每个公开地图资源接口必须根据 `publicId` 解析分享，再读取当前空间范围。
- 分享 Cookie 不能用于普通 `/api/v1/map/catalog`、普通瓦片接口或其他分享。
- 不接受客户端传入任意图源 URL、代理出口、访问头或空间边界。

### 19.2 防止接口绕过

至少覆盖以下绕过方式：

- 直接修改 `z/x/y` 请求范围外瓦片。
- 使用负数、超大整数、世界环绕等价坐标或重复世界 x 值。
- 修改公开清单中的客户端 bbox。
- 直接调用普通地图 catalog 或非分享瓦片路径。
- 通过搜索、历史记录、URL 中心点或浏览器定位把地图带出范围。
- 利用旧范围缓存、旧 Service Worker 响应或 CDN 缓存继续读取已收紧区域。
- 利用跨 180 度经线计算错误把小范围识别为全球或把全球识别为小范围。

### 19.3 分享链接保护

- `publicId` 继续使用不少于 128 bit 熵的随机值。
- 分享页设置 `noindex, nofollow`，不进入站内公共目录或搜索索引。
- 密码验证、公开清单和瓦片访问继续限流，并区分暴力破解和资源滥用。
- 首期公开清单按“分享 + 来源 IP”每分钟最多 120 次，瓦片按“分享 + 来源 IP”每分钟最多 600 次；达到上限返回 `429`，不同分享和来源 IP 相互隔离，图源切换不能绕过分享级额度。
- 暂停、撤销、封禁和轮换链接必须即时生效。

### 19.4 日志与审计最小化

- 日志不记录密码、Cookie、Token、完整 KML、完整空间几何或敏感请求头。
- 可记录分享内部 ID、范围版本、面积分档、对角线分档、拒绝原因、图源 ID 和瓦片坐标。
- 公开错误不返回管理员阈值、其他分享信息或图源凭据。

### 19.5 外部媒体

空间限制不把第三方 iframe 或媒体变成服务端代理。只允许现有受控 provider 和安全策略；不得因半公开分享新增任意网页代理能力。

## 20. 审计与监控

### 20.1 审计事件

至少记录：

- `share.spatial.enable`
- `share.spatial.disable`
- `share.spatial.recalculate`
- `share.password-access.unlimited.enable`
- `share.password-access.unlimited.disable`
- `share.password-access.auto-downgrade`
- `admin.share-spatial-policy.update`
- `admin.share-access-session.revoke`

审计元数据只保存范围指标、状态、策略版本和原因码，不保存完整几何、密码或 Token。

### 20.2 运行指标

至少监控：

- 空间受限分享数量和半公开分享数量。
- 有限与不限授权会话数量。
- 范围计算耗时、失败率和缓存命中率。
- 范围外瓦片拒绝次数。
- 边界瓦片遮罩耗时和缓存命中率。
- 自动降级、策略超限和空几何分享数量。
- 单分享瓦片访问速率和异常放大行为。

首期使用进程内有界聚合器记录内部分享 ID、受控图源 ID、事件、空间判定、计数、范围缓存命中/失效和空间重算累计/最大耗时，并通过 `GET /api/v1/admin/kml/shares/runtime-metrics` 向具备 `admin.share.moderate` 权限的管理员提供只读查询。响应同时给出当前空间分享、半公开分享、范围状态和有限/不限授权会话数量快照。不得把来源 IP、`publicId`、Cookie、Token、完整 URL 或瓦片坐标写入该指标；多实例部署时应迁移到统一指标系统。

## 21. 性能与可靠性

- 分享创建、更新、范围摘要和分享项写入需保持事务一致性。
- 大 KML 范围计算应支持后台任务，但分享在范围未确认前不得进入可公开访问状态。
- 空间范围使用版本化缓存和空间索引，瓦片校验不能每次全量扫描要素。
- `displayGeometry` 需要受控简化，限制坐标数量和响应大小；简化只影响客户端展示，不扩大服务端权威范围。
- 遮罩后的边界瓦片需设置内存和并发上限，防止图片处理造成资源耗尽。
- KML 更新和策略变更并发发生时，以最新 KML revision 和最新策略版本计算，旧任务结果不得覆盖新结果。
- 数据库迁移、范围重算和会话撤销失败时应保守拒绝公开地图资源，并保留可恢复状态。

## 22. 版本切换与测试数据处理

- 当前没有正式用户，不提供旧空间范围版本、旧分享状态或旧前端的兼容读取与迁移逻辑。
- 现有测试分享直接删除并按新规则重建；旧空间范围缓存不复用，重新创建后统一生成 `version=2`、`geometryType=BoundingBox` 的范围。
- 不为旧范围结构保留 `primitives`、几何联合缓冲或 `allowExisting` 等兼容分支。
- 数据库已有通用版本迁移机制仍按项目规范保留，但本次需求不新增专门迁移旧测试分享的逻辑。
- 部署时只需更新代码和构建产物，然后删除旧测试链接、重新创建并验收新链接。

## 23. 测试要求

### 23.1 单元测试

- 单点、同点多点、短线、长线、多线、多边形和多 KML 外包矩形。
- 分散点、断裂线段和多个离散要素之间的矩形空白区域均可查看。
- 默认隐藏 KML 仍计入允许区域。
- 边界余量按米计算。
- 无效坐标、NaN、Infinity、空几何和混合合法非法几何。
- 跨 180 度经线、接近极区和世界环绕。
- 面积和对角线阈值边界及浮点容差。
- KML revision 和策略 revision 导致缓存失效。
- 有限与不限授权会话有效性、撤销和密码版本变化。

### 23.2 服务测试

- 未登录用户只能通过公开分享路径读取被分享数据。
- 管理员开放时，无密码分享可直接查看且可以不设置固定链接期限。
- 管理员关闭时，新建无密码分享、移除密码、继续保存、同步内容和轮换无密码分享链接均被拒绝。
- `inherit_site_access` 下仍要求站点访问授权。
- 不限授权未启用、无密码、无空间限制或范围超限时均被拒绝。
- 直接请求范围外瓦片不会回源，也不会返回普通缓存内容。
- 边界瓦片被遮罩或返回空白，不返回未处理的范围外像素。
- 普通地图 catalog、普通瓦片、其他分享和私有接口不接受分享 Cookie。
- KML 扩大后自动降级并撤销不限会话。
- 管理员关闭不限授权或收紧阈值后即时生效。
- 空间计算失败时不回退为不受限分享。

### 23.3 前端与端到端测试

- 创建和编辑分享时可启停空间限制。
- 范围摘要和不限授权资格随 KML 选择更新。
- 2D 拖动、缩放、旋转、URL 恢复和点击要素不会带出允许区域。
- 覆盖 bearing `0°/90°/180°/270°` 及任意角度、非正方形视口、放大后拖动和旋转后归北再拖动；每种场景都必须能查看完整外包矩形内的 KML 要素，且边界不会沿用旧 bearing 的宽高限制。
- 搜索、历史、定位和其他越界入口在空间受限分享中不可绕过。
- 3D 未具备完整限制时入口隐藏或回退 2D。
- 密码有限授权到期后重新验证。
- 不限授权在浏览器保留 Cookie 时可持续使用，在撤销事件后立即要求重新验证。
- 无痕模式、清 Cookie 和更换浏览器不会被错误描述为仍保持不限授权。
- 移动端和桌面端均无内容重叠、横向溢出或阻塞弹窗。

### 23.4 安全测试

- 修改 publicId、shareItemId、sourceId、z/x/y 和世界环绕坐标。
- 重放已撤销、已轮换或旧密码版本的 Cookie。
- 旧范围缓存、并发重算和策略更新竞态。
- 直接访问反向代理或 CDN 缓存路径。
- 高频边界瓦片请求和大 KML 计算资源消耗。
- 公开响应、日志和审计的密码、Token、内部 ID及图源凭据脱敏。

## 24. 验收标准

以下条件全部满足，方可认为需求完成：

1. 分享所有者可以为单个或多个 KML 的分享启用“限制地图范围”。
2. 服务端按全部有效分享 KML 的 WGS84 坐标最小/最大边界和管理员余量生成权威外包矩形，矩形内部全部可查看。
3. 2D 分享页在没有合法 URL `coords` 时首屏适配允许区域，并在拖动、缩放、旋转和 URL 恢复时保持范围限制；合法 URL `coords` 不被首屏适配覆盖。
4. 范围外瓦片请求在服务端被拒绝且不回源，修改前端代码不能绕过。
5. 边界瓦片不会原样暴露明显超出允许区域的地图内容。
6. 空间受限分享仍保留完整 KML 点、线、面、详情和媒体只读体验。
7. 超级管理员可以启停不限授权并配置面积、对角线阈值。
8. 只有设置密码、启用空间限制且范围符合策略的分享可以选择不限授权。
9. 管理员开放无密码分享时，无密码、独立访问、空间受限分享可以直接打开，可不设置固定链接期限，并且只能使用当前分享及范围内地图资源。
10. KML 扩大超出不限阈值后自动改为有限授权并撤销已有不限会话。
11. KML 范围无效或超过总体阈值时不会自动回退为不受限访问。
12. 分享暂停、撤销、封禁、过期、轮换链接和修改密码后，已有不限授权立即失效。
13. 分享 Cookie 不能访问普通地图 catalog、其他分享或私有接口。
14. 管理后台可查看受影响分享并记录策略变更、自动降级和会话撤销审计。
15. 相关 `node:test`、前端契约测试、构建和浏览器端到端验证全部通过。

## 25. 分阶段实施建议

### 阶段 1：空间模型和服务端边界

- 数据库迁移和管理员设置模型。
- KML 坐标收集、外包矩形、余量、面积、对角线和反经线处理。
- 空间预检、分享保存校验和范围版本。
- 分享 catalog、瓦片校验、缓存隔离和边界瓦片策略。

### 阶段 2：2D 分享体验

- 创建和编辑分享交互。
- 2D 相机范围、最低缩放和越界入口控制。
- 我的分享、后台治理和审计状态展示。
- 半公开无密码分享端到端验收。

### 阶段 3：不限密码授权

- 会话模型支持 `finite` / `unlimited`。
- Cookie 持久化、Token 轮换、策略版本和批量撤销。
- KML 变化和管理员策略变化后的自动降级。

### 阶段 4：3D 安全开放

- 3D 相机目标、最大高度、影像和地形范围限制。
- 只在全部服务端资源路径通过空间测试后开放 3D 入口。

阶段之间不得以“前端已限制”为由提前开放尚未完成服务端边界的能力。

## 26. 已确定设计决策

1. 空间限制是服务端授权，不是前端显示偏好。
2. 允许区域使用全部 KML 坐标形成的轴对齐外包矩形，矩形内部均为可查看区域。
3. 范围计算包含全部有效分享项，不受默认显隐影响。
4. 边界余量由管理员控制，分享所有者首期只选择开关。
5. 不限授权只适用于设置密码且空间受限、范围合规的分享。
6. 管理员开启 `passwordlessSharingEnabled` 后，无密码空间受限分享可通过 `independent` 策略形成半公开模式，不创建无意义的授权会话。
7. 空间计算失败或策略收紧时不自动扩大为不受限访问。
8. KML 后续扩大超出不限阈值时自动降级为有限授权并撤销不限会话。
9. 3D 无法完整限制时必须隐藏或回退到 2D。
10. 当前没有正式用户，不保留旧范围或旧分享的兼容逻辑；测试分享删除后按新规则重建。

## 27. 实施前参数复核

以下数值已有建议默认值，但实施前需使用生产环境典型徒步、骑行、长距离轨迹和多点分享样本进行复核：

- `spatialPaddingMeters`。
- `spatialMaxAreaKm2`。
- `spatialMaxDiagonalKm`。
- `unlimitedAccessMaxAreaKm2`。
- `unlimitedAccessMaxDiagonalKm`。
- 各图源边界瓦片遮罩成本和最低可用缩放级别。

参数复核只能调整默认数值，不能放宽本文确定的服务端校验、会话撤销、无自动扩权和审计要求。
