# 用户管理与个人空间 KML 工具栏界面优化需求

> 状态：已实现，待发布验收
> 日期：2026-08-29
> 计划版本：v1.5.52
> 适用范围：管理后台用户管理、管理后台顶栏、个人空间“我的 KML”

## 1. 背景

当前管理后台的用户列表和新增用户表单纵向平铺。用户数量增长后，新增入口会被长列表推到页面底部，管理员需要滚动较长距离才能创建账号。后台顶栏的“个人空间”入口使用文字，而相邻的地图、刷新和退出均为紧凑图标，视觉与尺寸不一致。

个人空间“我的 KML”页同时展示文件筛选、排序、导入、新建、回收站、批量选择、批量删除和分享操作，现有 `account-toolbar` 缺少清晰分组，桌面端扫描成本高，移动端容易形成无序换行。

## 2. 目标

1. 用户列表和添加用户在同一页面内通过 Tab 切换，新增入口不受列表长度影响。
2. “后台添加用户”统一改为“添加用户”。
3. 管理后台“个人空间”入口与相邻顶栏图标保持相同尺寸、视觉重量和可访问语义。
4. “我的 KML”工具栏按筛选、文件级操作和批量操作形成稳定层级，桌面和移动端均无横向溢出。
5. “创建多 KML 分享”按钮缩短为“分享”，权限和创建流程保持不变。

## 3. 非目标

- 不改变用户列表、创建用户、角色分配、密码重置或配额接口。
- 不增加新的用户权限或改变既有 RBAC 门禁。
- 不改变 KML 筛选、排序、导入、回收站、批量删除或分享的数据行为。
- 不引入新的前端框架、图标依赖或原生阻塞弹窗。

## 4. 用户管理 Tab

- 页面顶部使用现有 `admin-settings-tabs` 组件体系呈现“用户管理”和“添加用户”。
- 默认打开“用户管理”；切换 Tab 只改变当前面板，不重新请求或丢失已加载列表。
- “添加用户”仅对具备 `admin.user.manage` 的管理员显示；只读管理员只看到用户列表，不显示不可用入口。
- Tab 使用 `role="tablist"`、`role="tab"`、`role="tabpanel"`、`aria-selected`、`aria-controls` 和 `hidden`。
- 创建成功后保留现有临时密码单次展示、安全再验证和用户列表刷新逻辑。

## 5. 管理后台顶栏

- “个人空间”入口改为单字符房屋图标 `⌂`，与现有地图、刷新和退出图标按钮使用相同容器样式。
- 链接继续指向 `/account#kml`。
- 必须同时提供 `aria-label="个人空间"` 和 `title="个人空间"`，不能仅依赖图形表达含义。

## 6. 我的 KML 工具栏

工具栏划分为三个语义区域：

1. 筛选区：搜索、状态、排序字段、排序方向和查询按钮。
2. 文件操作区：返回、新建目录、导入菜单、新建 KML 和回收站。
3. 批量操作区：已选数量、全选本页、批量移入回收站和“分享”。

具体规则：

- 导入 KML、从两步路导入和迁移本地数据收纳到“导入”菜单，减少常驻按钮数量；能力不可用的项目不渲染。
- “新建 KML”作为主要创建动作保留在文件操作区。
- 回收站数量继续显示；回收站视图的“返回”保持短文案。
- 批量操作区与文件操作区视觉分离；没有写权限或分享权限时按现有能力隐藏对应操作。
- “分享”按钮继续使用 `data-account-action="create-share"`，仅修改显示文案和布局。
- 桌面端筛选区优先占满可用宽度；窄屏时各区域按顺序纵向排列，输入框和选择器不得造成页面横向滚动。

## 7. 验收

- 用户总数较大或分页时，“添加用户”Tab 始终位于页面顶部可达。
- 只读用户管理权限不会看到“添加用户”Tab 或创建表单。
- 管理后台顶栏四个导航/操作按钮视觉尺寸一致，个人空间图标悬停可见说明。
- “我的 KML”工具栏在桌面、`390px`、`375px` 和 `320px` 视口下无重叠、无横向溢出，操作分组顺序稳定。
- 页面不再出现“后台添加用户”和“创建多 KML 分享”文案。
- `npm run check`、`npm test`、`npm run build` 和 `git diff --check` 全部通过。

## 8. 发布

- 使用补丁版本 `v1.5.52`。
- 先完成本地自动化与浏览器验收，再部署 161 和 66。
- 两台服务器均须在发布前建立可恢复备份，发布后执行双健康检查和版本核验。
- 66 继续强制关闭 Artalk 镜像，不改变生产环境密钥和 PM2 资源保护配置。
