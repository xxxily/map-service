# 用户体系、角色权限、个人空间与多 KML 分享需求

> 状态：核心功能已实施（验收中）  
> 版本：v1.0  
> 日期：2026-08-05  
> 适用范围：map-service 前台地图、用户中心、管理后台及 `/api/v1` 服务端接口

## 1. 文档目的

本文将“用户登录注册、角色权限、个人 KML、位置收藏、后台用户管理、多 KML 链接分享”统一为一套可实施的产品和系统需求，作为后续数据模型、接口、前端交互、迁移、测试和验收的共同基线。

本文重点解决以下问题：

- 现有系统只有单一管理员账号，无法表达普通用户、管理员和超级管理员的职责边界。
- 个人 KML 只保存在浏览器 `localStorage`，换设备、清缓存或更换浏览器后无法继续管理。
- 现有“公共 KML”只能由管理员发布为全站公共图层，不适合作为普通用户的私有数据分享机制。
- 当前缺少用户级位置收藏、个人分享管理和跨设备同步能力。
- 现有管理员 Bearer Token 保存在 `localStorage`，账号、会话和权限模型需要升级。

## 2. 核心设计结论

本需求采用以下基线方案：

1. 使用统一用户体系替换“普通用户无账号 + 单一管理员账号”的双轨模式。
2. 权限采用 RBAC：内置角色、权限码和可选自定义角色结合，服务端始终是最终授权判定方。
3. 内置角色至少包括普通用户 `user`、管理员 `admin`、超级管理员 `super_admin`。
4. 超级管理员拥有全部业务权限，但仍不能查看明文密码、绕过输入校验、安全边界或审计记录。
5. 登录态使用可撤销的服务端会话和 HttpOnly Cookie，不再把长期管理 Token 存入 `localStorage`。
6. 用户 KML 和位置收藏迁移为服务端持久化的个人数据；浏览器本地数据保留显式迁移入口，不自动上传。
7. 多 KML 分享使用独立“分享包”模型。一个分享包可以包含一个或多个 KML，并生成一个稳定、不可枚举的分享链接。
8. 用户 KML 默认始终私有。公开分享只授予分享包的只读访问权，不把原 KML 自动变成全站可发现的公共图层。
9. 现有管理员发布的“公共 KML”继续作为全站公共图层目录，与用户链接分享并存，避免概念和权限混淆。
10. 用户、会话、角色、KML 归属和分享关系需要事务及唯一约束，一期推荐使用 SQLite 和统一仓储层；不得继续拆成多个相互无约束的 JSON 文件。

## 3. 背景与现状

### 3.1 当前能力

- 管理后台使用一个由环境变量或 `.db/admin/auth.json` 提供的管理员账号。
- 管理后台登录后返回自签名 Bearer Token，前端保存在 `mapServiceAdminToken`。
- 前台个人 KML 存储在 `map_kml_list`，仅存在于当前浏览器。
- 管理员可把个人 KML 复制为服务端公共 KML；公共 KML 存储在 `.db/admin/shared-kml.json`。
- 公共 KML 只有 `draft`、`published`、`disabled` 状态，面向全站用户，不具备用户归属和独立分享链接。
- 前台已有独立的站点访问密码，可用 `map_access_token` Cookie 保护地图和部分公开接口。
- 位置收藏尚未实现，仅在总体路线文档中预留。

### 3.2 当前主要问题

- 单管理员模型无法支持人员增长、职责分工、停用账号和审计追责。
- 管理员密码历史实现允许明文持久化，不能继续作为正式用户系统基础。
- 前端只根据本地是否存在管理员 Token 判断管理员身份，存在状态过期和前端越权展示风险。
- 个人 KML 无服务端所有者，无法安全判断谁能查看、修改、删除或分享。
- “共享为公共 KML”本质是复制并全站发布，不具备撤销链接、有效期、多文件组合和分享管理能力。
- `localStorage` 数据没有版本冲突、配额、备份、跨设备同步和可靠恢复机制。

## 4. 产品目标与成功标准

### 4.1 产品目标

- 超级管理员可控制是否开放自助注册，并可在后台创建、停用用户和分配角色。
- 管理员可完成应用日常维护，但默认不能修改超级管理员、注册策略和根级安全设置。
- 普通用户登录后可跨设备保存、编辑、导入、导出和删除自己的 KML。
- 普通用户可保存和管理自己的位置收藏。
- 用户可选择一个或多个自己的 KML 创建只读分享链接，并可查看、修改、暂停、恢复或撤销分享。
- 登录用户、未登录用户在具备有效分享授权时都能查看分享内容。
- 任意用户均不能通过修改 ID、请求体或 URL 访问其他用户的私有数据。
- 现有个人 KML、管理员公共 KML和站点访问密码在升级后有明确兼容和迁移路径。

### 4.2 可衡量成功标准

- 注册开关关闭后，所有自助注册入口和接口均立即拒绝新注册，但不影响已有账号登录。
- 用户在设备 A 保存的 KML 和收藏，登录设备 B 后可以读取。
- 一个分享包至少可包含 20 个 KML；打开链接后可独立显示、隐藏各 KML。
- 分享撤销、过期或管理员封禁后，旧链接不能继续读取清单或 KML 数据。
- 自动化测试证明不存在普通用户横向读取、修改、删除他人 KML、收藏或分享的路径。
- 用户和管理 API 在单机正常负载下，列表及元数据请求的服务端 P95 响应时间目标不高于 300 ms；分享清单请求目标不高于 500 ms，不含客户端大 KML 渲染时间。

## 5. 范围

### 5.1 本需求纳入范围

- 用户注册、登录、退出、修改密码、会话查看和会话失效。
- 超级管理员控制注册开关。
- 后台创建用户、编辑用户基础信息、停用/启用用户、重置密码、强制退出。
- 内置角色、权限码、角色分配和自定义角色管理。
- 用户个人 KML 的服务端持久化、归属、配额、导入导出、跨设备同步和本地迁移。
- 用户位置收藏的新增、编辑、分类、检索、定位和删除。
- 单个或多个 KML 的分享包创建、编辑、查看、停用、恢复、撤销和链接轮换。
- 匿名只读分享页及其安全边界。
- 管理员对公开分享和用户数据的合规处置、审计和日常维护。
- 现有管理员认证、个人本地 KML和公共 KML 的迁移兼容。
- 对应 API、数据模型、测试、文档和开发记录要求。

### 5.2 暂不纳入范围

- OAuth、LDAP、企业 SSO、微信或其他第三方登录。
- 邮件、短信验证码和用户自助找回密码；一期由超级管理员重置为一次性临时密码。
- 多人实时协同编辑、评论、审批流和要素级协作锁。
- 将 KML 分享给指定用户或用户组并授予编辑权。
- 用户上传图片、视频等二进制附件；现有 KML 外部媒体仍按受控 URL 规则处理。
- 公开内容广场、搜索引擎收录、点赞、评论和社交推荐。
- 组织、租户、部门和项目空间；数据一期直接归属于用户。
- GPX、GeoJSON、KMZ 等格式的完整用户数据管理；接口和模型需为后续格式扩展预留。

## 6. 核心概念

### 6.1 用户账号

可登录系统的持久身份。账号具有稳定 ID、登录名、展示名、状态、角色和安全属性。

### 6.2 角色与权限

- 角色是一组权限码的集合。
- 用户可以拥有一个或多个角色，生效权限取并集。
- 内置角色用于保证系统始终存在可理解的基础权限模型。
- 前端根据权限控制入口和交互，服务端对每次请求重新鉴权，不能信任前端隐藏按钮。

### 6.3 用户 KML

由某个用户拥有的服务端 KML 数据。默认私有，只有所有者和具有全局数据管理权限的管理人员可以访问。

### 6.4 公共 KML 图层

由管理员维护、在前台公共图层目录中可发现的系统级 KML。它不是普通用户链接分享的别名。

### 6.5 分享包

用户针对一个或多个 KML 创建的只读分享集合。分享包拥有独立标题、公开 ID、状态、访问策略、文件顺序和默认地图视图。

### 6.6 位置收藏

用户保存的私有地点记录，统一以 WGS84 原始坐标持久化，渲染到特定底图时再执行坐标转换。

## 7. 用户角色与权限模型

### 7.1 角色定义

| 角色 | 代码 | 主要职责 |
| --- | --- | --- |
| 匿名访问者 | 无 | 浏览允许匿名访问的地图内容和有效公开分享；不能保存个人数据 |
| 普通用户 | `user` | 管理自己的 KML、收藏、分享和个人安全设置 |
| 管理员 | `admin` | 日常运维、公共图层管理、缓存与任务维护、分享合规处置和审计查看 |
| 超级管理员 | `super_admin` | 拥有全部业务权限，管理注册、用户、角色、关键安全设置和其他管理员 |
| 自定义角色 | 自定义稳定代码 | 由超级管理员按权限码组合，用于数据管理员、运维人员、只读观察者等细分职责 |

### 7.2 权限码基线

| 权限码 | 说明 | 普通用户 | 管理员 | 超级管理员 |
| --- | --- | ---: | ---: | ---: |
| `account.self.read` | 查看自己的账号信息 | 是 | 是 | 是 |
| `account.self.update` | 修改自己的展示名和密码 | 是 | 是 | 是 |
| `session.self.manage` | 查看和注销自己的会话 | 是 | 是 | 是 |
| `kml.own.read` | 查看自己的 KML | 是 | 是 | 是 |
| `kml.own.write` | 创建、修改、导入和删除自己的 KML | 是 | 是 | 是 |
| `share.own.manage` | 管理自己的分享包 | 是 | 是 | 是 |
| `favorite.own.manage` | 管理自己的位置收藏 | 是 | 是 | 是 |
| `admin.overview.read` | 查看后台概览 | 否 | 是 | 是 |
| `admin.cache.manage` | 管理缓存 | 否 | 是 | 是 |
| `admin.precache.manage` | 管理预缓存任务 | 否 | 是 | 是 |
| `admin.layer.manage` | 管理图源、图层和代理配置 | 否 | 是 | 是 |
| `admin.public_kml.manage` | 管理系统公共 KML 图层 | 否 | 是 | 是 |
| `admin.share.moderate` | 查看分享元数据并封禁违规分享 | 否 | 是 | 是 |
| `admin.audit.read` | 查看授权范围内审计日志 | 否 | 是 | 是 |
| `admin.user.read` | 查看脱敏用户列表 | 否 | 可选 | 是 |
| `admin.user.manage` | 创建、启停普通用户和重置密码 | 否 | 默认否 | 是 |
| `admin.role.manage` | 创建角色、修改权限和分配管理角色 | 否 | 否 | 是 |
| `admin.registration.manage` | 控制注册开关和默认注册角色 | 否 | 否 | 是 |
| `admin.security.manage` | 管理会话策略、访问策略和关键安全设置 | 否 | 否 | 是 |
| `kml.any.read` | 因运维或合规需要读取任意用户 KML | 否 | 默认否 | 是 |
| `kml.any.manage` | 管理任意用户 KML及其归属 | 否 | 默认否 | 是 |
| `system.super_admin` | 根级业务权限 | 否 | 否 | 是 |

### 7.3 权限规则

- 内置 `super_admin` 角色及其权限集合不可删除、不可降权。
- 系统必须始终保留至少一个状态为 `active` 的超级管理员。
- 删除、停用、降级最后一个超级管理员必须返回冲突错误。
- 管理员默认不能创建管理员、修改角色、修改注册策略或操作超级管理员。
- 自定义角色只能由超级管理员创建和修改，角色代码创建后不可变，显示名称可修改。
- 自定义角色不得包含 `system.super_admin`；超级管理员身份只能通过受保护的内置角色授予。
- 一期不支持给单个用户直接增减权限码，权限必须通过角色授予，避免形成无法审计的用户级例外。
- 用户权限发生变化或账号被停用后，其现有会话必须立即失效或在下一次请求时被拒绝。
- 对角色、用户状态、密码重置、分享封禁和根级设置的操作必须记录审计日志。
- 角色判断不得写死为前端 `isAdmin` 布尔值；前后端均使用权限集合判断能力。

## 8. 注册、登录与账号生命周期

### 8.1 注册开关

- 系统设置使用 `registration.mode` 表达注册策略，一期只允许：
  - `closed`：关闭自助注册。
  - `open`：开放自助注册。
- 升级已有部署时默认使用 `closed`，避免升级后意外开放注册。
- 只有拥有 `admin.registration.manage` 的超级管理员可以修改注册模式。
- 关闭注册只影响新账号自助创建，不影响已有账号登录，也不影响超级管理员从后台创建用户。
- 注册页和登录页必须从 `GET /api/v1/auth/config` 获取公开配置，不允许仅依赖前端构建变量决定是否显示注册入口。
- `POST /api/v1/auth/register` 在关闭注册时必须返回 `403 REGISTRATION_CLOSED`，即使调用者绕过前端直接请求。
- 注册开关变更应实时生效并写入审计日志。

### 8.2 注册字段与规则

一期自助注册字段：

| 字段 | 规则 |
| --- | --- |
| `username` | 3～32 个字符；使用字母、数字、点、下划线和短横线；忽略大小写唯一；创建后不可修改 |
| `displayName` | 1～50 个字符；允许中文；可由用户后续修改 |
| `password` | 默认至少 12 个字符，最大 128 个字符；允许粘贴和密码短语；不强制无意义的字符组合规则 |
| `email` | 一期可选，仅作为私有联系信息保存；没有验证前不得用于找回密码或作为可信身份 |

- 注册账号默认分配内置 `user` 角色。
- 自助注册请求不得允许提交角色、权限、账号状态或配额字段。
- 用户名冲突检查和数据库唯一约束均按规范化后的用户名执行。
- 登录和注册错误不得泄露已有用户名、邮箱或账号状态的敏感细节。
- 若后续增加人工审批，应新增明确状态和接口，不得复用 `disabled` 模糊表达。

### 8.3 密码存储与策略

- 密码只保存单向密码哈希，推荐 Argon2id；若一期使用 Node 原生能力，可使用参数经过基准测试的 `scrypt`。
- 每个账号使用独立随机盐，不得保存或记录明文密码。
- 不允许继续使用 `admin/admin` 作为生产默认账号密码。
- 超级管理员后台重置密码时，系统生成一次性临时密码或由超级管理员输入临时密码；响应只展示一次。
- 使用临时密码登录后必须先修改密码，完成前不能访问其他业务接口。
- 修改密码、重置密码、角色提升和关键安全设置应要求最近 10 分钟内完成过密码再验证。
- 不强制定期改密；发生泄露、管理员重置或安全策略升级时再强制修改。

### 8.4 登录与会话

- 使用服务端可撤销会话，浏览器通过 `HttpOnly`、`SameSite=Lax` Cookie 携带会话标识。
- HTTPS 环境必须设置 `Secure`；生产环境禁止通过明文 HTTP 传输账号密码和会话。
- Cookie 中只保存高熵随机会话令牌，数据库只保存令牌哈希。
- 默认会话有效期建议为 7 天；“记住我”最长建议为 30 天，具体值由超级管理员配置。
- 会话记录至少包含用户 ID、创建时间、过期时间、最后活动时间、设备摘要、IP 摘要和撤销时间。
- 用户可以查看自己的活跃会话，退出当前会话或退出其他所有会话。
- 管理人员可以强制注销目标用户的全部会话。
- 退出登录必须在服务端撤销会话并清除 Cookie，不得只由前端删除本地状态。
- 修改密码、账号停用、删除、角色提升或降级后，必须撤销受影响会话。
- 状态变更接口必须具备 CSRF 防护；同源检查、SameSite Cookie 和 CSRF Token 至少采用一种完整、可测试的组合方案。

### 8.5 登录安全

- 登录、注册、密码验证和分享密码验证必须限流。
- 限流至少同时考虑 IP、账号规范化标识和短时间失败次数，避免只按单一维度防护。
- 连续失败可触发短时锁定，响应统一使用“用户名或密码不正确”，不暴露账号是否存在。
- 成功登录或密码验证后只清理规范化账号桶和对应 IP + 账号组合桶；共享 IP 桶必须保留，防止攻击者用合法账号循环清空同一出口的密码喷洒计数。
- 审计日志不得记录密码、Cookie、会话令牌、CSRF Token 或完整敏感请求头。

### 8.6 账号状态

| 状态 | 说明 | 是否允许登录 |
| --- | --- | --- |
| `active` | 正常账号 | 是 |
| `disabled` | 管理员停用 | 否，现有会话失效 |
| `locked` | 因安全策略临时锁定 | 否，达到解锁条件后恢复 |
| `deleted` | 已删除或匿名化的逻辑状态 | 否 |

- 一期后台删除用户默认采用软删除，避免立即破坏数据归属和审计链。
- 硬删除前必须先明确处理用户 KML、收藏、分享和审计记录：转移、匿名化或永久删除。
- 管理员不能停用或删除权限高于自己的账号。

## 9. 后台用户与角色管理

### 9.1 用户管理页面

后台新增 `/admin/users`，支持：

- 按用户名、展示名搜索。
- 按账号状态、角色、创建时间过滤。
- 按创建时间、最后登录时间排序。
- 分页显示用户列表，默认每页 20 条，最大 100 条。
- 查看用户脱敏信息、角色、状态、KML 数量、收藏数量、活跃分享数量、最后登录时间和创建时间。
- 创建用户并指定初始角色。
- 修改展示名、可选邮箱、状态和配额。
- 分配或移除角色。
- 重置密码并强制下次登录修改。
- 强制注销全部会话。
- 查看与该用户相关的审计事件。

后台永远不得展示：

- 密码或密码哈希。
- 会话令牌或 Cookie。
- 分享密码明文。
- 不必要的完整 IP、敏感请求头或代理凭据。

### 9.2 角色管理页面

后台新增 `/admin/roles`，仅对 `admin.role.manage` 开放：

- 查看内置角色和自定义角色。
- 查看每个角色的权限、用户数量、创建人和更新时间。
- 从权限模板创建自定义角色。
- 修改自定义角色显示名、说明和权限集合。
- 删除没有用户引用的自定义角色。
- 有用户引用时禁止直接删除，必须先迁移用户角色。
- 所有权限变更必须展示影响用户数量并二次确认。

### 9.3 超级管理员保护

- 提升用户为超级管理员、移除超级管理员角色、停用超级管理员均属于高风险操作。
- 高风险操作需要最近密码再验证、统一确认弹窗和审计记录。
- 禁止用户移除自己的最后超级管理员身份。
- 超级管理员虽有全局业务权限，也不能读取密码明文、会话令牌哈希原文或服务端密钥。

## 10. 用户中心与前台身份体验

### 10.1 入口与页面

- 前台提供明确的“登录 / 注册”入口；登录后显示头像或展示名菜单。
- 用户中心建议路由为 `/account`，至少包含：
  - 个人资料。
  - 我的 KML。
  - 位置收藏。
  - 我的分享。
  - 登录与安全。
- 管理员和超级管理员在身份菜单中显示“管理后台”入口，但后台菜单仍按权限码过滤。
- 未登录访问需要账号的页面时，跳转登录并保留安全的站内回跳地址。
- 回跳地址只允许同源相对路径，防止开放重定向。

### 10.2 身份状态

- 应用初始化时通过 `GET /api/v1/auth/session` 获取当前用户和权限摘要。
- 前端不得只通过 Cookie 是否存在推断登录状态，也不得读取 HttpOnly Cookie。
- 会话失效时清理内存中的用户私有数据并提示重新登录，不删除访客本地 KML。
- 登出后用户服务端 KML、收藏和分享不得继续残留在当前页面可操作状态。

## 11. 个人 KML 数据管理

### 11.1 数据归属

- 每个用户 KML 必须有不可为空的 `ownerId`。
- 普通用户只能读取和操作 `ownerId` 为自己的 KML。
- 分享访问通过分享包授权，不改变 KML 的 `ownerId` 或私有属性。
- 管理员若因合规或运维读取用户 KML，必须具备 `kml.any.read` 并留下审计记录。
- 超级管理员可以转移 KML 归属，但必须记录原所有者、新所有者和原因。

### 11.2 KML 功能

登录用户应支持：

- 新建空白 KML。
- 导入 `.kml` 文件。
- 查看、搜索、排序和按更新时间过滤自己的 KML。
- 重命名、修改描述、主题色、坐标纠偏模式、拖拽锁定和默认显隐。
- 编辑点、线、面及其现有富媒体描述信息。
- 导出单个 KML。
- 批量选择、批量归档或删除。
- 查看每个 KML 被多少个分享包引用。
- 从回收站恢复或永久删除 KML。

### 11.3 默认 KML

- 每个用户首次进入个人空间时创建一个服务端默认 KML，用于快速新增点位和持续定位记录。
- 默认 KML 是用户级数据，不再使用全局固定 ID `default-kml`；每个用户拥有独立稳定 ID。
- 默认 KML不能直接永久删除，但可重命名；用户可选择另一个 KML 设为默认后再处理旧默认 KML。
- 访客仍可保留现有浏览器默认 KML，登录后由用户选择是否迁移。

### 11.4 保存与并发

- KML 记录包含递增 `revision` 或等价 ETag。
- 地图增量同步的每个 `create` 操作必须携带 1～160 字符的稳定 `clientId`，字符集限制为 ASCII 字母、数字、点、下划线、冒号和连字符；服务端以 `(ownerId, clientId)` 作为幂等键。服务端已提交但响应丢失后，客户端重放同一操作必须返回首次创建的 KML，不得重复占用文件或要素配额。
- 同步创建键必须独立于 KML 内容行持久化。KML 永久删除后旧 `clientId` 仍不可复用；旧请求重放必须返回稳定冲突，只有显式生成新的 `clientId` 才能创建副本。
- 私有 KML 响应可返回只对所有者同步有用的 `syncClientId`，恢复逻辑必须用它把“本地创建项”和“已提交服务端项”合并为一个工作项；公开分享、公开清单和下载响应不得返回该字段。
- 若 `create` 已发送但响应丢失，用户在重新关联服务端快照前删除了本地项，客户端必须持久化对应 `clientId` 的删除墓碑；服务端同步接口必须支持按当前用户的 `(ownerId, clientId)` 幂等移入回收站。删除请求早于 create 到达时，服务端也必须持久化用户范围的删除墓碑；随后乱序到达的旧 create 必须返回稳定冲突，不得创建文件。已永久删除时返回无副作用结果，并继续由创建账本阻止复活。
- 已同步 KML 移入回收站后，客户端必须保留带 `trashed` 状态、服务端 ID、revision 和内容指纹的快照。2D/3D 删除都必须在修改列表前写入撤销历史；撤销删除必须生成按 `kmlId` 的 `restore`，不得以相同 `clientId` 直接重新 create；恢复后若本地内容不同，再以恢复响应的新 revision 发送 `update`。删除先于 create 到达时，应保留无服务端 ID 的 trashed 快照；撤销时先按同一 `clientId` restore/cancel 服务端删除墓碑，再继续原 create。若该 restore 在途时用户重做删除，收到 absent 后必须重新保留 `clientId` 删除意图并续发 `trash(clientId)`，不得误报已保存。多阶段同步必须自动续跑至无剩余操作。
- 更新请求必须携带客户端已读取的版本；版本不一致时返回 `409 KML_REVISION_CONFLICT`。
- 前端发生冲突时不得静默覆盖，应提供重新加载、保留本地副本或另存为新 KML 的选项。
- 编辑状态需要显示“保存中 / 已保存 / 保存失败 / 存在冲突”。
- 登录账号的未同步修改必须按用户 ID 隔离保存恢复草稿，草稿至少包含工作文件、服务端快照、创建/更新/删除意图、已发出但尚未确认结果的精确操作批次和单调递增代次。
- 新同步批次发送前必须先把精确操作写为在途批次并等待完整草稿持久化成功；持久化失败时不得发送。成功响应先清除在途批次再归并服务端快照；带 HTTP 状态的明确失败表示事务未提交，应清除该批次并按错误处理；网络中断等无响应状态错误必须保留原批次，后续同步优先原样重放，再根据最新工作文件自动计算后续操作。
- 恢复包含 pending `trash` / `restore` 的草稿时，目标本地 ID 必须由 `clientId` 或草稿快照中的 `serverId -> localId` 映射得到；文件最终应存在还是缺失只以草稿的最新 `files` 为准，并同时保留原快照用于归并重放响应。当前服务器 active 清单不得覆盖请求在途期间发生的撤销或重做；该 pending presence 足以解释的服务器缺失、出现或 revision 变化不视为普通编辑冲突，其他文件的真实 revision 冲突仍须正常处理。用户选择加载服务器冲突版本或另存冲突副本后，只移除目标冲突项的旧 revision pending，其他非冲突在途操作继续重放。
- 完整恢复草稿以 IndexedDB 为唯一主载荷存储；`localStorage` 只同步保存用户 ID、代次、更新时间、文件数等轻量标记和删除墓碑，不得在每次编辑时同步序列化数 MB 的 KML。升级时应兼容读取旧版本遗留的完整 `localStorage` 草稿。
- 若新代次轻量标记已写入、但浏览器退出导致对应 IndexedDB 写入未完成，恢复时必须回退到上一代最近完整草稿并提示可能缺少最后一批修改；轻量标记不得遮蔽仍可恢复的完整记录。
- 页面隐藏、关闭和会话失效时，必须先保存恢复草稿，再清理账号内存数据或切换到访客数据。
- 收到 `409 KML_REVISION_CONFLICT` 后必须停止自动重试。冲突处理应支持加载服务器冲突版本、本地冲突版本另存为非默认 KML、保留草稿稍后处理。
- 冲突恢复必须保留其他未冲突的新建、修改和删除意图；服务器新增文件和本地未修改文件不得因旧快照被误判为客户端写入。
- 重新登录同一账号时可选择恢复、全部另存为新 KML 或丢弃草稿；不同用户之间不得发现或恢复彼此草稿。
- 大批量要素更新可以先使用整文件覆盖，但服务层必须校验所有权、版本、大小和要素结构。

### 11.5 导入和数据校验

- 单文件默认上限 10 MB，超级管理员可在安全范围内调整。
- 默认单 KML 最多 50,000 个要素；超过上限时拒绝并返回可理解错误。
- KML XML 解析必须禁止 XXE、外部实体和非预期网络访问。
- 要素必须经过 normalize、validate、sanitize 流程。
- 原始空间坐标统一按 WGS84 存储；底图纠偏仅发生在渲染层。
- 名称、描述和富媒体链接继续执行现有 XSS、协议、iframe 白名单和 SSRF 安全规则。
- 导入前显示文件名、大小、要素数量、几何类型和无法识别项摘要。

### 11.6 配额

推荐默认值：

| 配额 | 默认值 | 说明 |
| --- | ---: | --- |
| 每用户 KML 数量 | 100 | 含回收站，不含系统公共 KML |
| 单 KML 文件大小 | 10 MB | 指导入源文件或等价序列化数据上限 |
| 单 KML 要素数 | 50,000 | 防止解析和渲染失控 |
| 每用户总要素数 | 200,000 | 可由超级管理员按用户覆盖 |
| 回收站保留时间 | 30 天 | 到期后异步永久清理 |

- 达到配额时不得部分写入。
- 管理后台可查看用量，但不应默认读取用户内容。
- 配额变更必须验证新值不会低于当前已用量，或明确进入“只读直到降至配额内”状态。

## 12. 位置收藏

### 12.1 基础功能

登录用户可以从以下入口保存位置：

- 搜索结果。
- 地图长按或坐标拾取结果。
- 当前定位。
- KML 点位详情。

地图工具栏不提供单独的“收藏当前地图中心”按钮；地图收藏应通过长按、坐标拾取或其他明确的候选位置交互完成，避免与点位弹窗收藏入口重复。

收藏管理支持：

- 新增、重命名、修改备注和删除。
- 设置分类、标签和颜色。
- 按名称、地址、备注、分类和标签检索。
- 点击收藏后定位地图并显示详情。
- 复制 WGS84 坐标。
- 按创建时间、更新时间和名称排序。

### 12.2 收藏字段

| 字段 | 说明 |
| --- | --- |
| `id` | 稳定收藏 ID |
| `ownerId` | 所有者用户 ID |
| `name` | 收藏名称 |
| `note` | 用户备注 |
| `longitude` / `latitude` | WGS84 坐标 |
| `sourceType` | `search` / `map` / `location` / `kml` / `manual` |
| `sourceRef` | 可选来源引用；公开响应不得泄露他人私有 KML ID |
| `address` | 可选地址文本 |
| `category` | 可选分类 |
| `tags` | 字符串数组 |
| `color` | 展示颜色 |
| `createdAt` / `updatedAt` | ISO 8601 时间 |

- 收藏默认永远私有。
- 一期分享包不包含收藏；未来如需分享，应显式复制为 KML 要素或新增独立分享类型。
- 删除来源 KML 不应自动删除用户收藏，但来源引用需标记失效。

## 13. 多 KML 分享

### 13.1 分享语义

- 用户 KML 默认私有。
- 用户点击“公开分享”时实际创建或更新一个 `public_link` 分享包。
- `public_link` 表示任何获得有效链接的人可以只读查看，但该内容不会自动进入全站公共 KML 列表，也不应被公开搜索接口枚举。
- 一个 KML 可以加入多个分享包；一个分享包可以包含多个 KML。
- 分享包引用 KML 当前版本，默认是“实时引用”而非静态快照。所有者保存 KML 后，访问者下次加载看到最新内容。
- 后续如需冻结版本，应新增 `snapshot` 模式，不能把快照语义混入一期实时引用。

### 13.2 创建分享包

用户在“我的 KML”中可多选 1～20 个 KML，点击“创建分享”，填写：

- 分享标题，默认由所选 KML 名称生成。
- 可选说明。
- KML 顺序和默认显隐状态。
- 默认地图视图：中心点、缩放级别、旋转角度、底图 ID、2D/3D 模式。
- 是否允许下载原 KML，默认允许。
- 可选过期时间，默认永不过期。
- 可选分享密码。分享密码是面向临时访问的独立口令，长度为 4～128 位，不沿用账号密码的 12 位强度和常见密码限制；服务端仍必须哈希保存并执行独立失败限流。

创建成功后返回：

- 内部分享 ID `id`，只用于所有者管理 API。
- 公开 ID `publicId`，只用于分享 URL 和匿名访问 API。
- 规范分享链接 `/share/<publicId>`。

### 13.3 公开 ID 与链接安全

- `publicId` 必须由密码学安全随机数生成，随机熵不少于 128 bit。
- 禁止使用自增 ID、用户名、KML ID、时间戳或可预测短码作为公开 ID。
- 内部分享 ID 和公开 ID必须分离，避免公开链接暴露内部数据关系。
- 分享链接默认不包含访问 Token、用户 ID、文件名或中文名称。
- 用户可以“轮换链接”；轮换后旧 `publicId` 立即失效，分享内容和内部管理 ID不变。

### 13.4 分享状态

| 状态 | 说明 | 公开链接行为 |
| --- | --- | --- |
| `draft` | 尚未公开或暂存配置 | 404 |
| `active` | 正常分享 | 按访问策略返回 |
| `paused` | 所有者临时暂停 | 410 或统一不可用页 |
| `revoked` | 所有者永久撤销或链接已轮换 | 404，不披露曾经存在 |
| `blocked` | 管理员因安全或合规封禁 | 404，对所有者显示后台原因 |
| `expired` | 已超过有效期 | 410 |

- 分享过期状态可在读取时动态判断，但响应和管理列表应统一显示 `expired`。
- 用户可从 `paused` 恢复到 `active`。
- `revoked` 默认不可恢复；如需继续分享，应创建新分享或轮换链接。
- 管理员封禁不得删除原 KML，除非另有具备权限且被审计的数据处置操作。

### 13.5 分享内容变更规则

- 所有者可以向现有分享包增加或移除 KML、调整顺序、修改标题和默认视图，规范分享 URL 保持不变。
- KML 被移入回收站后，公开分享清单中立即不再返回该文件。
- 分享包仍有其他有效 KML 时继续可用；最后一个有效 KML 被移除时自动转为 `paused`。
- 恢复 KML 不自动恢复其原分享引用，避免意外再次公开；由用户确认后重新加入。
- 永久删除 KML 前必须提示其被多少个分享包引用。
- KML 所有权转移时，默认从原所有者的分享包移除；超级管理员可在明确确认后同时转移分享归属。

### 13.6 匿名分享查看页

分享页 `/share/<publicId>` 应：

- 无需用户账号登录即可查看有效 `public_link` 分享。
- 显示分享标题、说明、更新时间和 KML 图层清单。
- 按分享配置恢复底图、旋转和 2D/3D 模式；全部默认可见 KML 加载完成且存在有效点、线或面时，首屏必须自动适配这些内容的联合几何范围，配置中心点和缩放级别只作为没有有效几何内容时的兜底。
- 每个 KML 独立加载、显示和隐藏；图层面板必须展示完整点、线、面要素列表，点击任一要素可定位并打开对应信息窗口。
- 复用现有 KML 渲染、详情面板、图片大图、视频/音频/受控页面预览和安全过滤能力，浏览体验与常规 KML 保持一致；只移除新增、编辑、拖拽、删除和重新分享等写操作。
- 分享页不得额外显示遮挡地图的分享横幅；分享标题和说明保留在 KML 管理面板内。
- 某一个 KML 加载失败时展示单项错误，不阻断其他 KML。
- 分享整体没有可用 KML 时显示明确不可用状态。
- 不把分享内容写入访问者的个人 KML 或 `map_kml_list`。
- 不向匿名访问者返回所有者邮箱、登录名、内部用户 ID、管理备注或内部 KML ID。
- 所有者可选择是否公开展示自己的 `displayName`；默认不展示。

### 13.7 下载规则

- `allowDownload=false` 时不展示下载按钮，公开导出接口必须拒绝请求。
- 禁止下载只是一项产品访问控制，不能被描述为 DRM；浏览器已获得的可视数据无法保证绝对不可复制。
- 多 KML 下载可先逐文件下载；后续如增加 ZIP，必须防止路径穿越、压缩炸弹和超大输出。

### 13.8 站点访问密码与公开分享

用户账号登录、站点访问密码和分享授权是三套不同概念：

- 用户账号决定个人数据和后台权限。
- 站点访问密码保护常规地图入口和现有公开资源。
- 分享授权决定某个分享包是否可以被链接访问。

超级管理员设置 `share.publicAccessPolicy`：

| 值 | 行为 |
| --- | --- |
| `independent` | 有效公开分享无需账号登录，也无需站点访问密码；符合面向外部分享的预期 |
| `inherit_site_access` | 无需账号登录，但若站点访问密码已启用，仍需先通过站点访问验证 |

- 已有部署升级时默认使用 `inherit_site_access`，防止升级后意外扩大公开范围。
- 超级管理员显式切换为 `independent` 后，前端才可使用“任何获得链接的人均可直接查看”的文案。
- 创建分享时必须显示当前实际生效的访问范围，避免用户误判。

### 13.9 与公共 KML 图层的区别

| 维度 | 用户分享包 | 管理员公共 KML 图层 |
| --- | --- | --- |
| 发现方式 | 仅持有链接者 | 前台公共图层目录可发现 |
| 所有者 | 普通用户或管理员个人 | 系统或管理团队 |
| 文件数量 | 一个分享包可包含多个 KML | 每条公共图层记录通常对应一个 KML |
| 主要用途 | 临时或定向只读分享 | 全站标准数据发布 |
| 管理入口 | 我的分享 | 后台 KML 管理 |
| 生命周期 | 暂停、撤销、过期、轮换链接 | 草稿、发布、禁用 |

- 普通用户不能自行把 KML 发布到公共图层目录。
- 管理员可以在获得 `admin.public_kml.manage` 且有合法数据来源的前提下，把用户 KML复制为公共图层；该操作必须明确提示“生成独立副本”，并记录审计。

## 14. 管理员日常维护与超级管理员控制

### 14.1 管理员默认职责

管理员默认可以：

- 查看系统概览和健康状态。
- 管理缓存和预缓存任务。
- 管理图源、图层、代理和公共 KML。
- 查看公开分享元数据、访问异常和安全告警。
- 因违规、安全或资源滥用封禁分享。
- 查看授权范围内的审计日志。

管理员默认不可以：

- 开放或关闭注册。
- 创建或提升其他管理员。
- 修改角色权限。
- 停用超级管理员。
- 查看用户密码、会话令牌或私有 KML 内容。
- 修改根级会话、安全和数据保留策略。

仅拥有 `admin.share.moderate` 的管理员只能查看分享标题、状态、文件数量、用量和访问异常等元数据；读取分享中的实际 KML 内容仍需单独具备 `kml.any.read`。

### 14.2 超级管理员能力

超级管理员可以：

- 管理注册策略、默认角色、密码策略、会话策略和分享公开策略。
- 创建、编辑、启停和软删除用户。
- 分配内置角色和自定义角色。
- 创建、修改和删除自定义角色。
- 强制注销用户会话、重置密码和解除锁定。
- 在审计约束下查看、转移或删除任意用户数据。
- 管理管理员和其他超级管理员，但仍受“至少一个有效超级管理员”保护。
- 查看完整审计范围和系统数据用量。

## 15. 数据模型

### 15.1 持久化原则

- 一期推荐使用 SQLite 文件，例如 `.db/map-service.sqlite`，通过统一 repository/service 层访问。
- 不允许路由层直接执行 SQL或直接读写 JSON 文件。
- `service/bin/admin/store.js` 可继续保存非关系型运行设置，但用户、角色、会话、所有权和分享关系应进入事务型存储。
- 所有数据库变更使用版本化迁移，迁移可重复检测且失败时可回滚或从备份恢复。
- 时间统一存储为 UTC，接口使用 ISO 8601 字符串返回。

### 15.2 核心实体

#### `User`

| 字段 | 说明 |
| --- | --- |
| `id` | 稳定、不可猜测的用户 ID |
| `usernameNormalized` | 规范化登录名，唯一索引 |
| `usernameDisplay` | 用户输入的显示形式 |
| `displayName` | 展示名 |
| `email` | 可选私有邮箱 |
| `passwordHash` | 密码哈希 |
| `status` | `active` / `disabled` / `locked` / `deleted` |
| `mustChangePassword` | 是否必须改密 |
| `quota` | 可选用户级配额覆盖 |
| `createdAt` / `updatedAt` / `lastLoginAt` | 时间字段 |

#### `Role`、`Permission`、`UserRole`、`RolePermission`

- `Role.code` 稳定唯一；内置角色带 `isBuiltIn=true`。
- `Permission.code` 由代码和数据库共同约束，未知权限码不得保存。
- 多对多关系必须有唯一约束，避免重复授权。

#### `Session`

- 保存用户 ID、令牌哈希、权限版本、过期时间、最后活动时间、撤销状态和设备摘要。
- 权限版本变化后旧会话失效，避免角色变更后继续沿用旧权限。

#### `KmlDocument`

| 字段 | 说明 |
| --- | --- |
| `id` | 稳定 KML ID |
| `ownerId` | 所有者用户 ID，必填索引 |
| `name` / `description` | 名称与说明 |
| `isDefault` | 是否为用户默认 KML |
| `status` | `active` / `trashed` |
| `coordCorrection` | 坐标纠偏配置 |
| `theme` / `color` / `lockDrag` | 展示和编辑配置 |
| `features` | 规范化要素数据；一期可用 JSON 存储，服务层统一校验 |
| `featureCount` / `byteSize` | 配额和列表摘要字段 |
| `revision` | 乐观锁版本 |
| `sourceType` | `created` / `imported` / `migrated` / `copied` |
| `createdAt` / `updatedAt` / `deletedAt` | 时间字段 |

#### `KmlShare`

| 字段 | 说明 |
| --- | --- |
| `id` | 内部分享 ID |
| `publicId` | 高熵公开 ID，唯一索引 |
| `ownerId` | 分享创建者 |
| `title` / `description` | 分享展示信息 |
| `status` | `draft` / `active` / `paused` / `revoked` / `blocked` |
| `accessMode` | 一期为 `public_link`，预留后续模式 |
| `passwordHash` | 可选分享密码哈希 |
| `allowDownload` | 是否允许下载 |
| `expiresAt` | 可选过期时间 |
| `viewConfig` | 默认地图视图和底图配置 |
| `revision` | 分享配置版本 |
| `blockedReason` | 仅所有者和有权限管理员可见 |
| `createdAt` / `updatedAt` / `lastAccessedAt` | 时间字段 |

#### `KmlShareItem`

- 字段至少包括 `shareId`、`kmlId`、`position`、`visibleByDefault`、可选 `displayName`。
- `(shareId, kmlId)` 唯一。
- 通过外键或服务层约束保证加入分享时 KML 归属于分享所有者。

#### `FavoritePlace`

- 使用第 12.2 节字段，`ownerId` 建索引。
- 坐标范围必须校验，经度 `[-180, 180]`、纬度 `[-90, 90]`。

#### `AuditLog`

- 字段至少包括操作者、动作、目标类型、目标 ID、结果、原因、时间、IP 摘要和结构化差异摘要。
- 不保存密码、Token、Cookie、KML 全文或敏感请求头。

### 15.3 关键约束和索引

- 规范化用户名唯一。
- 公开分享 ID 唯一。
- 每个用户最多一个 `isDefault=true AND status=active` 的 KML。
- 用户、KML、收藏和分享列表按 `ownerId + updatedAt` 建索引。
- 分享项按 `shareId + position` 建索引。
- 会话按令牌哈希唯一，并按用户和过期时间建索引。
- 删除用户、KML和角色时不得依赖不透明的级联删除；服务层必须执行明确策略并记录审计。

## 16. API 契约草案

### 16.1 通用约定

- 基础路径统一为 `/api/v1`。
- JSON 响应继续使用现有 `jsonSuc` / `jsonErr` 结构。
- 错误对象增加稳定机器错误码：

```json
{
  "code": -1,
  "result": null,
  "error": {
    "code": "REGISTRATION_CLOSED",
    "message": "当前未开放注册"
  }
}
```

- ID 均为稳定不透明字符串，URL 不使用用户名、显示名或中文名称作为主键。
- 时间均为 ISO 8601 UTC 字符串。
- 列表接口默认 `page=1&limit=20`，`limit` 最大 100，并返回：

```json
{
  "items": [],
  "page": 1,
  "limit": 20,
  "total": 0
}
```

- 排序参数使用 `sort=<field>&order=asc|desc`；每个接口只接受文档明确列出的字段。
- 私有 API响应使用 `Cache-Control: no-store`；Service Worker 不缓存 `/api/`。
- 所有修改请求校验 `Content-Type`、请求体大小和 CSRF。

### 16.2 认证接口

| 方法 | 路径 | 鉴权 | 用途 |
| --- | --- | --- | --- |
| `GET` | `/api/v1/auth/config` | 无 | 返回注册开关和公开密码策略摘要 |
| `POST` | `/api/v1/auth/register` | 无 | 自助注册 |

| `POST` | `/api/v1/auth/reauth` | 登录 | 再次验证当前密码，在服务端标记短时高可信会话 |
| `POST` | `/api/v1/auth/password` | 登录 + 最近再验证 | 修改自己的密码 |

```json

```

登录成功响应不返回会话令牌：

```json
{
  "code": 0,
  "result": {
    "user": {
      "id": "usr_7mQ...",
      "username": "map-user",
      "displayName": "地图用户",
      "roles": ["user"],
      "permissions": ["kml.own.read", "kml.own.write", "share.own.manage", "favorite.own.manage"]
```

| `GET` | `/api/v1/admin/audit-logs` | `admin.audit.read` | 查询审计日志 |

后台创建用户请求不得接受密码哈希、会话、审计字段或未知权限码。

| HTTP | 错误码 | 场景 |

## 17. 前端交互要求

### 17.1 通用要求

- 登录、注册、用户管理、分享配置和删除确认均使用项目统一 Dialog 组件体系。
- 禁止使用 `alert`、`confirm`、`prompt` 及其 `window.*` 形式。
- 所有表单显示字段级错误、提交中状态和服务端错误，不以静默失败结束。
- 权限不足时不显示不可用主操作；直接访问路由或调用接口时仍由服务端返回 403。
- 桌面和移动端均需支持主要账号、KML、收藏和分享流程。

### 17.2 KML 数据管理页

- 提供“新建、导入、批量选择、创建分享、回收站”入口。
- KML 卡片或表格显示名称、要素数、更新时间、分享引用数、保存状态和是否默认。
- 支持多选 KML 后一次创建分享包，不要求逐个分享。
- 单个 KML 的“分享”入口可以创建只包含当前文件的分享包，也可以将其加入已有分享包。
- 分享状态不能只用模糊的“公开/私有”开关表示，应展示“未分享、已加入 N 个分享、分享已暂停”等真实状态。

### 17.3 我的分享页

- 显示标题、包含 KML 数量、状态、访问策略、创建时间、更新时间、过期时间和最近访问时间。
- 支持复制链接、打开预览、编辑内容、暂停、恢复、轮换链接和撤销。
- 复制链接后使用非阻塞提示。
- 暂停、轮换和撤销必须说明对旧链接的影响。
- 被管理员封禁时显示原因和只读状态，不提供绕过或自行恢复入口。

### 17.4 收藏页

- 支持列表和地图联动。
- 点击收藏时关闭其他临时状态并定位对应位置。
- 删除使用统一确认弹窗；批量删除需显示数量。
- 移动端收藏列表不能永久遮挡地图，应支持收起或底部面板模式。

## 18. 安全与隐私要求

### 18.1 鉴权与越权防护

- 所有用户私有资源必须在服务层校验所有权或显式全局权限。
- 不能仅依赖查询条件 `ownerId`，更新和删除时必须再次验证目标资源归属。
- 对无权访问的私有资源统一返回 404，降低 ID 枚举价值。
- 管理员权限必须细分，不能继续用一个全能 `scope=admin` Token 代替。
- 角色和权限只接受服务端已知枚举，忽略或拒绝客户端提交的未知字段。

### 18.2 分享安全

- 公开 ID 使用安全随机数并限流，禁止提供可枚举的公开分享列表。
- 分享密码必须哈希保存并设置独立失败限流；创建或更换时接受 4～128 位口令，不套用账号密码的 12 位和常见密码规则。
- 分享清单和 KML 响应必须脱敏，不返回所有者私有信息和内部管理字段。
- 分享撤销、封禁、过期和轮换后应即时生效；一期公开 API 建议 `Cache-Control: no-store`，避免缓存延迟泄露。
- 富媒体 URL 继续禁止内网、localhost、link-local、metadata 服务和非预期协议。
- 不新增任意 URL 代理入口。
- 受控图源、派生资源和代理测试目标必须在每次回源前校验全部 DNS 结果并禁止内网、metadata、link-local、组播及保留 IPv4/IPv6；直连必须固定到已验证地址，代理模式必须让代理连接已验证 IP 并保留原 HTTP `Host` 与 HTTPS SNI/证书主机名，所有路径均禁止跟随重定向。

### 18.3 XSS、CSRF 与注入

- KML 名称、描述、收藏备注、分享标题和用户展示名输出前必须转义或使用受控渲染。
- KML 原始 HTML 不直接注入页面；继续复用现有内容解析和安全分类。
- 数据库查询使用参数绑定，不拼接用户输入。
- Cookie 会话下所有状态变更请求必须具备 CSRF 防护。
- 回跳地址、分享外链和富媒体链接必须校验协议及来源规则。

### 18.4 隐私最小化

- 匿名分享页默认不展示所有者登录名和邮箱。
- 管理员列表只展示完成管理工作所需的脱敏信息。
- IP 只保留安全审计需要的摘要或受限字段，并配置保留期限。
- 审计日志不得保存 KML 全文和收藏备注全文，必要时保存资源 ID和变更摘要。

## 19. 非功能需求

### 19.1 可靠性

- 用户创建、角色分配、分享创建和分享项写入使用数据库事务。
- 任何失败不得留下“分享已创建但没有分享项”等半完成状态。
- 数据库写入失败时前端保留未保存状态并允许重试。
- 数据库文件、迁移版本和关键运行设置纳入备份；恢复演练需验证用户、KML、收藏和分享关系完整。

### 19.2 性能

- KML 列表、分享列表和用户列表只返回摘要，不返回完整要素数组。
- 分享页先获取轻量清单，再按默认显隐和用户操作并行限量加载各 KML。
- 同时加载多个大 KML 时限制并发，显示单项进度并支持取消。
- 对大量点位继续复用现有视口过滤和 LOD 机制。
- 数据库访问必须有针对所有者、状态、更新时间和公开 ID的索引。

### 19.3 可用性与可访问性

- 登录、注册和关键管理表单支持键盘操作、正确标签、错误关联和焦点恢复。
- 状态不能只依赖颜色表达。
- 会话过期、配额不足、保存冲突和分享不可用均提供可行动的中文提示。
- 网络暂时失败不能导致本地正在编辑的 KML 内容立即丢失。

### 19.4 可观测性

- 记录登录成功/失败统计、注册量、活跃会话、KML 数量、分享创建/访问/撤销量、配额拒绝和公开接口错误率。
- 日志使用资源 ID和错误码，不记录密码、Token、Cookie 或 KML 大片段。
- 管理后台提供用户系统健康摘要：数据库状态、会话数、分享数、存储用量和最近迁移版本。

## 20. 迁移与兼容方案

### 20.1 超级管理员初始化

- 数据库首次初始化时，从部署配置显式创建首个超级管理员。
- 现有 `MAP_SERVICE_ADMIN_USERNAME` / `MAP_SERVICE_ADMIN_PASSWORD` 可用于一次性引导迁移，但密码必须立即哈希写入新用户库。
- 数据库已存在超级管理员后，环境变量不得在每次启动时覆盖其密码。
- 数据库没有有效超级管理员、且显式引导用户名命中已有普通或停用账号时，必须用引导密码重新哈希该账号、递增权限版本、撤销全部旧会话后再授予超级管理员；不得让旧密码或旧会话继承新增权限。
- 若检测到默认 `admin/admin` 或弱密码，必须要求首次登录立即修改。
- 迁移后旧管理 Bearer Token 统一失效，管理员重新登录并使用新会话 Cookie。

### 20.2 现有本地 KML 迁移

- 登录后检测 `map_kml_list`，显示一次性迁移向导。
- 向导展示本地 KML 数量、要素总数、预计用量和重名处理策略。
- 用户可以全选、部分选择或暂不迁移。
- 迁移成功后默认保留本地备份，并明确提供“确认后清理本地副本”操作。
- 不允许在用户未确认时自动把浏览器本地 KML上传到账号。
- 本地固定 `default-kml` 迁移后生成用户级新 ID；若服务端已有默认 KML，则作为普通 KML 导入并提示重命名。
- 批次迁移接口应支持幂等批次 ID，避免网络重试产生重复文件。

### 20.3 现有公共 KML 迁移

- `.db/admin/shared-kml.json` 中的数据迁移为系统所有的公共 KML 数据。
- 尽量保留现有公共 KML ID；若必须生成新 ID，应维护迁移映射和兼容别名。
- 现有 `/api/v1/kml/shared` 可在兼容期继续提供公共图层接口，不得改为用户分享接口。
- 后台现有 KML 管理页继续管理公共图层，后续可在 UI 中明确改名为“公共 KML 图层”。

### 20.4 站点访问密码兼容

- 现有 `map_access_token` 与用户登录会话互不替代。
- 升级后保留当前站点访问密码行为。
- `share.publicAccessPolicy` 在已有部署默认 `inherit_site_access`。
- 登录用户如果尚未通过站点访问密码，是否可访问常规地图由站点策略决定；不得因“已登录”自动绕过，除非超级管理员明确配置。

### 20.5 回滚与备份

- 执行用户系统迁移前自动备份 `.db/admin/` 和新数据库文件。
- 迁移写入版本号和结果摘要，不在日志中输出用户敏感数据。
- 迁移失败时服务不得带着半完成权限模型继续提供写入，应回滚事务并进入明确故障状态。

## 22. 验收标准

### 22.1 注册与账号

- 超级管理员可以开启或关闭注册，普通管理员不能修改该设置。
- 关闭注册时注册页不展示入口，直接请求注册接口仍返回明确错误。
- 超级管理员能在后台创建用户、分配角色、停用账号、重置密码和强制退出。
- 被停用用户无法登录，已有会话立即失效。
- 系统无法停用、删除或降级最后一个有效超级管理员。
- 密码、会话令牌和分享密码不以明文持久化或返回。

### 22.2 角色权限

- 普通用户只能使用个人 KML、收藏和分享能力。
- 管理员可以执行被授权的日常维护，但不能修改注册策略、角色或超级管理员。
- 超级管理员具备全部业务管理能力。
- 自定义角色修改后，相关用户权限按设计及时生效。
- 前端隐藏越权入口，服务端对伪造请求返回 403 或防枚举 404。

### 22.3 个人 KML

- 用户新建、导入、编辑和删除的 KML 在重新登录和更换设备后仍存在。
- 两个用户不能读取或修改彼此的私有 KML。
- 本地 KML 只能在用户确认后迁移，迁移失败不删除本地数据。
- 并发版本冲突不会静默覆盖较新数据。
- KML 配额、文件大小、XML 安全和富媒体安全边界均生效。

### 22.4 多 KML 分享

- 用户可以选择一个或多个自己的 KML 创建一个分享链接。
- 未登录用户在满足实际访问策略时可以打开链接并查看全部授权 KML。
- 分享页支持各 KML 独立显隐，并展示完整点、线、面要素列表；点击要素可定位、查看详情和进入富媒体预览，但不能编辑。
- 分享页首次加载后自动适配全部默认可见 KML 的联合几何范围，不显示额外分享横幅；仅当没有有效几何内容时使用分享配置或系统默认视图兜底。
- 修改分享包内文件、顺序和默认视图后链接保持不变。
- 暂停、撤销、过期、轮换或管理员封禁后，旧链接按状态不可访问。
- 分享响应不包含所有者邮箱、内部用户 ID、内部 KML ID或管理备注。
- 用户删除被分享 KML 前能看到影响范围；删除后分享不会暴露已删除内容。

### 22.5 收藏与后台维护

- 用户可从搜索结果和 KML 点位保存收藏，并跨设备管理；单次定位成功仅更新地图位置与左下角状态，不展示收藏快捷条，也不要求提供独立的地图中心工具栏收藏按钮。
- 收藏统一保存 WGS84 坐标，切换底图不会改变原始坐标。
- 管理员能完成缓存、预缓存、图层、公共 KML和分享合规维护。
- 所有高风险管理操作均可在审计日志中追溯，且日志不包含敏感明文。

## 23. 分期实施建议

### 阶段 0：数据与安全基础

- 引入 SQLite、仓储层和数据库迁移框架。
- 建立用户、角色、权限、会话和审计模型。
- 完成首个超级管理员引导和旧管理员认证迁移。

- 位置收藏 CRUD 和地图联动。

每个阶段均必须先完成后端契约、服务方法、测试和文档，再进行对应前端对接。

- 本需求扩展 [管理后台 MVP](./admin-console-mvp.md) 中明确暂不纳入的多用户和角色权限，并规划替换其单一管理员认证方式。
- [KML 公共图层共享管理需求](./kml-shared-layers.md) 继续约束管理员公共图层；普通用户分享以本文“分享包”为准，两者不得复用同一公开语义。
- [地图分享、KML 标注工作流与访问密码调整需求](./map-share-kml-workflow-and-access-password.md) 中的地图视图 URL 分享继续保留；本文新增的是具备服务端授权和多 KML 数据的分享链接。
- [访问控制加固需求](./access-control-hardening.md) 中的站点访问密码继续作为部署级入口保护；其与用户会话、公开分享的优先关系以本文第 13.8 节为准。

## 25. 实施前需确认但不阻塞架构的产品项

本文已给出推荐默认值，实施排期前仍需由产品负责人最终确认：

1. 新部署的 `share.publicAccessPolicy` 是否直接默认 `independent`；已有部署必须默认 `inherit_site_access`。
2. 一期是否同时交付分享密码，还是仅预留模型并在阶段 4 实现。
3. 普通管理员是否默认拥有 `admin.user.read`，推荐默认关闭，仅给确有运维需要的自定义角色。
4. 用户是否可以自助注销账号；推荐一期不开放，先由超级管理员软删除并完成数据处置流程。

## 26. 实施结果与验收说明

### 26.1 已实施能力

- SQLite v4 数据库、幂等迁移、外键、WAL、事务、KML 同步创建幂等键、永久删除账本、删除先行墓碑和内置角色/权限初始化。
- 首个超级管理员安全引导、弱密码强制修改、注册统一受理、注册开关、多维登录/注册限流、可撤销会话、CSRF、最近再验证和审计脱敏；成功登录不会清空共享 IP 限流桶。
- 普通用户、管理员、超级管理员和自定义角色的权限码授权；最后一个超级管理员保护和角色变化后的会话失效。
- 用户中心的资料、密码、会话、个人 KML、回收站、本地迁移、收藏和多 KML 分享管理。
- 2D/3D 地图登录账号 KML 加载、按权限只读或读写、分页拉取、幂等增量同步、用户隔离恢复草稿、revision 冲突处理闭环和会话失效前草稿保存；会话失效监听先于账号加载/恢复绑定，访客 localStorage 与账号数据不自动混用。
- 分享包 1～20 个 KML、稳定分享链接、文件顺序、默认显隐、视图配置、密码、有效期、下载开关、暂停、恢复、撤销和链接轮换。
- 匿名只读分享页、多 KML 独立显隐、受控底图 catalog 和瓦片、站点访问策略联动。
- 后台用户、角色、注册/安全设置、分享治理和审计页面；后台统一迁移为 Cookie 会话 + CSRF。
- KML/分享/收藏的归属隔离、配额、事务回滚、公开响应脱敏、XXE、XSS、IDOR 和受控图源边界测试。

接口契约见 [用户体系与多 KML 分享 API](../api-user-system.md)，初始化、备份和恢复见 [用户体系部署与运维](../user-system-deployment.md)。

### 26.2 当前实施边界

- 分享密码、登录和注册限流为单进程内存状态；多实例部署需要共享限流存储。
- 当前 SQLite 和会话架构以单机、单写进程为部署基线。
- KML 导入支持 Point、LineString、Polygon，不支持 KMZ、MultiGeometry 和完整 KML 样式体系。
- `trashRetentionDays` 已进入设置和模型，但回收站超期异步清理任务尚未实现。
- 超级管理员跨用户 KML 归属转移尚未提供管理接口。
- 分享 scoped catalog 当前只支持受控公开栅格图源。
- 当前迁移流程不会自动复制数据库备份；生产升级前必须先完成一致性备份。

上述项目作为后续增强，不改变本期用户登录、RBAC、个人 KML、收藏和多 KML 只读分享的核心验收范围。
