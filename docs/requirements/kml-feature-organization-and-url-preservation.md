# KML 要素组织与受控 URL 参数保留需求

> 状态：第一版已实现  
> 更新时间：2026-08-17  
> 关联文档：[KML 点位 720 云内容与可配置图标](./kml-720yun-and-marker-icons.md)、[用户体系、角色权限、个人空间与多 KML 分享](./user-system-rbac-and-multi-kml-sharing.md)、[KML 导入导出](./kml-import-export.md)

## 1. 背景

现有 KML 管理已经支持新增、编辑和删除要素，但要素一旦保存到某个文件，后续无法直接调整所属文件，也不能保留原要素并复制到另一个文件。管理面板中的点位、线段和区域只能点击定位，缺少文件内排序和跨文件整理能力。

同时，第三方公开内容识别会将部分受控 URL 重建为不带查询参数的规范地址。720 云等内容会把初始场景、视角或展示状态放在查询参数和片段中，丢失这些内容后 iframe 虽然仍能打开作品，但不能还原用户指定的视图。

## 2. 目标

1. 受支持 provider 的合法 URL 在严格校验后保留业务所需查询参数和片段，不因识别、编辑或重新保存而截断。
2. 用户编辑 Point、LineString 或 Polygon 时可以选择其他可写 KML，并决定移动或复制。
3. KML 数据管理面板支持同文件拖拽排序，以及拖放到其他个人 KML。
4. 跨文件拖放必须通过统一 Dialog 明确选择移动或复制，取消时不得修改数据。
5. 2D、3D、本地 KML 和账号 KML 使用一致的数据操作语义，并复用现有整文件 revision 同步机制。

## 3. 范围与边界

### 3.1 本期范围

- 720 云受控地址保留查询参数和 URL 片段。
- provider 可声明是否允许保留参数；未声明的 provider 继续执行原有规范化规则。
- 编辑要素时显示可写目标 KML；目标与原文件不同时询问移动或复制。
- 复制生成新的稳定要素 ID；移动保留原要素 ID。
- 同文件拖拽可以将要素插入目标要素之前，拖到文件空白区域则移到末尾。
- 跨文件拖拽可以放到目标文件卡片、标题或要素列表，确认后追加到目标文件末尾，或插入指定目标要素之前。
- 操作进入现有撤销/重做历史，并通过账号 KML 增量同步同时更新受影响文件。
- 移动端和键盘环境可通过编辑弹窗完成移动或复制，不依赖 HTML5 拖拽。

### 3.2 不在本期范围

- 不提供任意网页 iframe，不扩大 provider 主机、协议、路径或资源 ID 白名单。
- 不跨用户、公共 KML、分享只读 KML 或无写权限 KML 移动和复制要素。
- 不新增独立的服务端“移动要素”接口；账号模式继续按已有 `/api/v1/kml/sync` 原子同步多个整文件操作。
- 不实现批量多选、文件夹层级、跨账号协作、服务端实时协同或拖拽文件本身排序。

## 4. 权限与只读规则

- 个人 KML 操作沿用现有可写判断；账号模式要求 `kml.own.write`，管理员代管场景沿用既有管理权限边界。
- 公共 KML、分享访问、无写权限账号和加载失败文件不显示拖拽能力，也不能作为跨文件目标。
- 公共 KML 编辑模式只允许在当前公共 KML 内修改要素，不允许与个人 KML 相互移动或复制。
- 前端隐藏入口不是安全边界；账号数据最终仍由现有鉴权、owner 校验、revision 校验和后端 KML 模型校验保护。

## 5. URL 参数保留规则

1. 先完成 `https`、精确主机、禁止账号密码和端口、固定路径、资源 ID 的 provider 校验，再处理查询参数和片段。
2. `canonicalUrl` 始终是不带查询参数和片段的稳定资源地址，用于身份识别和去重。
3. `sourceUrl` 保存经过 provider 规范化的用户地址；允许参数的 provider 保留 `search` 和 `hash`。
4. `embedUrl` 由 provider 根据稳定资源 ID 和合法 `sourceUrl` 生成，不得只用资源 ID 重建后丢失参数。
5. 从已有 iframe 重建媒体项时，`src`、provider、资源类型和资源 ID 必须一致，防止通过修改 `data-*` 属性替换到另一个资源。
6. 抖音等使用固定官方播放器的 provider 保持既有去追踪参数和固定播放器策略，不因本需求统一放宽。

## 6. 要素操作语义

### 6.1 编辑保存

- 目标文件与原文件相同：更新当前要素，不生成新 ID。
- 目标文件不同且选择“移动”：原文件删除要素，目标文件保存编辑后的要素，ID 保持不变。
- 目标文件不同且选择“复制”：原文件及原内容保持不变，目标文件保存编辑后的副本，并生成新 ID。
- 取消移动/复制选择：原文件和目标文件均不修改。

### 6.2 拖拽排序

- 同文件放到另一个要素：移动到该要素之前。
- 同文件放到文件卡片或列表空白区域：移动到末尾。
- 拖到原位置或无有效变化时不写存储、不创建撤销记录。
- 当面板只显示经过视口或 LOD 过滤的部分要素时，禁用文件内排序，避免局部列表产生不可预期的全量顺序；仍可通过编辑弹窗迁移单个要素。

### 6.3 跨文件拖放

- 放下后显示“移动”“复制”“取消”三个选择。
- 移动保留 ID；复制生成新 ID，并检查目标文件内不重复。
- 目标文件自动展开；隐藏状态不自动改变。
- 一个操作只产生一次撤销快照和一次保存调度，2D/3D 重新渲染源文件与目标文件。

## 7. 数据与同步

- 要素顺序继续由 `features` 数组顺序表达，不新增 `sort` 字段。
- 复制 ID 使用 `feat-` 前缀的本地稳定 ID；服务端继续校验单个 KML 内 ID 唯一。
- 账号模式下，移动会形成源文件和目标文件两个 update；复制只更新目标文件，若编辑副本内容则原文件不变。
- `/api/v1/kml/sync` 保持现有 revision 冲突行为：任一受影响文件版本过期时返回 `KML_REVISION_CONFLICT`，前端沿用恢复草稿和冲突处理流程。
- 本期不调整 API 请求和响应结构，仅补充文档说明现有 `features` 数组顺序和多文件同步语义。

## 8. 交互要求

- 可拖拽要素显示抓取手柄，并提供清晰的 hover、拖动中和可放置目标状态。
- 拖拽状态只作用于 KML 面板，不得触发地图拖动、文件导入 dropzone 或页面横向滚动。
- 跨文件选择使用 `src/ui/dialog.js` 的统一组件，不使用原生 `confirm`。
- 编辑弹窗的目标文件字段只在存在多个合法目标时显示，文案保持简短。
- 键盘和移动端至少可通过“编辑 -> 所属 KML -> 移动/复制”完成完整操作。

## 9. 验收标准

1. `https://www.720yun.com/vr/f4ejtOsf5y0?scene_id=12#view` 经过识别、保存、重新编辑和 iframe 重建后，查询参数与片段保持不变。
2. 非法协议、仿冒主机、额外路径、显式端口和资源 ID 不一致的 iframe 仍被拒绝。
3. Point、LineString、Polygon 均可通过编辑弹窗移动或复制到其他个人 KML。
4. 复制后源要素保留，目标副本 ID 不同；移动后源文件不再包含要素，目标要素 ID 不变。
5. 同文件拖拽顺序保存后刷新仍保持；跨文件拖拽取消时数据不变。
6. 只读、公共和分享 KML 不出现可写拖拽入口，也不能作为目标。
7. 2D 与 3D 行为一致；账号同步、撤销/重做、导出和分享按新的数组顺序工作。
8. 定向测试、`npm run check`、`npm test`、`npm run build` 和 `git diff --check` 通过。
