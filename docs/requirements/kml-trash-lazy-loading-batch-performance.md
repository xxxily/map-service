# KML 回收站、按需加载与批量能力增量需求

状态：实施完成，2026-08-29 增补配额统计、自动清理和全局个人地图聚合

## 1. 背景与目标

上一版本已建立个人 KML 目录、文件排序、分享点位聚合和账号同步防误删基础。本增量需求解决以下体验与容量问题：

- 用户能够在页面中找到回收站、恢复文件；永久删除属于高风险操作，必须再次验证当前登录密码。
- 移动端目录标题中的名称、数量和操作图标保持同一行的稳定对齐。
- 隐藏的 KML 在分享和地图中保持隐藏状态，并且默认不请求其完整要素；用户主动显示、展开或参与批量选择时才按需加载。
- 大量点位/线段场景要有可重复的性能基准和可调参数；不得通过静默截断数据或改变连续缩放行为来“优化”。
- 分享点位聚合图标更紧凑，并允许管理员设置默认聚合阈值；分享创建者仍可覆盖合法范围内的分享级参数。
- 目录可按管理员开关提供批量下载；默认关闭。开启后先进入选择模式，用户选中后才显示批量下载/删除操作。
- KML 要素批量操作归属到单个 KML 文件的更多菜单，避免全局跨文件误操作。

## 2. 领域规则

### 2.1 回收站

1. “我的 KML”提供明确的“回收站”入口，入口切换到 `status=trashed`，显示名称、要素数、删除时间、原目录和恢复/永久删除操作。
2. 恢复只对当前账号拥有且仍为 `trashed` 的文件生效，幂等和并发规则沿用账号 KML 同步契约。
3. 永久删除必须提交当前登录密码；服务端在执行删除前完成独立密码校验和限流，密码错误不得改变 KML 或审计状态。
4. 默认 KML 不允许移入回收站或永久删除；跨账号 ID 按资源不存在处理。
5. 回收站列表不加载完整 `features_json`，只有用户展开详情、恢复前预览或导出时才请求详情。
6. 活动配额只统计 `active` 文件；回收站通过 `trashCount`、`trashFeatureCount`、`trashByteSize` 独立报告物理占用，不重复占用文件数和总要素配额。恢复时重新校验活动配额。
7. `trashRetentionDays` 由每日异步任务执行。任务按删除上限继续扫描后续记录，不能被未到期或仍有分享引用的旧记录长期阻塞；被分享引用的源记录保留并写审计。

### 2.2 显隐与按需加载

1. 文件 `enabled=false` 与分享项 `visibleByDefault=false` 必须在刷新、重新打开分享和切换 2D/3D 后保持。
2. 列表/manifest 只返回渲染所需摘要；隐藏项不触发详情请求、解析、媒体集合展开或地图图层创建。
3. 以下行为必须触发一次幂等详情加载：用户点击显示、展开隐藏文件、将文件加入分享/批量选择、导出或编辑。加载失败保留隐藏状态并给出可重试错误，不清空其他文件。
4. 同一文件并发触发多个加载请求时合并为一个 Promise；成功后缓存详情，删除/恢复/版本变化时失效缓存。
5. 目录显隐只批量修改目录内 active 文件的 `enabled`；单文件后续显隐修改不被目录按钮覆盖之外的状态误判为删除。

### 2.3 批量下载与文件级批量操作

1. 管理员设置 `kml.batchDownloadEnabled` 默认 `false`，公开分享下载权限仍由分享自身 `allowDownload` 决定。
2. 设置开启时，目录标题显示下载图标；点击后进入该目录的选择模式，默认不渲染复选框。
3. 选择模式支持选择单个/全部 active 文件；未选择任何文件时不显示批量删除/下载按钮。回收站文件不可下载到当前地图目录。
4. 批量下载接口必须按当前用户权限和文件状态重新校验，采用异步/流式打包或逐文件下载策略，不能因单文件失败而静默丢失其他文件；响应应报告成功与失败明细。
5. KML 要素批量移动、复制、删除只作用于一个 KML 文件，在该文件的更多菜单中进入；全局 KML 面板不再提供跨文件要素批量入口。单文件内的选择状态、撤销/重做和拖动排序保持现有行为。

### 2.4 聚合与性能

1. 聚合图标默认直径和数字字号应小于上一版，保持可点击、可读和稳定尺寸，不改变聚合成员计数。
2. 管理员配置项：

   - `kml.pointClustering`：个人地图 2D/3D 全局 Point 聚合配置，默认开启，`minClusterPoints=10`，并包含 `minZoom`、`maxClusterZoom`、`gridSize`、`maxMembersPerCluster`；
   - `share.kmlClusterForceEnabled`：是否对未显式开启聚合的分享强制启用，默认 `false`；
   - `share.kmlClusterMaxZoom`：管理员强制聚合的最大缩放级别，默认 `12`，范围 `0～24`；
   - `share.kmlClusterMinPoints`：管理员强制聚合的最少点位数，默认 `250`，只校验为不小于 `2` 的安全整数，不设置固定业务最大值；
   - `kml.batchDownloadEnabled`：目录批量下载总开关，默认 `false`。

   服务端必须对整数、范围和布尔值归一化。分享自身通过 `viewConfig.kmlPointClustering` 配置 `enabled`、`minZoom`、`maxClusterZoom`、`gridSize`、`minClusterPoints`、`maxMembersPerCluster`。管理员强制开关开启时，无论分享是否自行开启聚合，都必须标记 `forcedByPolicy=true` 并按更积极聚合合成：缩放范围取并集、网格大小取较大值、最少聚合点数取较小值；分享自身的成员明细上限保持有效，更积极的配置继续生效，较弱配置不得绕过管理员阈值。
3. 个人地图全局聚合和分享级聚合都只作用于 Point，按视口和像素网格递归计算；LineString/Polygon、点位 popup、媒体和连续缩放动画不变。进入分享页后分享配置优先，全局配置不得覆盖分享显式关闭。
4. 性能基准至少覆盖：10/100/1,000/10,000/50,000 点，1/10/50/100 个 KML 文件，以及混合 LineString/Polygon；记录列表加载、详情解析、首次渲染、缩放帧耗时、内存峰值和网络请求数。
5. 优化只能采用分页、视口虚拟化、详情懒加载、请求合并、缓存和渲染批处理；不得固定数量省略文件、要素、名称或成员计数。

## 3. 接口增量

现有 `/api/v1/kml/files?status=trashed`、`POST /kml/files/:id/restore` 和 `DELETE /kml/files/:id/permanent` 保持兼容。

- 永久删除请求体必须为 `{ "password": "..." }`；缺少密码返回 `400 REAUTH_REQUIRED`，密码错误返回 `401 INVALID_CREDENTIALS`，限流返回 `429`，均不改变数据。
- `/api/v1/auth/config` 返回脱敏的 `kml.batchDownloadEnabled`；管理员设置接口使用 `share.kmlClusterForceEnabled`、`share.kmlClusterMaxZoom`、`share.kmlClusterMinPoints`，不返回内部密钥或认证信息。
- `/api/v1/auth/config` 同时返回脱敏的 `kml.pointClustering` 六个渲染字段；管理员通过 `/api/v1/admin/user-system/settings` 统一配置。
- `GET /api/v1/kml/files` 的 `usage` 分别返回 active、trash 和 total 统计。回收站不计入活动配额，但清理前仍占物理存储。
- `/api/v1/kml/sync` 失败可返回安全的 `error.details`，包含文件名、操作、错误码、原因和建议；前端悬停显示摘要，点击统一 Dialog 查看完整详情。
- 当前批量下载由前端按目录选择后逐文件调用导出接口完成，未新增目录打包接口；服务端导出仍逐文件执行权限、状态和下载许可校验。

## 4. 验收标准

1. 未调用数据库或接口工具时，普通用户可通过“我的 KML -> 回收站”看到并恢复已移入回收站的文件。
2. 永久删除无密码、错误密码、并发重复请求均不会误删，正确密码成功后有一次 `kml.delete-permanent` 审计。
3. 移动端目录标题在常见 320/375/390px 宽度下名称、数量和图标不换行错位；长目录名可截断但不覆盖按钮。
4. 隐藏分享项首次打开不请求详情；显示/展开/批量选择时只请求对应文件一次，失败可重试。
5. 个人地图全局聚合默认开启且最少 10 点；分享显式设置优先。聚合关闭时与旧行为一致；大数据基准记录瓶颈而非删除能力。
6. 批量下载默认不可见；开启后必须先选择，取消选择后批量按钮消失；文件级要素批量操作不影响其他 KML。
7. 通过 `npm run check`、相关 `node --test`、`npm run build`，并在 161 完成备份、部署和冒烟验证后再考虑正式发布。

## 5. 非目标

- 不自动恢复无法确认归属的历史回收站文件。
- 不在本轮引入新的第三方聚合或压缩依赖。
- 不改变 2D 地图连续缩放、3D 地图交互或线段/面渲染语义；配额仅修正 active/trash 统计边界，不降低管理员已配置的活动配额。
