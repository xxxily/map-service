# KML 分享发布控制与地图交互性能需求

> 状态：开发中（分享生命周期、快照同步和删除增强已于 v1.5.37 实施）
> 适用范围：2D/3D 地图、个人 KML、用户分享、媒体预览  
> 关联文档：[用户体系、角色权限、个人空间与多 KML 分享需求](./user-system-rbac-and-multi-kml-sharing.md)、[KML 分享空间访问控制与半公开地图需求](./kml-share-spatial-access-and-semi-public-map.md)

## 1. 背景

当前个人 KML 的编辑结果会立即成为外部分享内容，缺少发布审核边界；地图端在 KML 要素增加后还存在定位反馈慢、保存标注后视图被重置、桌面连续缩放输入被动画吞掉，以及点位标签和高顶点线段放大缩放开销的问题。媒体预览仅显示序号和媒体标题，也不利于快速判断当前内容所属点位。

本需求将个人 KML 视为持续编辑的数据源，将分享链接视为显式发布的只读快照，同时优化 2D/3D 定位、编辑、媒体浏览和高频缩放体验。

## 2. 目标

- KML 修改先保存到个人空间，不自动改变已经对外发布的分享内容。
- 分享所有者通过“同步内容”显式发布当前 KML；同步失败时旧分享继续可用。
- 分享页面首个 HTML 响应应使用分享设置中的标题和说明生成可供社交平台识别的页面标题、Canonical、Open Graph、Twitter Card、基础 `itemprop` 和 JSON-LD 元信息；不把密码、坐标、图层等查询参数写入规范 URL。
- KML 面板点击要素后能及时定位，新增或编辑要素后保持用户当前地图视图。
- 桌面 2D 支持连续快速滚轮缩放，不因上一段动画或 KML 要素渲染丢失输入。
- 媒体预览优先显示点位名称，仍为无名称点位保留稳定序号回退。

## 3. 范围

### 3.1 本期范围

- 个人多 KML 分享的已发布快照、待同步状态和手动同步接口。
- 创建分享时生成首次快照；编辑分享包配置时只发布新加入或重新配置后的当前内容。
- 2D/3D KML 面板定位时长优化。
- 2D/3D 新增点位保存后保持当前相机；编辑现有要素不得触发全量范围适配。
- 2D 桌面滚轮连续缩放和 KML 要素量相关渲染优化。
- 媒体预览头部与缩略轨道显示点位名称。

### 3.2 非本期范围

- 分享快照历史版本浏览、回滚或定时发布。
- 为每个分享单独上传或编辑社交卡片图片；当前统一使用站点受控的地图应用图标作为预览图。
- 多人审批、草稿分支和逐要素发布。
- 改变分享链接首次打开时对默认可见 KML 执行联合范围适配的行为。
- 改变 720 云、抖音等 provider 的 URL 识别规则。
- 服务端矢量瓦片、聚类和动态 Feature Layer；超大数据仍按专项需求另行建设。

## 4. 分享内容状态模型

### 4.1 数据源与已发布快照

每个分享项同时维护：

- `sourceRevision`：个人 KML 当前 revision，只用于所有者判断是否有新内容。
- `publishedRevision`：该分享项最近一次成功发布时的 KML revision。
- `publishedSnapshot`：公开读取所需的脱敏 KML 内容快照。
- `publishedAt`：最近一次成功发布时间。

公开 manifest、单文件读取和导出必须只读取 `publishedSnapshot`，不得在请求时 JOIN 当前 `kml_documents.features_json` 作为公开内容。

### 4.2 同步状态

- `synced`：分享内所有有效项目的 `sourceRevision` 与 `publishedRevision` 一致。
- `pending`：至少一个项目的当前 KML revision 高于已发布 revision，或分享配置加入了尚未发布的项目。
- `unavailable`：本次同步无法为项目形成新快照的计算结果。该结果只用于返回错误和管理诊断，不得改变 `kml_shares.status`；旧已发布快照仍按原分享生命周期处理。

所有者列表和详情返回 `syncStatus`、`pendingSyncItemCount`，每个分享项返回 `sourceRevision`、`publishedRevision`、`syncStatus` 和 `publishedAt`。公开接口不得返回源 revision、同步状态或内部 KML ID。

### 4.3 创建和编辑分享

- 创建分享必须在同一事务中生成首次快照、空间范围和内容版本；任一步失败均不创建半成品分享。
- 编辑标题、描述、密码、状态、下载权限和视图配置不要求重新发布 KML 内容。
- 修改分享项目集合、顺序、显示名或默认显隐时，服务端保存配置并为新增项目生成当前快照；已有项目若源内容已变化，仍保持原已发布快照并继续显示待同步。
- 轮换链接、暂停、恢复和撤销不隐式同步 KML 内容。

### 4.4 手动同步

新增接口：

```http
POST /api/v1/kml/shares/:id/sync
Content-Type: application/json
X-CSRF-Token: <csrf>

{ "revision": 4 }
```

鉴权：登录会话、CSRF、`share.own.manage`，且分享属于当前用户。

同步必须在单个数据库事务内完成：

1. 校验分享 revision 和可同步状态。
2. 读取分享内全部有效源 KML 并生成脱敏快照。
3. 基于新快照重新计算空间范围和不限期授权资格。
4. 若空间范围、配额或内容校验失败，回滚全部修改并保留旧公开快照。
5. 成功后更新各项快照、`publishedRevision/publishedAt`、分享内容版本、空间范围和审计记录。

成功响应返回更新后的分享详情。并发 revision 不一致返回 `409 SHARE_REVISION_CONFLICT`；空间策略失败沿用现有 `SHARE_SPATIAL_*` 错误，不得暂停或破坏旧公开内容。

审计动作使用 `share.content.sync`，只记录分享 ID、项目数量、内容版本和结果，不记录完整 KML、密码或公开访问凭据。

### 4.5 分享生命周期、恢复与删除

- 源 KML 的编辑、几何范围重算失败、空间策略暂不合规、公开读取发现项目为空或读取异常，均不得自动把分享从 `active` 改为 `paused`，也不得删除分享配置、分享项或已发布快照。
- 能够停止公开分享的状态变更只有三类：所有者显式暂停、管理员显式封禁、所有者显式撤销。到期仍按 `expired` 的读取规则处理，不把到期误记为暂停。
- `resume` 只读取数据库中已经保存的标题、密码策略、视图、分享项、已发布快照和空间配置；不重新要求选择 KML 或填写参数。若没有可恢复的已发布项目，返回 `409 SHARE_EMPTY`，但保留原状态和配置，不能在读取或恢复失败时偷偷写入 `paused`。
- 更新分享项目集合时至少保留一个有效项目；空集合返回 `409 SHARE_EMPTY`，用户不再需要该链接时应使用删除接口。
- 删除分享是独立于撤销的永久清理操作。用户只能删除自己的分享，管理员可删除治理列表中的任意分享；删除会移除分享行及数据库级联的分享项、访问会话、访问事件和相关运行指标，并写入审计记录。删除绝不删除或修改原始 `kml_documents`。
- 删除后旧 `publicId` 立即返回 `404 RESOURCE_NOT_FOUND`。撤销保留历史记录且不可恢复，删除则清理分享及其访问数据，前端必须明确区分两种操作。

## 5. 前端交互

### 5.1 用户中心

- “我的分享”卡片显示“内容已同步”或“有 N 个 KML 待同步”。
- 有待同步项目且分享未撤销、未封禁时显示“同步内容”按钮；无待同步项目时按钮禁用或不显示。
- 点击后使用统一 Dialog 确认，明确本次操作会更新外部链接内容和重新计算可查看范围。
- 同步成功后刷新分享列表；失败时保留原状态并显示服务端可操作错误。

### 5.2 地图编辑反馈

- 登录用户完成账号 KML 保存后，如果该文件被分享且存在未发布修改，顶部同步状态显示“分享待同步”。
- 该状态可点击并跳转到 `/account/#shares`；不使用阻塞弹窗或覆盖地图的反馈条。
- KML 列表可显示分享引用数和待同步引用数，帮助用户判断哪些文件需要发布。

### 5.3 要素定位与编辑视图

- 从 KML 数据管理面板点击 Point、LineString 或 Polygon 时，应立即停止旧相机动画并启动新定位。
- 点位定位和线面范围适配的主要动画不超过 300ms；弹窗在相机稳定后及时打开，不使用固定约 850ms 的等待。
- 新的定位请求覆盖旧请求，旧定时器不得延迟打开错误要素弹窗。
- 新增或编辑要素保存后只更新对应 KML 图层和面板，不执行 `fitBounds`、`flyToBounds` 或全量 KML 范围适配。
- 空间受限分享的 2D 地图旋转后，拖动和自动校正必须使用当前 bearing 下视口四角包络重新计算允许中心区域；归北、缩放和窗口尺寸变化后不得继续使用旋转前的宽高边界。
- 空间受限分享连续旋转、缩放或调整窗口尺寸时，必须废弃旧拖拽快照，下一次拖拽重新读取当前 bearing、zoom、视口尺寸和投影范围；边缘拖动保留阻尼位移，松手后交由 Leaflet 原生边界动画回弹，不得通过 `moveend` 硬纠偏造成“完全拖不动”的反馈。
- 分享链接首次打开时仍按默认可见 KML 的联合范围适配。

### 5.4 媒体预览名称

- 媒体项具有非空 `featureName` 时，预览头部主标题优先显示点位名称，媒体类型和当前序号作为辅助信息。
- 缩略轨道优先显示点位名称；无名称时显示两位序号。
- 名称按钮使用受控宽度和单行省略，不得挤压导航或导致轨道换行。
- 点位名称编辑后重新打开预览必须显示新名称，轨道 DOM 缓存签名应包含名称。

### 5.5 分享页面元信息

- 服务端 `GET /share/:publicId` 在返回 HTML 前读取 active 分享的标题和说明；分享标题作为 `<title>`、`og:title`、`twitter:title` 和 JSON-LD `name`。
- 分享说明经纯文本清洗和长度限制后作为 `description`、`og:description`、`twitter:description` 和 JSON-LD `description`；不得把用户输入当作 HTML、脚本或 JSON 结构执行。
- 页面输出 `canonical`、`image_src`、`og:site_name`、`og:type`、`og:url`、`og:image`、`og:image:secure_url`、尺寸与 alt、`twitter:card`、`twitter:url`、`twitter:image`、`itemprop` 和 `WebPage`/`Map`/`WebSite` JSON-LD。预览图使用受控站点图标，暂不允许分享者提交任意图片 URL。
- Canonical、`og:url` 和 `twitter:url` 仅使用 `/share/:publicId` 稳定路径，移除 `password`、`coords`、`layer` 等查询参数；页面继续发送 `X-Robots-Tag: noindex, nofollow` 和 `Referrer-Policy: no-referrer`。
- 密码保护分享在密码验证前也允许公开读取最小化标题/说明，用于生成社交卡片；暂停、撤销、过期、封禁或没有已发布内容的分享不得泄露专属元信息。
- 浏览器完成公开 manifest 加载后再次同步更新 `document.title` 和所有元信息，保证客户端导航、2D/3D 切换与首屏 HTML 一致。

## 6. 2D 连续缩放与 KML 性能

### 6.1 输入与动画

- 仅桌面精细指针环境增强滚轮缩放；移动端双指缩放、`Shift` 旋转和媒体预览自身滚轮行为不变。
- 连续滚轮输入必须累积到最新缩放目标，不得因 `map._animatingZoom` 仍为 true 而静默丢弃后续目标。
- 非 `Shift` 滚轮输入在一帧内合并，降低事件风暴；缩放灵敏度和分级允许更快到达目标层级。
- 组件卸载时必须移除原生监听和未完成任务。

### 6.2 KML 渲染热点

- 缩放开始后临时暂停不必要的常驻点位名称布局，缩放稳定后恢复，避免旋转插件逐项执行 tooltip 投影和 DOM 定位。
- 线段和区域优先使用共享 Canvas renderer 或等价的单容器渲染路径，避免每个高顶点 SVG 路径独立参与缩放布局。
- 普通 KML 不因 `zoomend` 全量重建图层；实时轨迹仍按现有视口和 LOD 规则增量更新。
- 缩放期间不得重新解析媒体、重建 popup HTML、刷新 KML 管理面板或计算全部 KML 联合范围。
- 优化不能隐藏或永久丢失点位名称、popup、拖拽能力和媒体点位图标。

### 6.3 性能验收基线

在桌面 Chrome、1920×1080、4 个启用 KML、总计约 100 个 Point（其中至少 50 个有名称）、线段总顶点不低于 10,000 的测试数据下：

- 连续发送 10 次同方向滚轮输入，无需等待上一段约 250ms 动画结束，最终缩放级别持续向目标方向变化。
- 首次滚轮到地图 zoom 变化的主线程响应目标不超过 100ms；连续输入期间不出现超过 500ms 的完全无响应区间。
- 缩放结束后点位名称、线段、区域和点位交互完整恢复。
- 关闭 3 个 KML 与启用全部 KML 的操作语义一致；性能优化不得依赖用户手工隐藏文件。

## 7. 数据迁移

- 用户数据库 schema 升级到 v6。
- `kml_share_items` 新增 `published_revision`、`published_snapshot_json`、`published_at`。
- `kml_shares` 新增 `content_revision`、`content_published_at`。
- v5 升级时以迁移时当前 KML 内容回填现有分享快照；迁移需幂等，部分列已存在时可继续完成。
- 快照 JSON 使用现有 KML normalize/validate/sanitize 流程，公开读取仍执行输出脱敏。

## 8. 验收标准

- 修改已分享 KML 后，源 KML revision 增加，公开分享文件内容保持不变，所有者看到待同步状态。
- 手动同步成功后，公开分享内容更新，待同步状态清零，空间范围按新快照更新。
- 手动同步因空间范围不合规失败时，旧公开文件、旧范围和旧访问链接仍可读取。
- 修改源 KML、几何重算失败、空项目公开读取和异常重试均不会自动暂停 active 分享；分享配置、已发布快照和恢复所需参数保持不变。
- 显式暂停后恢复不要求重新选择 KML 或重新填写分享参数；恢复成功后继续使用暂停前的已发布快照。
- 用户和管理员均可删除分享；删除后分享项、访问会话、访问事件和运行指标清理，源 KML 仍可读取和继续编辑。
- 分享同步接口覆盖未登录、CSRF 失败、无权限、IDOR、revision 冲突和成功路径。
- 2D/3D 面板要素定位不再固定等待约 850ms；连续点击只打开最后一个目标。
- 新增或编辑点位后地图中心和缩放级别保持不变。
- 媒体预览有点位名称时在头部和缩略轨道可见，无名称时回退序号。
- 桌面 2D 在性能基线数据下支持连续滚轮缩放，移动端缩放和桌面旋转无回归。
- `npm run check`、`npm test`、`npm run build` 通过，并完成桌面与移动端浏览器验证。
