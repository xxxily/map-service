# 路线规划保存、临时添加与起终点交换

## 状态

实现于 `v1.5.72`，计划先发布到 161 内网测试环境，待内测验收后再决定是否发布到 66。本文记录当前交互和数据边界。

## 目标

路线规划完成后，用户可以在不遮挡地图的前提下：

- 保存当前选中的驾车方案到指定 KML 文件；
- 将一个或多个方案临时叠加到当前地图，并在地图上查看、保存或删除临时路线；
- 交换起点和终点并自动重新规划。

## 功能范围

### 路线工具栏

“开始规划”“交换起终点”“保存路线”“添加到地图”和“开始导航”均使用紧凑图标按钮，按钮同时提供 `title` 和 `aria-label`。规划成功后，方案列表可横向/纵向浏览；每个方案卡片独立提供保存和临时添加图标。

### 保存路线

点击保存后使用统一的编辑弹框：

1. 选择一个当前可写且已启用的 KML 文件；
2. 路线名称默认按“起点名称-终点名称”生成，允许用户修改；
3. 描述默认包含起点、终点、距离、预计用时和方案序号，允许用户修改。

起终点名称通过高德 Geocoder 反向解析，优先使用最近 POI/区域名称，再回退到建筑物、格式化地址或坐标占位名称。路线坐标按目标 KML 的既有 WGS84/GCJ-02 纠偏策略转换后保存为 `LineString`，并复用既有 KML 权限、同步、撤销和渲染链路。

### 临时添加路线

点击方案卡片或结果工具栏的“添加到地图”后，路线以橙色虚线显示并保存在当前页面内存中。允许重复添加同一方案，也允许同时添加不同规划结果中的多个方案，不做数量限制。临时路线不会写入 KML、`localStorage` 或账号同步数据；页面刷新、地图卸载或退出当前页面后自然消失。

点击临时路线会打开线段简介弹框，显示方案、名称、距离、预计用时和起终点，并提供：

- 保存：沿用上述 KML 文件选择和命名规则；
- 删除：使用统一确认弹框后移除当前临时路线。

### 起终点交换

起点和终点均有效时启用交换图标。点击后交换输入框、地图标记和内部 POI，并重新发起路线规划；旧规划请求在结果返回前失效，避免旧结果覆盖新结果。

## 数据与接口契约

本功能不新增后端 API。路线保存调用前端既有 KML 本地/账号同步链路，沿用现有权限校验、目标文件选择、坐标纠偏和错误提示。临时路线是页面会话态，不进入任何持久化接口。

## 验收标准

- 路线规划工具栏仅占用图标按钮空间，桌面和 320/375/390px 移动宽度均不溢出；
- 规划结果成功后，当前方案的保存、临时添加和导航按钮可用，规划中或无有效路线时禁用；
- 可从任意方案卡片保存或临时添加，多个临时路线同时可见且互不覆盖；
- 保存弹框默认选择最近使用的可写 KML，并按高德反向解析名称生成默认路线名；
- 临时路线点击后可查看简介、保存到 KML 或确认删除；
- 刷新/退出后临时路线不恢复，保存后的路线在 KML 面板中作为普通 `LineString` 可编辑、删除和同步；
- 交换起终点后输入框、标记和规划结果均对应新方向；
- 本地 `npm run check`、`npm test`、`npm run build` 和 `git diff --check` 全部通过；
- 161 发布前完成代码、环境、SQLite、admin 状态和 Compose 模板备份，并通过双健康检查与版本核对。
