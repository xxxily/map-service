# KML 点位 720 云内容与可配置图标需求

> 状态：第二版已实现，待用户验收  
> 更新时间：2026-08-11  
> 关联文档：[KML 点位第三方分享链接识别与嵌入预览](./kml-point-share-link-embed.md)、[KML 点位富媒体内容展示](./kml-feature-rich-content.md)、[KML 导入导出](./kml-import-export.md)、[KML 点位分享链接媒体使用说明](../user-guides/kml-share-link-media.md)

## 1. 背景

当前点位描述已经可以把抖音公开视频分享链接转换为受控 iframe，并能按图片、视频、音频、页面和链接显示媒体类型图标，但仍存在五个不足：

1. 用户粘贴 `https://www.720yun.com/vr/<作品 ID>` 等 720 云公开全景地址时，只能得到普通链接，无法在地图内沉浸式查看。
2. 抖音、720 云等平台内容都被归为通用“页面”图标，用户无法在地图上快速判断点位承载的是哪一种内容。
3. 用户手动新增或编辑点位时不能选择图标，普通地点只能使用主题默认点位，难以表达营地、停车、餐饮、观景等语义。
4. 图标数量增加后，完整图标网格会纵向占满点位编辑弹窗，常用图标和低频图标缺少分层，也无法快速复用最近选择。
5. 点位名称仍被通用编辑弹窗强制设为必填，用户只想用图标、坐标或媒体表达点位时无法保存；无名点位还会在部分列表和详情中显示无意义占位标题。

720 云官方公开说明允许将公开作品地址放入 iframe，并建议 iframe 使用 `width="100%"`、`height="100%"` 和 `allowfullscreen`。本需求不抓取作品数据、不推导私有嵌入码，只消费用户明确提供的公开页面。

## 2. 目标

1. 登录且具备 KML 写权限的用户在新增或编辑点位时，可以直接粘贴 720 云公开作品地址并保存为可预览的 iframe 内容。
2. 2D、3D、KML 数据管理列表和分享只读页使用一致的点位图标解析规则。
3. 抖音和 720 云拥有各自可辨识的专属自动图标，图片、视频、音频、普通页面和链接继续保留类型图标。
4. 用户可以在新增和编辑点位时选择通用语义图标，并可以随时切回“自动识别内容”。
5. 用户选择的图标能够经过账号同步、公开分享、本地存储和标准 KML 导入导出完整保留。
6. 新 provider 和自定义图标不得放宽现有 iframe、XSS、SSRF、鉴权和公开数据安全边界。
7. 图标选择器保持单行紧凑布局，优先提供当前、最近和常用图标，并通过“查看更多”访问完整内置图标库。
8. 点位名称允许留空；留空后地图、详情、媒体预览和列表均不显示伪造标题，同时保留必要的无障碍名称。

## 3. 范围

### 3.1 本期范围

- 识别 720 云公开全景地址：
  - `https://www.720yun.com/vr/<作品 ID>`
  - `https://720yun.com/vr/<作品 ID>`
  - `https://www.720yun.com/t/<公开嵌入 ID>`
  - `https://720yun.com/t/<公开嵌入 ID>`
- 将合法地址规范化到 `https://www.720yun.com/<vr|t>/<ID>`，移除追踪查询参数和片段。
- 生成带 `data-kml-share-provider="720yun"` 的受控 iframe 标记，并复用统一媒体预览器。
- 新增抖音和 720 云 provider 专属点位图标。
- 新增通用点位图标选择器，提供：经典标记、星标、旗帜、观景、相机、营地、餐饮、住宿、停车、提醒、爱心、住所、饮水、卫生间、医疗、商店、充电、公交、火车、骑行、徒步、山峰和瀑布。
- 图标快捷栏采用单行横向滚动，“查看更多”固定在快捷栏右侧；完整图标库在统一 Web 弹窗体系内打开。
- 记录当前浏览器最近成功保存的 5 个显式图标，自动模式、未知枚举和未保存选择不进入记录。
- 新增和编辑 Point 时名称可留空；空名称不生成默认标题，不影响坐标、描述、媒体和图标保存。
- 新增 `markerIcon` 点位字段及标准 KML `ExtendedData` 兼容规则。
- 更新自动化测试、需求索引、API 说明、用户手册和变更记录。

### 3.2 不在本期范围

- 不下载、转存、解析或二次托管 720 云全景图片、视频、音频及模型资源。
- 不登录 720 云、不读取 Cookie、账号、验证码或非公开作品。
- 不把任意网页 URL 转成 iframe，不增加通用 iframe 白名单或任意 URL 代理。
- 不绕过目标站点的 `X-Frame-Options`、CSP、会员、密码、地区、下架或版权限制。
- 不允许用户上传 SVG、图片 URL、HTML 或脚本作为自定义图标；本期只允许选择系统内置安全图标。
- 不实现用户级图标素材库、图标颜色编辑和第三方图标市场。

## 4. 用户与权限

- 新增、编辑点位及保存 `markerIcon` 继续沿用现有 KML 写权限：`kml.own.write`、`kml.any.manage` 或公共 KML 管理权限。
- 720 云地址不需要服务端展开，可以在浏览器本地转换；但用户必须先有权保存目标 KML 点位。
- 未登录访客和公开分享访问者只能查看已经保存的 720 云内容和点位图标，不显示编辑或图标选择入口。
- 分享页只读，不能通过修改 URL 或前端状态覆盖所有者保存的图标。

## 5. 720 云 provider 契约

### 5.1 地址校验

provider ID 固定为 `720yun`，只接受：

- 协议：`https:`；
- 主机：精确的 `720yun.com` 或 `www.720yun.com`；
- 端口：不得显式指定；
- 路径：精确匹配 `/vr/<ID>` 或 `/t/<ID>`，允许末尾 `/`；
- ID：6～64 位 ASCII 字母或数字；
- 不允许用户名、密码、额外路径段、非预期协议或仿冒子域名。

查询参数和 URL 片段不进入持久化 iframe，统一规范化为：

```text
https://www.720yun.com/vr/f4ejtOsf5y0
```

`/vr/` 和 `/t/` 的标识属于不同命名空间，稳定资源 ID 分别保存为 `vr:<ID>` 和 `t:<ID>`，不得假定二者可以互相换算。

### 5.2 生成内容

用户描述：

```text
全景查看：https://www.720yun.com/vr/f4ejtOsf5y0
```

系统持久化：

```html
<iframe
  src="https://www.720yun.com/vr/f4ejtOsf5y0"
  title="720 云全景"
  data-kml-share-provider="720yun"
  data-kml-share-source="https://www.720yun.com/vr/f4ejtOsf5y0"
  data-kml-share-canonical="https://www.720yun.com/vr/f4ejtOsf5y0">
</iframe>
```

编辑点位时继续隐藏机器生成的 iframe，只展示用户原始说明和规范化后的公开地址。重复保存必须幂等，不得重复添加媒体项。

### 5.3 iframe 策略

- iframe 水平方向占满预览舞台，使用统一深色背景，不产生额外白边。
- `sandbox` 只包含作品运行需要的脚本、同源、表单、弹窗、展示和指针锁能力，不包含顶层导航权限。
- `allow` 只开放全屏、自动播放、陀螺仪、加速度计、画中画和 WebXR 等全景查看所需能力。
- 设置 `allowFullscreen=true` 和固定 `referrerPolicy`。
- iframe 只在用户打开媒体预览后创建；关闭或切换媒体后销毁。
- 内容拒绝嵌入、作品失效或网络失败时，保留“打开原始页面”兜底，不尝试绕过平台限制。

## 6. 点位图标规则

### 6.1 自动识别优先级

点位最终图标按以下顺序解析：

1. 用户显式选择的通用 `markerIcon`；
2. 受控 provider 专属图标：`douyin`、`720yun`；
3. 富媒体类型图标：图片、视频、音频、普通 iframe 页面、普通链接；
4. 当前 KML 主题的默认点位样式。

用户选择“自动识别内容”时不保存显式 `markerIcon`，因此新增 provider 后旧点位也能自动获得更准确的图标。用户显式选择通用图标后，系统不得因描述中存在媒体而覆盖用户选择。

### 6.2 provider 专属图标

- 抖音：深色点位底板与具有青红层次的音乐符号，辅助文本为“抖音视频”。
- 720 云：蓝青色点位底板与橙色全景环/`720` 识别元素，辅助文本为“720 云全景”。
- 专属图标只由经过严格校验的 provider iframe 触发，普通文本中出现“抖音”或“720”字样不能触发。
- provider 专属图标不放入通用手动图标列表，避免无对应内容的点位被错误标记为平台内容。

### 6.3 图标选择器

- 新增和编辑点位弹窗增加“点位图标”字段。
- 默认选项为“自动识别内容”；辅助说明使用能力导向的短文案，不枚举会持续扩展的平台或媒体类型。
- 主弹窗只显示单行快捷栏，快捷顺序依次为：自动识别、当前选中、最近使用、默认常用；相同图标去重后最多显示 8 个，快捷栏可横向滚动但不能纵向扩张。
- “查看更多”按钮固定在快捷栏右侧，不随横向内容滚出视口；点击后在统一组件体系内打开完整图标库，按系统默认枚举顺序展示全部图标。
- 完整图标库选择后立即回填并关闭二级弹窗；新选择会进入主弹窗当前快捷位置，用户仍需点击主弹窗“保存”才真正写入点位。
- 快捷栏和完整图标库均支持 Tab、方向键、Enter/Space、Esc、焦点态、选中态和屏幕阅读器名称；关闭二级弹窗后焦点返回“查看更多”。
- 不使用浏览器原生 `alert`、`confirm`、`prompt`，也不允许二级弹窗覆盖或丢失主编辑表单内容。
- 横向滚动只能发生在快捷栏自身，主弹窗、字段容器和页面不得产生横向滚动；滚动到快捷栏边界时不得把横向滚动继续传递给主弹窗。
- 编辑旧点位时，没有 `markerIcon` 的点位选中“自动识别内容”；选择自动后删除旧的显式字段。

### 6.4 最近使用规则

- 本地存储键固定为 `map_kml_marker_recent_icons_v1`，值为最多 5 个图标 key 的 JSON 数组。
- 只在 2D 或 3D 点位新增/编辑完成并调用现有保存流程后记录显式图标；取消弹窗、保存失败或只在完整图标库中浏览不得改变记录。
- 新保存图标移到数组首位并去重；`auto`、空值和未知枚举不记录，读取到损坏 JSON 时按空数组处理。
- 最近使用只用于当前浏览器快捷排序，不同步到账号、不写入 KML、不进入公开分享，也不作为用户行为分析数据上传。

### 6.5 点位名称可选规则

- 2D、3D 的 Point 新增和编辑字段 `name` 为可选，输入只包含空白时规范化为空字符串；描述、坐标和图标不依赖名称。
- 空名称不得自动保存为“未命名点位”“未命名要素 N”或文件名，也不得阻止新增或编辑保存。
- 常规主题下仅有真实名称时才渲染地图文字标签；简约主题继续不显示任何点位名称。
- 点位 popup、富媒体详情标题、媒体预览标题和 KML 管理列表都不显示“未命名点位”占位文案；列表中的无名 Point 只显示图标。
- 无名 Point 的聚焦入口仍提供 `aria-label="定位到未命名点位"` 等辅助技术名称；线段和区域的既有“未命名线段/未命名区域”回退不在本需求中改变。
- KML 文件名、分享标题、收藏名称以及非 Point 要素的命名校验不受本规则影响。

## 7. 数据模型与 KML 兼容

### 7.1 JSON 模型

Point Feature 新增可选字段：

```json
{
  "id": "feat-1",
  "type": "Point",
  "name": "观景台",
  "description": "……",
  "markerIcon": "viewpoint",
  "coordinates": [113.2644, 23.1291]
}
```

允许值：

```text
pin, star, flag, viewpoint, camera, campsite,
food, lodging, parking, warning, heart, home, water,
restroom, hospital, shop, charging, bus, train,
bicycle, hiking, summit, waterfall
```

约束：

- 仅 Point 可以保存 `markerIcon`；线和面收到该字段时应忽略或拒绝。
- 前端本地数据读取时丢弃未知值，回退到自动模式。
- 后端 JSON 写接口收到未知值时返回 `400 VALIDATION_FAILED`，不得持久化任意字符串。
- `auto` 仅是界面选项，不写入 JSON 和 KML。

### 7.2 标准 KML

导出时使用标准 `ExtendedData` 保存项目扩展，不占用现有 `styleUrl`：

```xml
<ExtendedData>
  <Data name="map-service:marker-icon">
    <value>viewpoint</value>
  </Data>
</ExtendedData>
```

导入时：

- 只读取名称精确为 `map-service:marker-icon` 的 `Data`；
- 只接受内置枚举；未知值忽略并回退自动模式；
- 继续保留原有 `styleUrl` 媒体类型提示，两者互不覆盖；
- 不解析远程图标 URL，不因 `<IconStyle><href>` 发起网络请求。

## 8. 2D、3D 与管理面板一致性

- 2D Leaflet 和 3D Cesium 使用同一图标解析纯函数和同一 SVG 图形定义。
- KML 数据管理面板中的点位列表使用与地图一致的 provider/通用图标，不再统一显示几何点位符号。
- 编辑描述或图标后立即重建对应点位渲染，不能要求刷新页面或重新打开 KML。
- 有真实点位名称时继续显示在图标正上方，不与图标叠加；空名称不渲染标题或文字标签。
- KML 数据管理面板中的无名 Point 只显示图标，不显示占位名称；聚焦交互保留无障碍名称。
- `simple` 主题仍隐藏点位名称；但 provider 专属图标和用户显式图标仍应显示，确保内容属性和用户选择不丢失。

## 9. 安全与隐私

1. 720 云地址执行精确 origin、path、ID 和最终 embed URL 校验，环境 iframe allowlist 不能伪造 provider 身份。
2. provider 生成 URL，不接受调用方提供任意 `embedUrl`。
3. 公开内容 API 只返回规范化 URL、provider ID 和固定 iframe 策略，不返回 Cookie、鉴权头或页面正文。
4. iframe DOM 由统一预览器创建，点位描述 HTML 不直接注入页面。
5. `markerIcon` 是固定枚举，不接受 HTML、SVG、CSS、data URL、远程 URL 或脚本。
6. 720 云不可用不影响点位及 KML 保存；原始公开链接继续作为外链兜底。

## 10. 测试要求

### 10.1 纯函数与服务测试

- 720 云 `/vr/`、`/t/`、带追踪参数和非 `www` 主机规范化成功。
- HTTP、显式端口、账号密码、仿冒域名、额外路径、非法 ID 被拒绝。
- 720 云受控 iframe 能被内容解析器识别，原始重复链接不再生成第二个普通链接。
- 伪造 `data-kml-share-provider`、embed URL 或 canonical 元数据不被信任。
- 抖音和 720 云获得不同 provider 图标；普通 iframe 继续使用通用页面图标。
- 用户显式图标覆盖 provider 图标，自动模式恢复 provider/type 图标。
- `markerIcon` 服务端枚举校验、账号同步、KML 导入导出往返测试。
- 最近图标读取、损坏值恢复、去重、数量上限、自动/未知值过滤和快捷排序测试。
- Point 空名称规范化、编辑保存和各展示层不输出占位标题的测试。

### 10.2 UI 与源码契约测试

- 2D、3D 新增和编辑弹窗都包含图标选择器与 720 云提示。
- 选择器不使用 `alert`、`confirm`、`prompt`。
- 快捷栏保持单行横向滚动，“查看更多”固定可见，二级图标库支持 Esc 和焦点恢复。
- 编辑后 2D/3D 都立即重新渲染点位。
- 公开分享端只读显示相同图标和 iframe 内容。
- 2D、3D 新增和编辑点位名称都显式声明为非必填。

### 10.3 手工验收

1. 新建点位并粘贴 `https://www.720yun.com/vr/f4ejtOsf5y0`，保存后点位显示 720 云专属图标。
2. 点击点位或媒体速览，720 云内容在统一深色预览器中占满宽度，可交互查看；关闭后可以再次打开。
3. 抖音点位、720 云点位、图片点位和普通点位并排时可以一眼区分。
4. 为普通点位分别选择星标、营地、停车等图标，2D、3D 和 KML 列表同步变化。
5. 把含自定义图标的 KML 导出后重新导入，图标选择保持不变。
6. 将 KML 公开分享给未登录访客，访客能看到相同图标和 720 云预览，但没有编辑入口。
7. 输入 `https://evil.example.com/vr/f4ejtOsf5y0`、`http://www.720yun.com/...` 或带额外路径的地址，只作为普通/不安全链接处理，不生成 iframe。
8. 连续保存多个不同图标后重新打开新增点位弹窗，最近使用图标按最近优先出现在快捷栏；选择“自动识别内容”不改变最近记录。
9. 在“查看更多”选择低频图标，返回主弹窗后该图标显示为当前选中；取消主弹窗后点位和最近记录都不改变。
10. 新增或编辑 Point 时把名称留空仍能保存；地图、popup、详情、媒体预览和个人/公共/分享 KML 列表不出现“未命名点位”文字。

## 11. 后续路线

- 在同一 provider 注册机制中评估 Bilibili、视频号、小红书等有稳定官方嵌入能力的平台。
- 根据使用反馈评估用户固定常用图标、图标搜索、分类和 KML 文件级默认图标。
- 单独评估图标颜色、用户上传图标和团队图标库；这些能力需要额外的文件安全、配额、版权和内容审核设计。
