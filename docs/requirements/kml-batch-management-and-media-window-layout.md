# KML 批量管理与媒体窗口自由布局需求

> 状态：第二版已实现，已完成发布前自动化与浏览器 smoke 验证
> 更新时间：2026-08-20
> 关联文档：[KML 要素组织与受控 URL 参数保留](./kml-feature-organization-and-url-preservation.md)、[KML 媒体预览与 3D 地图界面精简](./kml-media-preview-and-3d-ui-polish.md)、[KML 性能优化与资源集合点位](./kml-performance-and-resource-collections.md)

## 1. 背景与目标

KML 数据管理目前可以通过拖拽逐个移动或复制要素，但在整理多个文件、清理导入数据或迁移一批素材时，逐项操作成本过高，也不适合触屏和键盘环境。媒体预览器已经支持居中大窗和小窗，但桌面大屏仍受固定最大宽度限制，小窗也不能自由移动和调整大小。

本需求建立两类可复用能力：

1. 在 2D、3D 管理面板中提供跨文件的批量选择、移动、复制和删除，操作可撤销、可同步、可扩展。
2. 将媒体预览器布局抽象为居中模式、宽屏模式和小窗模式；宽屏偏好、小窗位置和尺寸在本地持久化，并在视口变化时保持可用。

## 2. 用户场景

- 用户从一个导入文件中选择多条点位和线段，一次移动到目标 KML。
- 用户保留原文件内容，同时把选中的资源复制到另一个主题文件。
- 用户确认后批量删除无效点位，取消确认时数据完全不变。
- 大屏用户将媒体浏览器切换为占满可用页面宽度，下一次打开继续使用该模式。
- 用户把媒体小窗拖到地图空白处、调整为适合自己的尺寸，刷新或下次打开后布局仍保持。

## 3. 范围与边界

### 3.1 本期范围

- 2D 和 3D KML 管理面板均支持批量模式。
- 可选要素包括当前面板实际显示且属于可写个人 KML 的 Point、LineString、Polygon；只读、公共、分享和被视口过滤隐藏的要素不可选。
- 批量动作首期包括移动、复制、删除；动作定义采用可扩展注册表，后续可加入批量重命名、分类或计算。
- 移动和复制目标只能是当前账号可写的个人 KML 文件；目标文件通过统一弹窗选择。
- 批量操作一次生成一条撤销记录，并沿用现有账号同步和本地存储机制。
- 媒体预览器增加桌面宽屏模式按钮；仅在当前视口存在固定宽度模式未使用的水平空间时显示。
- 小窗模式支持标题区域拖动、右下角调整大小，位置和尺寸按视口约束持久化。

### 3.2 不在本期范围

- 不支持跨账号、公共 KML 或分享快照写入。
- 不改变现有 KML API 契约、服务端权限模型和冲突恢复协议。
- 不使用浏览器原生 `alert`、`confirm`、`prompt`。
- 不裁剪缩略轨道项目，不改变媒体解析白名单、图片缩放、地图缩放过渡和关闭释放逻辑。
- 不实现浏览器系统级 Fullscreen API；“宽屏模式”指应用页面内占满可用视口。

## 4. 批量 KML 管理

### 4.1 进入与退出选择模式

- “个人图层”分区标题区显示一个全局“批量”图标按钮，用于跨文件选择。
- 点击后进入选择模式，按钮变为“操作”，同时显示已选数量和“取消”按钮。
- 选择模式中，符合条件的要素行显示复选框；点击要素正文仍可定位，不得误触打开编辑或删除。
- 重新渲染、展开/收起文件或切换地图视口时保留仍存在的选择；要素被删除、文件变为只读或不再属于可写范围时自动移除选择。
- 关闭面板、进入分享只读模式、账号失效或点击取消时退出选择模式并清空选择。
- 选择模式提供“全选”和“反选”；两者只作用于当前面板中实际展示且可写的要素，不能把视口过滤隐藏的要素偷偷加入批次。

### 4.2 动作菜单

点击“操作”后使用统一选择弹窗显示：

- 移动
- 复制
- 删除
- 取消

无选择时“操作”按钮禁用。动作执行期间锁定重复提交，完成后显示成功/失败统计并退出选择模式。

### 4.3 移动与复制

- 选择移动或复制后，弹出可写个人 KML 目标文件选择器，不包含来源文件以外的只读文件。
- 移动：从来源文件移除，目标文件追加，保留原要素 ID。
- 复制：来源文件保持不变，目标文件追加深拷贝，为每个副本生成新的稳定 ID，并检查目标文件和本次批次内均不冲突。
- 目标与全部来源相同的移动视为无有效变化并给出短提示；复制到同文件允许。
- 多个来源文件移动到一个目标文件时，按 KML 文件顺序和文件内要素顺序追加，保证结果稳定可预测。
- 任一要素不存在、文件不可写、ID 冲突或目标无效时，整个批次不写入，返回可读错误。

### 4.4 批量删除

- 删除动作必须先显示统一确认弹窗，明确选中数量。
- 用户取消时不产生历史记录、不改变地图和存储。
- 确认后一次性从各来源文件移除要素，并清理对应地图图层和媒体画廊缓存。

### 4.5 权限、同步和撤销

- 前端入口隐藏不是安全边界；批量操作仅作用于 `isWritablePersonalKml`/`isKmlEditable` 判定通过的个人 KML。
- 本地模式写入 `localStorage`；账号模式调用现有 `scheduleKmlAccountSync`，多个受影响文件在同一同步调度中提交。
- 每次批量动作只调用一次 `pushKmlHistory`，撤销恢复全部受影响文件和顺序。
- 操作后 2D、3D 均重新渲染受影响文件，保持当前地图中心、缩放和相机状态不变。

## 5. 媒体预览布局

### 5.1 布局状态

| 状态 | 说明 | 默认 |
| --- | --- | --- |
| 居中模式 | 当前固定最大宽度，页面两侧保留空间 | 是 |
| 宽屏模式 | 预览控件占满可用页面区域，内容随容器增大 | 记忆上次选择 |
| 小窗模式 | 可移动、可调整尺寸的非模态预览 | 用户主动切换 |

- 宽屏按钮仅在桌面非触摸环境、且可用视口宽度大于居中模式最大宽度加安全边距时显示。
- 宽屏与居中模式可相互切换；切换结果写入版本化本地偏好。
- 打开媒体预览时读取偏好；移动端始终使用现有全屏触摸布局，不强制套用桌面宽屏偏好。
- 宽屏模式不改变历史返回栈、媒体项目索引、缩略轨道完整性或资源释放时机。

### 5.2 小窗拖动与缩放

- 小窗标题区域（按钮和链接除外）支持 Pointer Events 拖动。
- 小窗右下角显示可访问的调整大小手柄，支持拖动改变宽高；最小尺寸为 `280 × 180`，最大尺寸受当前视口安全边距约束。
- 拖动和缩放过程中使用 `requestAnimationFrame` 合并更新，避免触发地图重绘和页面横向滚动。
- 小窗自动限制在可视区域内，窗口旋转、浏览器缩放或视口尺寸变化后执行一次约束修正。
- 标题区高度压缩到 36-40px，仅保留必要标题和图标操作；内容区域优先获得空间。
- 小窗位置和尺寸使用版本化本地键保存；保存失败不影响媒体浏览。
- 移动端仍使用全屏布局，不显示桌面小窗拖动和缩放手柄。
- iframe 容器与 iframe 使用同一可用高度，不额外添加上下内边距，避免页面上下出现由宿主布局造成的黑边。
- 底部元信息始终贴靠右侧；即使图片缩放控件隐藏，也不能塌到左侧。
- 小窗标题栏压缩到约 32px，保留必要标题和操作命中区；左上角提供无装饰的透明缩放热点，和右下角热点共同调整窗口几何。

### 5.4 地图辅助控件

- 搜索面板右上角提供与路线规划一致的关闭按钮，关闭后不改变搜索结果标记，用户可立即访问其下方地图工具。
- 2D/3D 地图工具菜单只保留“用户中心”身份入口；管理员仍可从用户中心进入管理后台，不再重复显示独立后台按钮。
- 左上角 Leaflet 控件的 hover/focus 边框必须完整可见，不得被相邻控件或控制容器裁切。

### 5.3 可访问性与反馈

- 所有新增按钮使用图标、`aria-label` 和 `title`；状态通过 `aria-pressed` 或 `aria-expanded` 表达。
- 小窗调整手柄具备 `aria-label="调整预览窗口大小"`，键盘用户至少可以通过宽屏/居中和小窗恢复按钮操作。
- 任何动作都不使用阻塞式浏览器弹窗；错误和确认复用 `src/ui/dialog.js`。

## 6. 数据与本地偏好

### 6.1 批量选择

选择状态只存在当前页面内存，不写入 KML 数据，不参与账号同步。选择键使用序列化的 `[kmlId, featureId]` 稳定组合，避免 ID 中的分隔符产生歧义。

### 6.2 媒体布局偏好

建议本地键：

- `map_media_preview_layout_v1`：`centered` 或 `wide`。
- `map_media_preview_window_v1`：`{ left, top, width, height }`，数值均为 CSS 像素。

读取、解析、版本升级、数值裁剪必须集中在纯函数中；非法 JSON、旧版本或超出视口的值回退默认值。

## 7. 性能与安全要求

- 批量操作对要素数组最多线性遍历，不能为每个要素重复完整渲染；提交后一次性刷新受影响图层。
- 选择模式不得构造媒体详情、iframe 或完整缩略图，只显示现有列表图标。
- 拖动/缩放小窗只更新自身 transform/尺寸，不触发地图 `fitBounds`、KML 解析或瓦片请求。
- 所有批量目标仍由现有权限函数和 KML 数据校验约束；不得新增任意 URL、代理或跨账号入口。

## 8. 验收标准

1. 2D、3D 可进入批量模式，跨多个可写个人 KML 选择点位/线段；全选和反选数量准确，取消后无数据变化。
2. 批量移动保留 ID、源文件移除；批量复制源文件保留、副本 ID 全部不同；批量删除需确认且一次完成。
3. 任一批量失败时所有文件保持原样；成功操作可通过一次撤销完整恢复。
4. 只读、公共、分享 KML 不出现批量入口和复选框，账号同步包含全部受影响文件。
5. 桌面大屏在有额外水平空间时显示宽屏按钮；切换后内容区域扩大，刷新/再次打开仍保留选择；窄屏不显示该按钮。
6. iframe shell 与 iframe 高度一致且无宿主上下内边距造成的黑边；无缩放控件时底部元信息仍保持右对齐。
7. 小窗可拖动、可通过左上角和右下角透明/可视热点调整大小，边界不会跑出视口；刷新和再次打开后位置/尺寸恢复，移动端不出现桌面手柄。
8. 小窗标题区紧凑，按钮操作不触发拖动；拖动/缩放期间地图不移动、不横向滚动。
9. 搜索面板可用右上角关闭按钮关闭；即使地图 SDK 加载失败也保持可用；2D/3D 不再展示独立“管理后台”按钮；左上角控件 hover 边框完整。
10. 现有媒体缩略项目数量、图片缩放、iframe 参数、返回手势、关闭释放和地图缩放过渡测试全部保持通过。
11. 相关定向测试、`npm run check`、`npm test`、`npm run build`、`git diff --check` 通过。
