# 瓦片缓存治理与 URL 缓存键策略需求

> 状态：v1.5.53 已部署到 161，待内测验收
> 日期：2026-08-29
> 适用范围：管理后台缓存治理、瓦片回源缓存、预缓存、公开分享瓦片请求

## 1. 背景

现有缓存治理页只提供统计、按图源清理和清空全部缓存。缓存目录规模较大时，管理员无法先预演删除范围、按过期时间或归属筛选、控制单次清理规模，也看不到治理任务和 URL 重复分析记录。

当前物理缓存键默认使用完整回源 URL。查询参数顺序、可轮换密钥、等价子域名或供应商历史模板变化可能产生内容相同但键不同的文件；但不同供应商的参数语义并不一致，不能在代码中统一删除参数或合并主机，否则可能把真实不同的瓦片错误复用。

## 2. 目标

1. 将缓存治理改为“概览、清理策略、URL 分析、执行记录”子 Tab。
2. 支持容量水位、过期保留、自动治理周期、批次规模等策略，并给出建议值而非业务硬上限。
3. 清理必须先预演，再按文件数和字节数分批执行；保留可追溯记录和取消能力。
4. 管理查询优先读取派生索引和持久化快照，避免页面刷新反复扫描缓存目录。
5. URL 缓存键规则按图源配置，默认继续使用完整 URL；管理员分析确认后才可启用归一化。
6. 新缓存键启用后兼容读取旧缓存，不因规则切换一次性失效或搬迁全部文件。

## 3. 非目标

- 不硬编码高德、Google、百度或其他供应商的参数规则。
- 不在页面加载时自动执行高 I/O 的全量 URL 分析。
- 不改变 Leaflet/Cesium 连续缩放、瓦片清晰度或已有预缓存范围语义。
- 不以固定文件数静默裁剪缓存统计、清理结果或历史记录的真实总数。
- 不提供任意 URL 代理入口，不放宽现有回源白名单和 SSRF 防护。

## 4. 信息架构

### 4.1 概览

- 展示文件数、正文体积、Sidecar 体积、估算物理占用、新鲜/可回退/过期数量、索引覆盖率、最近校准时间和正在执行的任务。
- 展示按图源聚合的数据，允许把某个图源带入清理预演或 URL 分析。
- “清空全部”不作为默认主操作；危险操作必须先生成预演结果再确认执行。
- 统计刷新读取现有快照；索引校准由管理员主动触发，或按低频后台周期单任务执行。

### 4.2 清理策略

- 容量策略使用 `softLimitBytes`、`hardLimitBytes`。`null` 表示不限制，`0` 表示不写入持久缓存。
- 管理端可以展示服务器建议值，但后端不设置面向某台服务器的产品上限；只校验非负安全整数和软水位不高于硬水位。
- 支持最低空闲磁盘、自动治理开关、自动治理周期、过期保留天数、每批最大文件数和每批最大字节数。
- 容量水位按正文与 Sidecar 的估算物理占用计算；管理员输入不按 66 或其它单机规格设置业务最大值。
- 文件数、分析样本数、单批字节数允许设置技术安全上限，以避免单次请求或单批任务阻塞事件循环；该上限必须在界面和接口错误中明确标注为系统保护边界。
- 自动治理到达软水位时只排队一个低优先级任务；到达硬水位且无法释放空间时，允许回源响应返回但跳过持久化，不能阻断现有缓存读取。
- 自动治理按“超过保留期的过期项、其它过期项、无归属项、磁盘压力下的可回退项”逐级处理，不自动删除仍新鲜且有归属的缓存。
- 回源写入在收到响应头后先预留在途容量，落盘前再按实际正文与 Sidecar 大小复核；缺少 `Content-Length` 且配置了硬水位/最低空闲空间时，保守跳过持久化。

### 4.3 清理预演与执行

- 过滤条件至少支持：图源、缓存状态、新鲜度/失效时长、资源类型、无归属缓存、最大文件数和最大字节数。
- 预演只查询派生索引，不扫描文件系统；返回文件数、字节数、状态分布、最多 100 条脱敏样本、索引覆盖率和是否精确。
- 索引未完成时禁止执行破坏性任务并返回 `INDEX_NOT_READY`，避免基于部分索引误删。
- 预演生成固定的 `previewId`、筛选摘要和选择截止时间；执行只删除截止时间之前且仍匹配的条目。
- 清理任务同时受文件数和字节数批次约束，每批后让出事件循环，跳过正在写入或临时文件。
- 删除与缓存提交按物理路径串行；删除前校验正文大小、Sidecar 版本和更新时间，预演后被替换的新文件必须跳过。
- 单个文件超过当前批次字节上限时不得绕过上限强制删除，管理员需明确调整批次策略后重新预演。
- 任务支持取消；记录创建人、条件、扫描/命中/删除数、释放字节数、状态、耗时和错误摘要。

## 5. 低 I/O 索引

- 缓存正文和 sidecar 仍是可恢复事实来源；SQLite 派生索引用于查询、预演和任务选择。
- 新缓存写入、重验证和删除通过有界队列更新索引，不在每次缓存命中时写 `lastAccessAt`。
- 索引写入和兼容别名重建使用 SQLite 批量事务，避免大规模缓存下逐文件提交事务。
- 全目录校准使用 `fs.opendir` 流式遍历，优先复用 sidecar 的 `size`、`updatedAt`，每固定数量条目让出事件循环。
- 校准只读解析 Sidecar；损坏或缺失的 Sidecar 不会被隐藏删除，其正文和可见元数据体积仍作为无归属缓存进入索引。
- 同一时间只允许一个校准或 URL 分析扫描；重复请求返回当前任务状态，不启动第二次扫描。
- 默认校准冷却不少于 6 小时；即使使用强制参数也保留 5 分钟硬冷却。页面轮询只读取 SQLite 和小型任务快照，不触发目录扫描。
- 索引记录物理正文和 sidecar，容量统计同时展示正文体积与估算物理占用，避免忽略元数据文件和 inode 成本。
- 最低磁盘空间通过最多每 5 分钟一次的 `statfs` 快照校验，并在快照间依据缓存写入/删除增量修正，不对每个瓦片请求重复读取目录或磁盘统计。

## 6. URL 缓存键策略

### 6.1 默认与配置

- 默认模式为 `full_url`，行为与现状一致。
- 归一化模式按 `sourceId` 独立配置，规则包括：规范主机、等价主机列表、是否排序查询参数、明确忽略的查询参数、额外敏感参数名。
- 未明确列入规则的参数一律保留；路径、端口、协议、Range 和资源类型不得隐式丢弃。
- 管理接口和日志只显示结构化脱敏 URL，密钥参数永不回显。
- 结构化 URL 只返回协议、主机、路径和参数名，不返回任何查询参数值；历史中未知的供应商密钥参数也不会通过治理接口回显。

### 6.2 分析与启用门禁

- 管理员选择图源和候选规则后主动发起分析；分析从索引按样本上限读取，不默认遍历全部正文文件。
- 结果展示原始键数、归一键数、可合并数量/字节估算、主机和参数分布、冲突数量、样本和风险提示。
- 相同归一键下出现不同文件大小、ETag、Content-Type 或内容摘要时标记冲突。存在冲突时禁止启用该规则。
- 缺少 URL 或 URL 无法解析时计入 `malformedCount` 并阻止启用归一键，不能静默跳过后给出安全结论。
- 规则保存必须引用最近一次与候选规则摘要一致且无冲突的分析记录。

### 6.3 兼容迁移

- 归一化键包含版本、`sourceId`、`resourceType`、规范 URL、完整 Range 和显式声明的内容差异维度。
- 查找顺序为：当前 v2 键、旧完整 URL v1 键、索引中的兼容别名。
- 命中旧缓存时原地读取；后续回源刷新写入 v2，旧项由常规过期/容量治理逐步淘汰。
- 不执行一次性全目录重命名，也不因启用新规则清空现有缓存。

## 7. 接口与权限

- 所有接口归入 `/api/v1/admin/cache`，使用现有后台鉴权和 CSRF 保护。
- 读取需要缓存管理读权限；策略修改、分析、校准、任务创建和取消需要管理权限。
- 策略变更、URL 规则启用、任务创建/取消/完成写入现有审计日志，记录操作者和脱敏摘要。
- 保留精确 URL 删除兼容接口；按图源和全部清理迁移为预演后的异步任务。

## 8. 安全与故障处理

- 路径必须由索引中的受控相对路径解析并校验位于缓存根目录内，禁止客户端提交任意文件路径。
- 删除前再次校验文件时间、筛选条件和选择截止时间；新写入文件不会被旧预演删除。
- 服务重启后运行中任务标记为 `interrupted`，管理员可基于原条件重新预演，不自动继续破坏性操作。
- SQLite 索引损坏时允许重建；不能因此删除缓存正文。
- URL 分析和审计记录不得保存明文密钥、认证头或代理凭据。
- 索引状态为 `stale`、`failed` 或 `running` 时不得作为精确容量和删除依据；硬水位在索引不精确时采用保守拒绝持久化。

## 9. 界面约束

- 子 Tab 使用项目现有 `admin-settings-tabs`，支持键盘和窄屏横向滚动。
- 容量输入同时提供常用单位选择和字节级准确提交；建议值以辅助状态显示，不写入 `max` 限制。
- 分析结果使用指标、分布表和冲突列表，不用单一“可优化/不可优化”结论替代证据。
- 任务状态通过右下角 Toast 和记录列表反馈，页面滚动后仍可见。
- 危险操作使用统一 Dialog；不得使用原生 `alert`、`confirm`、`prompt`。

## 10. 验收

- 重复刷新缓存治理页不会触发重复目录扫描；扫描中再次请求只返回同一任务状态。
- 管理员可保存超过任一单机建议值的容量上限；非法安全整数、软硬水位倒置会得到明确错误。
- 索引未完成时清理执行被拒绝；索引完成后预演与执行数量可对账。
- 大批量清理按批次让出事件循环，可取消，且记录释放空间和操作人。
- 多个并发 MISS 的容量预留总和不得突破硬水位；上游实际响应大于声明长度时必须在提交前再次拒绝或调整预留。
- 索引校准遇到损坏 Sidecar 时原文件保留、任务记录异常数量、物理占用仍可治理。
- 清理任务与同路径新缓存写入并发时，新版本文件保留且任务记录为跳过。
- 默认 `full_url` 不改变既有命中；按图源启用无冲突规则后，参数顺序或声明的等价主机可复用同一 v2 缓存。
- 未声明参数、不同 Range 或不同资源类型不会被错误合并；旧 v1 文件仍可命中。
- 管理页面在桌面和 320/375/390px 视口下无横向页面溢出，表格可在自身容器滚动。
- `npm run check`、`npm test`、`npm run build` 和 `git diff --check` 通过。

## 11. 实施与验证记录

- 已完成容量策略、SQLite 派生索引、清理预演与任务、按图源 URL 分析、版本化归一缓存键和旧缓存兼容读取。
- 完整清空缓存使用全局清空/写入闸门：阻止新写入、等待在途正文和 Sidecar 提交完成后再删除；正常缓存和容量绕过响应在返回前打开文件描述符，清空路径后在途响应仍可继续读取。
