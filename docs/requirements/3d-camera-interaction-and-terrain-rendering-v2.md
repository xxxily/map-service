# 3D 相机交互与真实地形立体渲染 v2

> 状态：实施基线（2026-07-11）。本文定义当前专项的目标、边界和验收条件；其中标为“规划”或“后续”的项目不表示已经交付。本文同时记录已落地的最小实现边界，避免将候选服务或后续质量策略误写成既有能力。
>
> 替代关系：本文件替代 `3d-map-interaction-and-terrain-improvements.md` 中与相机交互、地形和三维观感有关的需求；旧文档保留为历史记录。

## 1. 背景与问题定义

`3d.html` 的三维浏览目前存在两个相互影响但本质不同的问题：

1. 在 3D 操作状态下，常规拖拽容易被解释为旋转或倾斜，而不是用户预期的“把地图平移到另一个位置”。桌面端和触摸端的手势语义不一致，且自定义相机逻辑与 Cesium 默认控制器可能同时响应同一次输入，导致卡顿、跳变或只能旋转。
2. 用户在调整倾角后，山体起伏仍不稳定或不明显。仅提高 `terrainExaggeration` 不能证明真实 DEM 已加载，也无法弥补纯俯视视角、地形法线/光照不足、影像分辨率不足和坐标基准偏移带来的问题。

本专项的目标是在**不自建高度模型**的前提下，使用经批准的公共或免费可用地形服务，并通过受控的相机、地形、光照和质量策略，提供可验证、可降级的三维地形浏览体验。它不承诺复制 Google Earth 的全球摄影测量城市模型；DEM 地形、建筑模型和摄影测量网格是不同层级的数据能力。

## 2. 目标与范围

### 2.1 目标

- 在 3D 页面中，普通浏览首先保证可预期的平移；用户需要绕点观察时再显式进入绕点手势。
- 将相机交互状态与地形加载状态解耦：切换 2D/3D 操作档位不得销毁、重建或误判真实地形。
- 使用真实地形时，向用户明确展示“加载中、已验证、降级、失败”等状态，而不是静默把椭球体当作地形。
- 用低空斜视、基于高度的夸张、地形法线、光照和可选阴影提升山地立体感，并在性能不足时平稳降档。
- 保持 KML、定位、搜索、辅助线、图层选择和访问控制的已有交互优先级；地图工具接管点击时，相机手势不得抢占。

### 2.2 范围内

- 桌面鼠标、触摸屏和触摸板的相机交互语义、冲突消解与相机安全边界。
- Cesium 兼容真实地形服务的选择、运行时状态机、可观测性和安全接入方式。
- 基于地形的渲染质量档、自动降档和山地演示视角。
- WGS84、GCJ-02、影像瓦片坐标和高程基准的识别与验证要求。
- 单元、集成、手动和视觉验收方案，以及可回滚发布策略。

### 2.3 范围外

- 自行采集、生产、托管或维护全球/区域 DEM 数据。
- 在本阶段承诺全球 3D Tiles 建筑、城市摄影测量网格或 Google Earth 同级的城市三维模型。
- 为任意用户输入 URL 建立地形代理、瓦片代理或 Token 转发入口。
- 改变 2D 首页的图层业务语义，或以三维改造破坏既有 KML、辅助线数据格式。

## 3. 用户场景与体验原则

| 场景 | 用户目标 | 系统行为 |
| --- | --- | --- |
| 桌面浏览 | 把地图移到相邻区域 | 普通左键拖拽执行平移，不转动视角。 |
| 桌面查看山体 | 围绕山脊、建筑或点击点观察 | `Shift + 左键拖拽` 或中键拖拽锁定落点并绕点旋转/调整倾角。 |
| 触摸浏览 | 单手像普通地图一样拖动 | 单指拖动执行平移。 |
| 触摸查看山体 | 调整距离、方向和倾角 | 双指捏合缩放，双指旋转调整 heading，两指竖向并行移动调整 tilt。 |
| 低性能或地形服务不可用 | 继续可靠浏览 | 保留平移、缩放和普通地球浏览，明确显示平面降级，不阻塞页面。 |
| KML/辅助线选点 | 点击地图添加或编辑要素 | 工具模式优先；相机适配器不消费该次点击和拖拽。 |

体验原则：平移优先、绕点显式、一次手势只做一种主操作、手势过程中不切换解释、真实状态可见、失败可继续使用。

## 4. 交互契约

### 4.1 相机交互矩阵

下表是 3D 页面在“3D 操作档位”下的强制契约。2D 操作档位可以限制倾角并提供更稳定的顶视浏览，但不得改变普通平移和缩放的基本语义。

| 输入 | 结果 | 锚点与约束 |
| --- | --- | --- |
| 普通左键拖拽 | 平移 | 优先使用拖拽前后地表交点的差值；没有交点时按相机高度退化为屏幕平移。 |
| 单指拖动 | 平移 | 与普通左键一致，不因进入 3D 操作档位自动变成旋转。 |
| `Shift + 左键拖拽` | 绕点旋转和调整倾角 | 手势开始时锁定地表命中点；水平位移改 heading，竖向位移改 pitch。 |
| 中键拖拽 | 绕点旋转和调整倾角 | 与 `Shift + 左键拖拽` 相同；不依赖右键，以免与浏览器菜单冲突。 |
| 鼠标滚轮、触摸板 pinch | 缩放 | 以鼠标/手势中心的地表命中点为优先锚点；无命中时使用视口中心。 |
| 双指捏合 | 缩放 | 只根据两指距离变化计算；以中点为缩放锚点。 |
| 双指旋转 | 调整 heading | 根据两指夹角变化绕当前地表锚点转向。 |
| 两指竖向并行移动 | 调整 tilt | 两指间距和夹角基本稳定时，按中点的纵向位移调整 pitch。 |
| 两指横向并行移动 | 平移补充手势 | 仅在未被识别为捏合、旋转或竖向 tilt 时执行，避免双指横移无响应。 |

键盘、屏幕阅读器和无法精确双指操作的用户必须能通过可聚焦的 2D/3D 按钮、缩放控件、复位视角和“山地演示视角”完成核心浏览；不能把关键能力仅绑定在手势上。

### 4.2 手势识别与冲突消解

双指手势在开始后的短阈值窗口内分类，达到阈值后锁定本次手势类型，直到两指全部离开。建议默认阈值为：距离变化比例不小于 4% 识别为 pinch，夹角累计变化不小于 4 度识别为 heading，双指平均纵向位移不小于 12 CSS 像素且横向位移较小识别为 tilt。阈值应为可测试常量，而非散落在事件回调中的魔法数。

优先级为：地图工具选点 > 浏览器/辅助技术默认行为 > 已锁定手势 > pinch > 双指旋转 > 两指竖向 tilt > 双指横向平移 > 单指平移。分类前只记录指针，不移动相机；这样可避免手势刚开始时先平移、再突然旋转的跳变。

桌面端也采用同一原则：只有明确的 `Shift + 左键` 或中键才进入绕点状态。普通左键进入平移状态后，即使拖动过程中按下修饰键，也在下一次手势开始时再切换，避免一次拖动发生语义跳变。

### 4.3 相机适配器设计

当前实现已将鼠标、触控和触摸板输入收敛到独立的“相机交互适配器”（`src/map3d/camera-interaction.js`），而不是在多个 DOM 事件监听器中各自修改相机。Cesium 默认相机输入在页面初始化时关闭，适配器只在活动手势期间接管对应事件。

1. 适配器在手势开始时确定操作类型、地表锚点和相机初始状态；手势结束、页面失焦、指针取消和页面隐藏时必须统一清理。
2. 相机锚点按“深度命中 → 地形射线 → 椭球体命中 → 视口中心”的顺序降级。KML 与辅助线的落点也必须遵循“深度命中 → 地形射线 → 椭球体命中”，不能在真实山地已可用时固定落到椭球面。
3. 执行自定义手势期间，临时挂起会竞争同一事件的 Cesium 默认 rotate/tilt/translate 控制；结束后恢复预设状态，而不是恢复某个可能已过期的布尔快照。
4. 常规左拖的平移通过前后地表命中差计算；无地表命中时，按相机高度、垂直 FOV、**canvas 的 CSS 宽高**和屏幕位移换算相机局部世界坐标位移，不能误用高 DPR 下的 drawing buffer 尺寸。该退化路径对单帧位移实施两道限制：先限制 CSS 位移（当前默认 180 CSS 像素），再限制世界坐标位移（当前默认 1,200,000 米），以避免指针捕获丢失或拖出画布造成镜头跳变。
5. 绕点操作使用开始时锁定的世界坐标锚点，水平增量改变 heading，竖直增量改变 pitch；pitch 维持在安全范围内，滚转保持为零。
6. 缩放采用连续的对数/指数曲线并按相机高度分段。高空加快、中空平滑、低空减速；单帧位移、最小离地距离和最大相机距离均受限。
7. 操作结束后不强制把相机复位成纯俯视。只有用户主动切换到 2D 操作档位或点击复位时，才执行明确的平面视角动画。

### 4.4 交互状态与地形状态解耦

相机操作档位仅描述用户如何操作相机，当前实现状态为 `2d` 与 `3d`（概念上分别对应顶视浏览和自由三维浏览）；真实地形状态只描述地形数据是否可用。两套状态禁止互相直接赋值。

- 从 `2d` 切到 `3d`：允许倾角和绕点操作，并在首次进入时尝试受控地形；同一配置已有 terrain 或处于 fallback 时不得因反复切换而无界重建 provider。
- 从 `3d` 切到 `2d`：可以将相机平滑回到顶视；已经加载的真实地形保留在场景中，状态仍真实反映其可用性。若 fallback 正在等待自动重试，离开 3D 档位不会继续在后台强行重建 provider，也不会消耗一次尚未真正发起的重试预算。
- 地形加载失败：只使地形状态降级为平面椭球体，不能关闭平移、缩放、KML 或 3D 操作。
- 质量档切换：只改变渲染参数和请求偏好，不得改变用户当前的交互手势定义。

## 5. 真实地形服务与状态机

### 5.1 服务决策

当前实现将 **ArcGIS Terrain3D**（受控 ID：`arcgis-terrain3d`）作为“不自建 DEM”的默认接入和 PoC 基线。它由客户端直接创建 Cesium 的 ArcGIS 高程 provider，不需要项目托管高度模型或配置 Cesium Ion Token。此默认值只表示当前代码的首选尝试顺序，**不表示 ArcGIS 服务已经获得生产授权、永久免费、无配额或覆盖所有部署网络**；正式发布前仍须确认当期服务条款、覆盖范围、可用性、跨域策略和项目用途是否获准。

服务接入按以下优先级决策：

1. **当前默认 / PoC：ArcGIS Terrain3D。** 适用于验证真实山地网格、相机和视觉策略；网络、CORS、上游异常或高程验证不足时必须进入降级状态，不能把椭球体称为真实地形。
2. **生产候选：经部署审批的 Cesium World Terrain。** 仅在确认服务条款、免费额度/计费方式、目标区域可用性和来源受限的只读访问凭据后，才可把 `provider` 切换为 `cesium-world-terrain`。它不是当前生产默认值；不得使用管理员凭据、可写 Token 或不受来源限制的长期密钥。
3. **受控替代：MapTiler 或自托管的 Quantized Mesh。** 仅使用已知 `provider` 枚举。`maptiler-quantized-mesh` 只读取 `VITE_MAPTILER_TERRAIN_URL` 提供的、已审批且受控的构建期 endpoint；该 endpoint 可包含服务商明确允许公开、权限和来源均受限的读取 Key，但不是用户输入、URL 参数或 relay/proxy 的目标地址。未配置或未审批时应自然降级，不能把它宣传为开箱即用的免费服务；`self-hosted` 的地址只允许来自受控部署配置，不来自用户输入。
4. **安全降级：椭球体平面。** 没有可用服务、授权失败、网络/CORS 失败、超时或持续瓦片错误时启用；页面继续可用，并明确提示不具备真实地形。

浏览器端只应拿到渲染所必需的、受约束的部署配置。访问 Token 不得来自 URL、localStorage、管理备注或公开 API 的敏感字段；若服务商架构要求浏览器携带 Token，必须使用可撤销、最小权限、来源限制的公开读取凭据，并在部署文档中单独登记其风险和轮换办法。项目不新增任意地形 URL 的表单、查询参数、代理或 Token 转发入口。

### 5.2 地形运行时状态机

地形状态机独立于相机模式，纯状态模型位于 `src/map3d/terrain-runtime.js`。当前状态与转换如下：

```text
standby --(进入 3D 且地形启用)--> loading --(provider ready)--> verifying
   |                                    |                             |
   | 配置明确关闭                         | provider 错误/20 秒超时       | 多点验证通过
   v                                    v                             v
disabled <-------------------------- fallback <--- 3 次瓦片错误 --- active
                                           ^              |              |
                                           |              v              | 单次/两次瓦片错误
                                           +-------- degraded <----------+
                                                    ^
                                                    | 验证 12 秒超时、采样异常或起伏不足
                                                    +-------------------- verifying

fallback --(可重试临时失败；1.5 秒、3 秒，至多两次)--> loading
fallback --(手动重试；重置重试预算)---------------------> loading
```

- `standby`：页面已初始化但尚未进入 3D 操作档位；显示“等待进入 3D 模式”，不会预先请求地形。
- `disabled`：用户或部署配置明确关闭真实地形；使用椭球体，不把它称为真实地形。
- `loading`：已开始创建 provider 或请求首批数据；当前 provider 加载 watchdog 为 20 秒，超时进入 `fallback`。
- `verifying`：provider 的 ready 事件已到达，但尚未验证实际高度数据；高程验证 watchdog 为 12 秒，不能仅凭 ready 就宣称地形效果已可用。验证使用固定 LOD 10，不把可能递归加载 availability 的 `sampleTerrainMostDetailed` 作为状态硬门槛。
- `active`：至少通过两个代表性山地区域的固定层级局部点簇采样；每个区域至少两个有限高度，且局部起伏差超过 100 米，并已将地形应用到当前场景。
- `degraded`：仍保留已加载的 provider，但高程验证超时/异常/起伏不足，或发生第一、第二次瓦片错误；保留当前视图，显示警告并允许手动重试。迟到的验证成功不得把已因瓦片错误降级的尝试重新标为 `active`。
- `fallback`：初始加载、provider 错误或连续第三次瓦片错误不可恢复，已回退至椭球体；必须展示失败原因的安全摘要，详细错误仅写控制台/受控遥测。

验证不得只判断“某一点高度不为零”，也不能用两个相距很远的单点绝对高差冒充局部起伏。采样点需覆盖至少两个已知山地区域，每个区域使用 3 个局部点检查有限数值和局部高程差。由于不同服务可能使用椭球高、正高或不同高程基准，绝对海拔值只作诊断，不作为唯一通过条件。

### 5.3 用户可见状态与重试

3D 页面提供非阻塞状态标签（当前为 `#terrain-status`，使用 `role="status"`、`aria-live="polite"` 和 `aria-atomic="true"`），明确呈现 `standby`、`loading`、`verifying`、`active`、`degraded`、`fallback` 与 `disabled`。状态文案只能给出安全摘要，不能暴露完整 URL、Token、服务商内部错误或网络拓扑。

状态标签附近提供独立且可访问的 `#terrain-retry-btn`（使用 `aria-describedby="terrain-status"`），不能将按钮嵌入会被状态更新覆盖的文本节点。按钮只在 `degraded` 或 `fallback` 可用；在 `loading`、`verifying`、`active`、`standby`、`disabled` 时隐藏并禁用。手动重试以 `{ force: true, manual: true }` 重建 provider、重置当前配置键的自动重试预算，但不改变当前图层、KML、辅助线或相机位置。

自动重试仅针对运行期间的临时加载/provider/持续瓦片失败，并且仅在页面仍处于 3D 操作档位时执行；同一受控配置键最多真正发起两次，固定指数退避为 **1.5 秒、3 秒**。重试次数在 provider 重建开始时才计入，退避期间切到 2D 不消耗预算，重新进入 3D 后可继续调度。配置缺失、显式关闭或缺少受控 Cesium Ion 凭据不会伪装为可自动恢复的网络失败。成功验证后重试预算清零；用户手动重试也会重置预算。相机移动、2D/3D 来回切换或状态标签刷新不得造成无界重建或无限请求。

## 6. 立体效果渲染策略

### 6.1 真实感的组成与限制

可感知的地形立体感来自四个必须共同满足的条件：真实地形网格、足够低的斜视相机、适度的高程夸张，以及可见的明暗/法线线索。只有卫星影像或仅提高高程夸张倍数，都无法稳定产生可信的山体。

DEM 地形能表现山脊、峡谷和宏观起伏，但不能自动生成城市建筑、桥梁或摄影测量立面。若后续需要城市级三维观感，应另立需求评估合规的 3D Tiles/建筑数据源、授权、性能预算和隐私风险。

### 6.2 质量档

质量契约包含 `auto`、`economy`、`balanced`、`quality` 四档。页面已提供固定定位、响应式的四段质量选择控件，使用 `aria-pressed` 读出当前值，并把输入限制在受控枚举。`auto` 当前规范化为 `balanced` 作为保守默认；基于帧时间、WebGL 能力和错误率的自动相邻档切换仍是后续能力，未实现前不得把 `auto` 宣传为动态自适应。平面降级时场景强制采用 `economy`，控件保留用户选择并明确提示实际执行档位。

| 档位 | 地形与光照 | 夸张策略 | 适用场景 |
| --- | --- | --- | --- |
| `economy` | 真实地形、基础深度关系；关闭高成本阴影 | 低空最高约 1.08x | 低端手机、节能或网络较差。 |
| `balanced` | 请求地形法线；启用地球光照和必要的大气线索 | 低空最高约 1.20x | 默认桌面和常见移动设备。 |
| `quality` | 在设备预算允许时增加地形阴影/更完整光照 | 低空最高约 1.35x | 山地观察、桌面高性能设备。 |
| `auto` | 当前等同 `balanced`；后续才按帧时间和请求失败率上下调 | 当前按 `balanced` 执行 | 推荐的保守默认。 |

夸张不是全局固定常数。provider 尚未通过验证时强制为 1.0x；验证成功后才按相机对地高度平滑衰减：低空可接近该档上限，中高空逐步回落至 1.0x，避免远景夸张导致地球轮廓失真。相机净空使用夸张后的地形高度计算，防止低空镜头进入被拉高的山体。

### 6.3 推荐视角与观察辅助

当前 3D 操作档位已提供“山地演示视角”入口，用于快速验证真实地形。该入口以已加载的地表高度为目标锚点，通过 `HeadingPitchRange` 从侧向安全距离观察，而不是把相机直接放在珠峰正上方的绝对海拔中；它是帮助用户理解效果的功能，不是地形状态的唯一判据。

## 7. 坐标与高程基准风险

Cesium 场景、GPS 和标准 KML 通常以 WGS84 为基础；国内影像服务可能采用 GCJ-02、BD-09 或服务商特定的 Web Mercator 瓦片坐标。地形看似“漂浮”、山脊与卫星影像错开，常常是水平坐标基准不一致，而不是 DEM 精度或夸张系数的问题。

必须满足以下约束：

- 每个图源在受控目录中声明水平坐标基准、瓦片矩阵和必要的转换策略；不以图层显示名推断坐标系。
- Cesium 内的实体、相机落点、地形采样和 KML 统一归一到 WGS84 语义。对 GCJ-02/BD-09 内容使用已验证的转换或服务端定义的图层适配，不在相机事件里临时猜测偏移。
- 上线前在至少三个已知地标（含山脊、道路/水体边界）比较影像、KML 和地形命中位置。出现系统性横向偏移时，先修坐标链路，不用高度偏移掩盖问题。
- 高程验证记录其基准（椭球高、正高或服务商未知）。不同垂直基准之间的常数差不能被误判为“地形加载失败”，但明显缺失起伏或非有限值必须报警。

## 8. 性能、可访问性与安全要求

### 8.1 性能

- 手势处理只在活动手势期间运行；不得在每帧重复采样地形、重建 provider 或附加监听器。
- 地形验证采样、质量档计算和状态更新均应节流/去抖；相机移动期间优先保障输入响应。
- 后续 `auto` 档应以持续帧时间、WebGL 能力和可恢复请求错误作为降档信号；恢复质量需有冷却时间，避免来回闪烁。当前 `auto` 固定映射至 `balanced`，不采集或依据帧时间自动切档。
- 真实地形请求失败不应阻塞首屏地图、目录加载或基本相机控制。低端设备的回退路径必须可用。
- 避免对每一块瓦片强制开启昂贵效果；阴影、法线和大气效果须受质量档和设备预算控制。

### 8.2 可访问性

- 当前 2D/3D 切换、重试、山地演示、视角复位和方向复位均使用可聚焦按钮，并提供中文 `aria-label` 或可见文字；状态更新使用非阻塞 live region，不使用 `alert`、`confirm`、`prompt`。
- 质量档入口可聚焦并通过 `aria-pressed` 读出当前选择；Cesium canvas 聚焦时，方向键平移、`+`/`-` 缩放，带 `Ctrl`/`Alt`/`Meta` 或输入法组合状态时不接管。地图工具激活或焦点位于输入控件时不抢占输入；canvas 通过 `aria-describedby` 向辅助技术提供键盘说明。
- `prefers-reduced-motion` 已覆盖 2D/3D 模式切换、平面化、山地演示、全局视角复位和方向复位，并由统一纯函数约束动画时长。
- 所有触摸阈值和无命中平移退化均基于 CSS 像素及 CSS canvas 尺寸，避免高 DPR drawing buffer 导致手势阈值或平移比例失真。

### 8.3 安全与隐私

- 地形服务仅允许受控 `providerId` 或经过服务端白名单校验的配置，不新增任意 URL 的前端/后端代理入口。
- 不将代理认证、私有 Token、完整请求头、内网服务地址或上游错误详情暴露给页面、日志或公开 API。
- 若增加管理配置或公开场景配置接口，必须按项目约定置于 `/api/v1/admin` 或 `/api/v1`，包含鉴权、输入校验、脱敏、错误码和 `jsonSuc`/`jsonErr` 契约；公开接口只返回渲染所需的非敏感字段。
- 服务端对任何受控地形 URL/域名执行协议、DNS/IP、重定向和内网地址校验，防止 SSRF；浏览器端不承担安全判断责任。

## 9. 配置与接口契约

本期没有新增地形管理 API 或公开场景配置 API。前端从 `src/config.js` 的构建期环境变量读取部署配置；页面不接受 URL 查询参数或 localStorage 中的原始 terrain URL/Token。受控运行时对象 `window.mapServiceTerrainConfig` 只能覆盖 `enabled`、`provider`、`quality`、`exaggeration` 和 `demoView`；其中的 `selfHostedUrl`、`mapTilerUrl`、`ionToken` 或其他 URL/Token 字段会被忽略并继续使用构建期值。不得将此能力暴露为用户可编辑的页面配置。

当前配置模型如下：

```json
{
  "terrain": {
    "enabled": true,
    "provider": "arcgis-terrain3d",
    "quality": "auto",
    "exaggeration": 1.18,
    "demoView": {
      "lng": 86.925,
      "lat": 27.988,
      "range": 32000,
      "heading": 28,
      "pitch": -28
    }
  }
}
```

字段约束如下：

| 字段 | 规则 |
| --- | --- |
| `enabled` | 布尔值；关闭时进入 `disabled`，不伪装为真实地形。 |
| `provider` | 受控枚举：`arcgis-terrain3d`（当前默认）、`cesium-world-terrain`、`maptiler-quantized-mesh`、`self-hosted`、`ellipsoid` 或 `none`；不接收公开请求中的原始 URL。 |
| `quality` | `auto`、`economy`、`balanced`、`quality` 之一；非法值按 `balanced` 处理，`auto` 当前也按 `balanced` 执行。 |
| `exaggeration` | 有限数值，建议限制在 1.0 至 1.6；最终有效值仍由相机高度函数约束。 |
| `demoView` | 仅部署配置使用的山地目标点与侧向观察参数；`range` 是到目标的安全视距，不是绝对相机海拔。 |
| `ionToken` | 仅 `cesium-world-terrain` 等需要 Cesium Ion 的 provider 使用；必须为可撤销、最小权限、来源受限的只读 Token。 |
| `selfHostedUrl` | 仅 `self-hosted` 使用，并只来自 `VITE_CESIUM_TERRAIN_URL` 等受控构建配置；不得来自表单、URL、localStorage 或普通公开 API。 |
| `mapTilerUrl` | 仅 `maptiler-quantized-mesh` 使用，并只来自 `VITE_MAPTILER_TERRAIN_URL`。它是已审批、受控的构建期 endpoint，可能包含服务商允许公开的受限读取 Key；不得来自用户输入、URL 参数、localStorage、公开 API 或任意 relay/proxy。 |

构建变量为 `VITE_CESIUM_TERRAIN_PROVIDER`、`VITE_CESIUM_ION_TOKEN`、`VITE_CESIUM_TERRAIN_URL`、`VITE_MAPTILER_TERRAIN_URL`、`VITE_CESIUM_TERRAIN_EXAGGERATION`、`VITE_CESIUM_SCENE_QUALITY` 和 `VITE_MAP3D_CAMERA_PROFILE`。相机档位仅允许 `enhanced` 或 `compatibility`；兼容档保留已验证的平移、缩放和键盘路径，关闭高风险绕点/倾角增强，且不影响地形、图层、KML 或辅助线。旧 `VITE_MAP3D_CAMERA_ADAPTER_ENABLED=false` 继续映射到兼容档。由于 `VITE_*` 会进入浏览器构建产物，任何通过它传入的 Token 或 endpoint 内 Key 都必须被服务商明确允许公开、严格限制来源和权限，不能当作秘密保存。

若后续新增接口，最小交付物必须包括路径、方法、鉴权方式、请求/响应示例、错误示例、字段说明和测试。地形 provider 的 URL、Token、管理备注、代理凭据和安全请求头不属于公开响应字段。

## 12. 回滚策略

- 当前 `terrain.enabled` 可独立关闭真实地形并进入 `disabled`；高成本效果受质量预设控制；`VITE_MAP3D_CAMERA_PROFILE=compatibility` 可独立回滚增强绕点/倾角，同时保留稳定平移、缩放和键盘路径。
- 目标回滚顺序为：切换节能质量档 -> 切换椭球体平面 -> 切换相机兼容档。三者不得清除用户图层、KML、辅助线或相机之外的数据。
- 回滚不得删除 localStorage 中的图层记忆、KML、辅助线或用户可见状态；不得修改后端数据。
- 回滚后的状态标签应清晰说明当前为平面/兼容模式，避免用户误以为真实地形仍生效。

## 13. 后续决策点

- 在部署环境中确认 ArcGIS Terrain3D 的实际授权、可用性、覆盖范围、跨域策略和合规条款；若不满足生产条件，再在同等审查后评估 Cesium World Terrain 或其他受控候选，不能仅因当前默认值就把任何服务视为生产默认。
- 在部署环境中确认 Cesium World Terrain 的可用性、免费额度、访问凭据来源限制和合规条款后，才能将 `provider` 切换为 `cesium-world-terrain`。
- 若需要更强的城市级立体观感，另行评估合规 3D Tiles/建筑数据源，而不是继续无限提高 DEM 夸张倍数。
- 若国内图层基准验证发现系统性偏移，优先建立图源坐标基准目录和转换测试，再推广新的地形提供商。
