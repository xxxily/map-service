# 图源管理与图层配置重构需求

## 背景

当前项目已经具备前台 2D/3D 地图、瓦片代理缓存、预缓存任务、对外图层 API 和管理后台能力，但“图层”和“瓦片提供方”的表达仍然分散：

- 前台图层组合写死在 `src/map/tile-sources.js` 和 `src/map/layers.js`，例如“高德/卫星”实际由高德卫星图源和高德道路图源叠加组成。
- 3D 页面通过 `createCesiumLayerSources()` 使用另一套图层组合映射。
- 后台预缓存 provider 写死在 `service/bin/admin/tileProviders.js`，只能表达单一瓦片源，不能表达前台组合图层。
- 管理后台 `src/admin/pages/layers.js` 目前只是只读展示 provider，没有运行时新增、编辑、禁用、排序、健康检查和策略管理能力。
- 代理策略目前接近单一全局代理加 providerId 开关，无法同时维护多个代理出口，也无法让不同图源按需选择不同出口或代理池。
- 对外图层 API 当前只有一套 `tileApi.upstreamUrl` 配置，只能对外提供一个固定上游图源，且代理、缓存、日志都与图源目录分离，容易形成重复缓存和隐性策略。
- 缓存策略在瓦片请求和对外图层 API 中分别控制，缺少以“图源”为中心的统一治理。

本次重构目标是引入明确的“图源”概念，将图源的地址模板、坐标协议、缓存策略、代理策略、可用缩放、服务商信息、健康状态和安全边界集中到管理后台维护；图层则变成一个或多个图源的展示组合，由管理员配置后下发给前台使用。代理也应同步升级为可管理的代理出口和代理池，让图源能关联一个或多个代理出口，并具备基础轮询、失败切换和外部专业代理工具适配能力。对外 API 应升级为“图源发布”能力，支持同时发布多个系统图源、系统图层或专用图源，并复用统一代理与缓存链路。项目当前无人正式使用，不需要兼容旧代码结构和旧配置格式，应按更优架构直接改版。

## 核心目标

- 建立统一的图源目录，作为瓦片请求、代理、缓存、预缓存、对外 API 和前台渲染的唯一事实来源。
- 将现有高德、Google 图源和现有组合图层全部初始化到后台配置中，保证改版后默认展示能力不降级。
- 管理后台从“图层配置”升级为“图源管理”主面板，并提供图层组合配置能力。
- 前台 2D 和 3D 地图不再硬编码底图目录，统一从后端公开配置接口加载可见图层。
- 图层由一个或多个图源叠加生成，支持透明度、顺序、可见性、默认图层、标签/影像混合等组合能力。
- 建立代理出口和代理池目录，支持多个代理出口并存，支持图源按需关联代理出口或代理池。
- 图源级集中控制是否使用服务端缓存、是否使用代理池、是否允许预缓存、是否允许对外 API 暴露。
- 对外 API 支持多发布项，不再只有一个固定对外图源；每个发布项显式关联图源、图层、代理、缓存、安全准入和日志策略。
- 对外 API 复用统一图源缓存，不再单独构造重复缓存体系。
- 代理能力聚焦基础适配和健壮性，不把系统建设成专业代理调度平台；复杂最优路由、地理出口优选、动态 IP 池等能力可交给外部代理工具。
- 为后续用户自定义图源预留机制，让用户能按需组合自己的图层，同时不破坏服务端安全边界。

## 术语定义

### 图源

图源是“可请求的数据来源”，是代理、缓存、预缓存和安全校验的最小策略单元。当前阶段主要指栅格瓦片源。

图源示例：

- 高德卫星瓦片
- 高德道路瓦片
- Google 卫星瓦片
- Google 街道瓦片
- 未来自定义 XYZ/TMS/WMTS/WMS 或矢量瓦片源

### 图层

图层是“前台可选择的展示组合”，由一个或多个图源按顺序叠加形成。

图层示例：

- 高德/卫星 = 高德卫星图源 + 高德道路图源（道路半透明）
- 谷歌高德/卫星 = Google 卫星图源 + 高德道路图源（道路半透明）
- 谷歌/街道 = Google 街道图源

### 系统图源与用户图源

- 系统图源：管理员在管理后台配置，持久化在服务端，能使用服务端代理、缓存、预缓存和对外 API。
- 用户图源：前台用户在浏览器内自定义，默认仅保存在用户本地，默认直连加载。若要使用服务端代理或缓存，必须符合管理员允许的自定义图源策略。

### 代理出口

代理出口是一个具体可用的代理连接配置，例如本机 Clash/Whistle 暴露的 HTTP 代理、远端 HTTP 代理或后续支持的 SOCKS5 代理。代理出口只描述“怎么连接代理”，不直接决定哪个图源使用它。

### 代理池

代理池是一组代理出口及其选择策略。图源可以关联一个代理池，由服务端在请求时按策略选择出口。当前阶段代理池只需要支持基础的优先级、轮询、失败跳过和手动测试；不要求实现复杂的最优线路计算。

### 对外发布项

对外发布项是把系统能力暴露给第三方 GIS 客户端的配置单元。它可以引用一个系统图源、一个系统图层，或内嵌一个只用于对外服务的专用图源配置。对外发布项只负责准入、路径、Token、限流、日志和可覆盖策略，实际瓦片请求仍走统一图源、代理和缓存链路。

## 用户与场景

### 管理员

- 新增或调整地图服务商的图源地址，不需要修改前端源码。
- 配置多个代理出口，并将不同图源关联到不同代理出口或代理池。
- 设置某个图源是否走代理，例如 Google 默认走代理池，高德默认直连。
- 为一个图源配置多个代理出口，在单个出口失败时自动切换到其他可用出口。
- 设置某个图源是否写入服务端缓存，是否可用于预缓存，是否可被对外 API 使用。
- 创建多个对外发布项，将不同图源或图层分别开放给外部系统使用。
- 为对外发布项选择系统已有图源，或配置仅用于对外发布的专用图源，并显式设置代理和缓存策略。
- 将多个图源组合成一个前台图层，并设置默认显示图层、排序、透明度和最大缩放。
- 查看图源健康状态、代理出口健康状态、最近错误、缓存命中、请求耗时和预缓存失败原因。

### 普通前台用户

- 在前台选择管理员发布的图层。
- 通过 URL 分享当前视图和当前图层。
- 后续可添加自己的私有图源，并组合成自己的临时或本地图层。

### 开发与运维人员

- 新增图源类型或图层能力时只扩展统一模型，不再分别修改 2D、3D、预缓存和对外 API 的硬编码目录。
- 排查瓦片加载问题时能按图源和代理出口查看代理、缓存、健康检查和请求日志。

## 范围

### 本次纳入

- 新建服务端图源与图层数据模型。
- 管理后台提供图源管理、图层组合管理和默认展示配置。
- 初始化现有图源和图层到新模型。
- 前台 2D/3D 地图从公开接口加载图层目录。
- 预缓存任务按图源或图层创建；选择组合图层时，任务可展开为多个图源的瓦片任务。
- 对外图层 API 从单一 `tileApi.upstreamUrl` 升级为多发布项，可发布系统图源、系统图层或专用图源。
- 对外 API 的代理、缓存、日志和限流策略纳入统一图源发布模型，不再维护独立上游和独立缓存。
- 缓存统计和清理能力支持按图源维度聚合。
- 代理策略从 `settings.proxy.providerPolicy` 收敛到代理出口、代理池和图源关联策略中。
- 管理后台支持代理出口和代理池配置，图源可关联指定代理出口或代理池。
- 代理池支持基础选择策略：优先级、轮询、失败切换。
- 用户自定义图源的前端入口和数据模型预留，至少支持本地保存和本地组合图层。

### 本次不纳入

- 多租户、多用户云端同步用户私有图源。
- 复杂 GIS 样式引擎和矢量瓦片样式编辑器。
- 分布式缓存、分布式预缓存 worker。
- 专业代理调度系统，例如按地理位置自动选最优出口、按延迟实时全局调度、动态住宅代理池、代理计费和流量控制。
- 商业地图服务授权自动校验；只在配置中提供服务条款、版权和风险提示字段。
- 旧配置格式兼容迁移。可以提供一次性初始化脚本或启动时补齐默认配置，但不需要长期兼容旧字段。

## 产品需求

### P1. 管理后台导航调整

- 将当前“图层”菜单升级为“图源管理”。
- 图源管理下至少包含五个视图：
  - 图源：管理可请求来源。
  - 图层：管理前台展示组合。
  - 代理：管理代理出口、代理池和健康状态。
  - 发布/API：管理对外发布项、访问凭证和接入示例。
  - 诊断：查看健康检查、请求日志、缓存命中和错误聚合。
- 当前独立的对外开放图层 API 页面应合并到图源管理的“发布/API”配置中，避免图层 API 再维护一套上游 URL、代理开关和缓存逻辑。

### P2. 图源列表

图源列表应支持：

- 按名称、厂商、类型、启用状态、代理池、代理状态、缓存状态搜索和筛选。
- 显示图源 ID、名称、厂商、类型、协议、缩放范围、缓存开关、代理策略、关联代理池、预缓存开关、健康状态。
- 支持启用、禁用、复制、编辑、删除。
- 被图层引用的图源删除前必须提示影响范围，并阻止直接删除；应先解除引用或禁用。
- 支持拖拽或字段排序，但排序只影响管理展示，不影响图层渲染。

### P3. 图源编辑

图源编辑表单至少包含：

- 基本信息：名称、唯一 ID、厂商、分类、描述、标签、启用状态。
- 请求配置：类型、URL 模板、子域、坐标方案、请求方法、请求头、图片格式、retina/scale 参数策略。
- 缩放配置：最小缩放、最大缩放、最大原生缩放、瓦片倍率 scale。瓦片网格尺寸当前固定为 256，不允许管理员随意输入任意像素值；1x/2x/3x 只影响上游 `{scale}` 请求倍率。
- 空间配置：可用区域 bounds、坐标系、是否需要纠偏说明。
- 策略配置：是否允许前台显示、是否允许作为叠加图源、是否允许预缓存、是否允许对外 API、是否允许用户引用。
- 缓存配置：是否启用服务端缓存、TTL、stale TTL、最小缓存字节、是否允许强制刷新。管理端展示和编辑必须使用天、小时、分钟，提交接口前换算为毫秒。
- 代理配置：代理模式、关联代理出口或代理池、出口选择策略、失败回退策略、健康检查阈值。
- 合规信息：attribution、服务条款 URL、密钥使用说明、备注。
- 诊断信息：测试坐标、测试 URL、最近检查结果。

代理模式建议：

- `never`：该图源始终直连。
- `fixed`：该图源固定使用一个代理出口。
- `pool`：该图源使用一个代理池，由代理池按策略选择出口。

代理池选择策略建议：

- `priority`：按管理员配置的优先级选择第一个健康出口。
- `round_robin`：在健康出口之间轮询，适合均摊请求压力。
- `failover`：默认使用主出口，失败后在本次请求或短时间窗口内切换到备用出口。

第一阶段必须支持图源关联指定代理出口或代理池；`round_robin` 和 `failover` 可以按实现复杂度分阶段落地。暂不要求实现按延迟、地理位置、服务商质量自动选择最优出口。

### P4. 代理出口与代理池管理

代理视图应支持：

- 新增、编辑、禁用和删除代理出口。
- 代理出口字段包括名称、ID、协议、主机、端口、账号、密码、启用状态、备注和测试 URL。
- 第一阶段至少支持 HTTP/HTTPS 代理；如果外部专业代理工具提供本地 HTTP 代理端口，应可直接作为普通代理出口接入。
- 本机代理出口必须支持 `localhost`、`127.0.0.0/8` 和 `::1`，不能因上游 URL 的 SSRF 校验而误拒绝管理员明确配置的本机 Clash、Mihomo 或 Whistle 进程。
- Clash/Mihomo Fake-IP 模式下，公开域名可能被本机 DNS 合成为 `198.18.0.0/15`。仅允许本机回环代理消费“全部结果均属于该合成网段”的解析结果；直连、远程代理、混合 DNS 及其他内网/保留地址继续拒绝。
- 模型可预留 SOCKS5、PAC 或自定义连接器，但不作为首期必需能力。
- 新增、编辑、禁用和删除代理池。
- 代理池字段包括名称、ID、出口列表、出口优先级、选择策略、失败冷却时间、单请求最大切换次数。
- 支持对单个代理出口执行连通性测试，并记录最近成功时间、最近失败时间、耗时和错误摘要。
- 支持对代理池执行批量健康检查，展示健康出口数和最近一次检查结果。
- 删除被图源引用的代理出口或代理池时必须阻止删除，并展示引用它的图源列表。
- 代理账号密码属于敏感信息，后台列表只展示是否已配置，不展示明文。

### P5. 对外发布/API 管理

发布/API 视图应把当前“对外开放图层 API 设置”重构为多发布项管理：

- 支持创建多个对外发布项，而不是全系统只能配置一个 `upstreamUrl`。
- 发布项可以选择：
  - 系统图源：直接发布管理后台已有图源。
  - 系统图层：发布一个组合图层的 TileJSON 或图源列表说明。
  - 专用图源：创建只服务于该发布项的图源配置，不出现在前台图层选择器和常规图源列表默认视图中，但仍纳入统一图源、代理和缓存链路。
- 每个发布项必须有稳定 `publishId`，作为外部 URL 的一部分。
- 每个发布项支持启用/禁用、名称、描述、访问路径、发布对象、Token 策略、限流策略、日志上限和接入示例。
- 每个发布项的代理策略默认继承所关联图源；如需覆盖，必须显式选择代理模式、代理出口或代理池，并在详情页展示“已覆盖图源代理策略”。
- 每个发布项的缓存策略默认继承所关联图源；如需覆盖，只能在图源允许的范围内调整，且必须继续写入统一缓存命名空间。
- 同一个系统图源被前台、预缓存和对外 API 使用时，应共享同一套缓存键和缓存文件，不能因为请求入口不同重复存储同一瓦片。
- 发布项应提供 Leaflet、OpenLayers、QGIS 和通用 XYZ URL 示例。
- 发布项日志支持按 publishId、sourceId、layerId、proxyOutboundId、状态码、缓存状态筛选。
- 删除发布项不删除图源和缓存；如管理员要清理缓存，应跳转到缓存治理按图源清理。

专用图源规则：

- 专用图源本质仍是图源，只是 `visibility.scope` 为 `external_only`。
- 专用图源可配置自己的 URL 模板、代理池、缓存策略、权限和健康检查。
- 专用图源不参与前台 catalog，不允许预缓存，除非管理员显式打开。
- 专用图源允许后续提升为系统图源，提升后才可用于前台图层组合。

### P6. 图层列表

图层列表应支持：

- 显示图层 ID、名称、图层类型、包含图源数量、默认状态、前台可见状态、更新时间。
- 支持新增、复制、编辑、禁用、删除、设为默认图层。
- 支持排序，排序结果影响前台图层选择器的展示顺序。
- 支持区分“底图图层”和“叠加图层”。当前阶段已有底图按底图图层管理；KML 公共图层保持在 KML 模块，但命名上应避免与底图图层混淆。

### P7. 图层编辑

图层编辑表单至少包含：

- 基本信息：名称、唯一 ID、描述、启用状态、前台可见、默认图层、标签。
- 适用客户端：2D、3D 或两者都支持。
- 图源组合：选择一个或多个图源，设置顺序、透明度、混合模式、是否可由用户调整透明度。
- 显示配置：缩放范围、默认不透明度、图例信息、attribution 聚合策略。
- 分享配置：URL 中使用稳定 layerId，不再使用中文图层名作为主要状态。
- 预览：在管理后台内用小地图预览组合效果，并显示当前生成的瓦片请求 URL。

### P8. 默认初始化数据

系统首次启动或后台配置为空时，应初始化以下图源：

| 图源 ID | 名称 | 类型 | 默认代理策略 | 默认缓存 | 默认预缓存 | 缩放 |
| --- | --- | --- | --- | --- | --- | --- |
| `amap-satellite` | 高德卫星 | satellite | 直连 | 是 | 是 | 3-18 |
| `amap-road` | 高德街道 | road | 直连 | 是 | 是 | 3-18 |
| `google-satellite` | Google 卫星 | satellite | 默认代理池 | 是 | 是 | 3-22 |
| `google-satellite-hd` | Google 卫星 HD | satellite | 默认代理池 | 是 | 是 | 3-22 |
| `google-road` | Google 街道 | road | 默认代理池 | 是 | 是 | 3-22 |

系统首次启动或代理配置为空时，应初始化：

- `default-proxy-outbound`：默认代理出口，使用当前系统代理配置的 host、port、protocol、username、password；如果当前未配置代理，则保持禁用并标记为“待配置”。
- `default-proxy-pool`：默认代理池，包含 `default-proxy-outbound`，选择策略为 `priority`。

Google 图源默认关联 `default-proxy-pool`。如果代理池没有可用出口，图源健康检查应提示代理不可用；具体请求是否允许回退直连由图源的 `fallbackToDirect` 策略决定，默认不回退，避免管理员误以为请求已经通过代理出口。

系统首次启动或后台配置为空时，应初始化以下图层：

| 图层 ID | 名称 | 图源组合 |
| --- | --- | --- |
| `amap-hybrid` | 高德/卫星 | `amap-satellite` + `amap-road` 透明度 0.5 |
| `amap-road` | 高德/街道 | `amap-road` |
| `google-amap-hybrid` | 谷歌高德/卫星 | `google-satellite` + `amap-road` 透明度 0.7 |
| `google-amap-hybrid-hd` | 谷歌高德/卫星（HD） | `google-satellite-hd` + `amap-road` 透明度 0.7 |
| `google-sat` | 谷歌/卫星 | `google-satellite` |
| `google-road` | 谷歌/街道 | `google-road` |

默认图层为 `amap-hybrid`。

系统首次启动或对外 API 配置为空时，应初始化一个兼容当前能力的发布项：

- `default-google-satellite-api`：默认禁用，关联 `google-satellite` 图源，用于替代旧的单一 `tileApi.upstreamUrl` 配置。
- 如果旧配置中已启用对外 API，可在一次性初始化时转换成一个专用发布项，但不需要长期兼容旧字段。

### P9. 前台图层选择

- 前台图层选择器只展示启用且前台可见的图层。
- 前台应按后台排序展示图层。
- 用户切换图层后，保存稳定 `layerId` 到 localStorage 和 URL。
- URL 支持 `layer=<layerId>`；若 layerId 不存在或已禁用，回退到后台默认图层。
- 2D 和 3D 使用同一份图层配置；当某图层不支持当前客户端时不展示。
- 图层加载失败时使用项目统一的非阻塞提示，不得使用原生 `alert`、`confirm`、`prompt`。

### P10. 用户自定义图源

用户自定义图源作为后续扩展能力，但本次模型需要预留：

- 前台允许用户新增本地私有 XYZ/TMS 图源，保存在浏览器 localStorage。
- 用户可用本地图源组合出本地图层，并在当前浏览器中使用。
- 用户图源默认由浏览器直连，不默认进入服务端代理和缓存。
- 若管理员允许“用户图源使用服务端代理”，必须配置允许的协议、域名白名单、请求频率和缓存限制，避免 SSRF 与滥用。
- 用户自定义图源不得影响系统图源目录，不得被对外 API 自动发布。

## 系统架构需求

### A1. 统一配置来源

服务端应新增图源与图层配置存储，建议由 `AdminStore` 持久化为独立 JSON 文件：

- `tile-sources.json`
- `map-layers.json`
- `proxy-outbounds.json`
- `proxy-pools.json`
- `external-publishes.json`
- `tile-source-health.json`
- `proxy-health.json`

配置读取路径：

1. 服务启动时读取持久化配置。
2. 若配置不存在或为空，写入默认初始化数据。
3. 管理后台修改后立即更新持久化配置和内存缓存。
4. 代理出口和代理池由同一套服务层读取，图源只保存引用关系和策略。
5. 对外发布项只保存发布元数据和覆盖策略，实际请求仍委托图源服务。
6. 前台、后台、预缓存和对外 API 都从同一个服务层读取。

不再保留前台硬编码图层目录作为运行时事实来源。

### A3. 瓦片请求解析

服务端应提供基于图源 ID 的瓦片请求接口，避免前台继续把完整上游 URL 传给 `/tiles/relay`：

- 推荐：`GET /api/v1/tiles/:sourceId/{z}/{x}/{y}`
- 或保留查询形式：`GET /api/v1/tiles/source?sourceId=...&z=...&x=...&y=...`

服务端根据 `sourceId` 读取图源模板并生成上游 URL，然后统一执行：

1. 访问控制校验。
2. 图源启用状态校验。
3. 坐标和缩放校验。
4. 图源权限校验。
5. 代理策略计算。
6. 代理出口选择。
7. 缓存策略计算。
8. 回源请求。
9. 失败切换或直连回退判断。
10. 日志与指标记录。

旧的 `url=` 直传模式可以直接废弃，或仅保留为管理员诊断接口，不作为前台主路径。

### A4. 代理池与出口选择

代理池应定位为轻量适配层：

- 支持多个代理出口配置，便于不同图源选择不同出口。
- 支持一个图源关联一个代理池，代理池内部可有多个出口。
- 支持出口级健康状态，短时间内连续失败的出口进入冷却，冷却期间不参与自动选择。
- 支持单请求失败切换：请求通过某出口失败后，可在同一代理池中选择下一个健康出口重试，重试次数受 `maxAttemptsPerRequest` 限制。
- 支持基础轮询，减少单出口压力。
- 支持固定出口，便于某些图源必须使用指定出口。
- 支持外部专业代理工具接入：管理员可把 Clash、Whistle、Nginx、商业代理 SDK 网关等暴露的本地或远端 HTTP 代理作为一个普通代理出口。

暂不要求：

- 按瓦片地理坐标自动选择最近出口。
- 按实时网络质量做全局最优路由。
- 代理出口自动采购、自动扩容、自动计费。
- 复杂 PAC 解析和浏览器级代理规则复刻。

出口选择结果应作为请求上下文的一部分传递给 fetch relay，日志中记录 `proxyOutboundId`、`proxyPoolId`、`proxyAttempt` 和 `proxyFallbackReason`。

### A5. 白名单与安全边界

- 系统图源的上游域名来自管理员配置，保存前必须校验 URL 模板合法性。
- 服务端瓦片请求不得接受任意用户传入的完整 URL 作为默认路径。
- 用户自定义图源若需要服务端代理，必须命中管理员配置的自定义图源白名单，并只能使用管理员允许的代理池。
- 上游目标与代理出口必须采用不同安全语义：上游目标继续禁止 localhost、内网、link-local、metadata 和保留地址；管理员配置的受控代理出口允许指向本机回环代理。
- `198.18.0.0/15` 仅作为本机 Clash/Mihomo Fake-IP 兼容信号，不得用于直连，也不得与公网或其他私网 DNS 结果混用；代理出口不是本机回环地址时必须拒绝。
- 代理出口 host 禁止配置为 localhost、内网地址、link-local、metadata 服务等敏感地址，除非管理员显式以本机代理类型创建，并且只用于代理连接本身，不用于图源上游模板。
- 代理出口的账号密码不得下发给前台。
- URL 模板只允许明确占位符：`{x}`、`{y}`、`{z}`、`{s}`、`{scale}`、`{yTms}`。
- 禁止模板指向内网地址、localhost、link-local、metadata 服务和非 http/https 协议。
- 请求头配置需要分普通头和敏感头；敏感头只在服务端保存，后台列表不得明文展示。

### A6. 预缓存改造

- 预缓存表单可选择图源或图层。
- 选择图层时，后端按图层 items 展开为多个图源任务。
- 估算结果应返回每个图源的瓦片数、预计体积、总瓦片数和总预计体积。
- 图源禁用 `precacheAllowed` 时不能创建预缓存任务。
- 对组合图层执行预缓存时，应按图源分别记录进度和失败明细，避免一个图源失败掩盖其他图源状态。
- 预缓存任务执行时使用图源配置的代理池，任务日志需记录每个图源实际使用的代理出口和代理失败切换次数。
- 管理员可在创建预缓存任务时选择是否允许临时覆盖图源代理策略，但默认应使用图源自身策略，避免预缓存和前台表现不一致。
- 删除任务关联缓存时，应按图源生成缓存键并删除，不再依赖旧 provider URL 识别。

### A7. 对外图层 API 改造

对外 API 不再配置单一 `upstreamUrl`。管理员应创建一个或多个对外发布项，每个发布项选择一个已允许对外发布的图源、图层或专用图源：

- 发布图源：外部系统请求该图源的 XYZ 瓦片。
- 发布图层：外部系统获得 TileJSON/配置说明；若是组合图层，需明确外部客户端如何叠加多个图源。
- 发布专用图源：管理员为外部客户单独配置一个图源，该图源不进入前台图层目录，但仍复用统一代理和缓存。

推荐接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/v1/external/:publishId/:z/:x/:y` | 按发布项获取单图源瓦片 |
| `GET` | `/api/v1/external/:publishId/tilejson` | 输出发布项 TileJSON 或组合说明 |
| `GET` | `/api/v1/external/:publishId/sources` | 输出组合图层包含的外部图源 URL |
| `GET` | `/api/v1/external/catalog` | 可选，输出允许公开发现的发布项目录 |

请求处理流程：

1. 根据 `publishId` 读取发布项。
2. 校验发布项启用状态、Token 和限流。
3. 解析发布项目标图源或图层。
4. 如果是单图源目标，调用统一图源瓦片服务生成响应。
5. 如果是图层目标，返回 TileJSON 或组合图源说明；首期不要求服务端把多个图源合成为一张瓦片。
6. 应用发布项显式覆盖的代理或缓存策略；未覆盖时继承图源策略。
7. 读写统一缓存元数据，记录 `publishId`，但缓存键仍以 `sourceId + tile + render options` 为主，避免重复缓存。
8. 异步记录对外访问日志。

外部 API 的 Token、限流、日志上限、缓存策略和代理策略应保留，但配置归属于发布项。默认使用图源自身代理和缓存策略；如允许对外 API 覆盖代理或缓存策略，必须在发布设置中显式声明并记录审计日志。

旧接口处理：

- `GET /api/v1/external/tile` 的单 upstreamUrl 模式应废弃并从新后端契约中移除。
- 不保留独立 `tileApi.upstreamUrl`、`tileApi.useProxy`、`tileApi.cacheEnabled` 和旧 `/api/v1/admin/tile-api/logs` 配置；对外访问日志统一归属发布项。

### A8. 缓存治理

- 缓存元数据必须记录 `sourceId`、`layerId`（如果由图层触发）、`publishId`（如果由对外 API 触发）、上游 URL、生成时间、过期时间、状态。
- 缓存统计按图源聚合，后台展示每个图源的文件数、体积、新鲜/可回退/过期数量。
- 缓存可按发布项筛选查看，但清理底层仍应指向图源缓存，避免同一瓦片被多个发布项重复存储。
- 清理缓存支持按全部、图源、图层、状态、时间范围清理。
- 图源关闭缓存后，新请求不再写入缓存，但历史缓存是否清理由管理员决定。
- 图源 URL 模板变更后，应提示旧缓存可能失效，并提供“清理该图源历史缓存”操作。

### B3. 校验规则

- 图源 ID 和图层 ID 使用稳定 slug：小写字母、数字、短横线，不能使用中文名作为主键。
- 图层至少包含一个启用图源。
- 图层引用的图源不存在、禁用或不支持对应客户端时，保存失败或标记为不可发布。
- 缩放范围必须落在所有引用图源的交集内；如允许超出，应明确按图源级 `maxNativeZoom` 处理。
- URL 模板必须能使用测试坐标生成合法 URL。
- 子域只能是短字符串数组，生成 URL 时按瓦片坐标稳定散列选择。
- 图源使用 `fixed` 代理模式时，`outboundId` 必须存在且启用。
- 图源使用 `pool` 代理模式时，`poolId` 必须存在且启用，并且代理池内至少有一个启用出口。
- 代理出口 ID 和代理池 ID 使用稳定 slug。
- 代理出口协议第一阶段支持 `http` 和 `https`；若支持 `socks5`，必须同步补充测试和文档。
- 代理出口 host、port、认证信息必须校验，密码只可写入，不可从普通详情接口明文读取。
- 代理池不能引用不存在或禁用的代理出口；删除被代理池引用的出口前必须解除引用。
- 图源启用代理但代理池无健康出口时，健康检查应给出明确错误。
- 对外发布项 ID 和 pathSlug 使用稳定 slug，不能与系统保留路径冲突。
- 发布项引用系统图源时，该图源必须启用 `externalApiAllowed`。
- 发布项引用系统图层时，图层内至少一个图源允许对外发布；不允许发布禁用图层。
- 专用图源必须满足图源完整校验，默认 `visibility.scope=external_only`。
- 发布项覆盖代理策略时，代理出口或代理池必须存在且启用。
- 发布项覆盖缓存策略时，不能绕过统一缓存目录和缓存元数据模型。
- 同一个发布项 Token 重置后，旧 Token 必须立即失效；日志不能保存明文 Token。

### B4. 观测与日志

- 每次瓦片请求记录 `sourceId`、命中状态、耗时、状态码、错误类型、`proxyMode`、`proxyPoolId`、`proxyOutboundId`。
- 图源健康检查记录最近一次成功时间、最近一次失败时间、状态码、错误摘要和样例 URL。
- 代理出口健康检查记录最近一次成功时间、失败时间、耗时、错误摘要和冷却截止时间。
- 代理池诊断展示健康出口数、冷却出口数、最近失败出口和最近一次选择结果。
- 预缓存失败按 sourceId 聚合。
- 对外 API 日志记录 publishId、sourceId、layerId、clientIp、userAgent、状态码、耗时、缓存状态、代理出口、错误摘要和脱敏 URL。
- 管理后台的请求日志可按 publishId、sourceId、layerId、proxyPoolId、proxyOutboundId、状态码、缓存状态筛选。

## 前端需求

### F1. 管理后台体验

- 图源管理是运维工具界面，应保持信息密度和可扫描性。
- 表单编辑复杂配置时使用分组、折叠区和即时校验。
- 删除、禁用、清缓存、重置默认等危险操作必须使用 `src/ui/dialog.js` 的统一弹窗组件。
- 不得在业务代码中直接使用 `alert`、`confirm`、`prompt`。
- 管理后台内置预览地图，图源编辑可以用固定测试点预览单源，图层编辑可以预览组合效果。
- 代理编辑页应提供“测试连接”按钮，图源测试页应显示实际使用的代理池和代理出口。
- 发布/API 页应提供按发布项生成的接入 URL、Token 操作、客户端示例、日志筛选和测试请求。
- 保存图源或图层后，前台目录下次刷新应立即生效；当前前台会话可提供“配置已更新，刷新图层目录”的非阻塞提示。

### F2. 前台 2D 地图

- `src/map/tile-sources.js` 不再维护硬编码图层，只保留把后端 catalog 转换为 Leaflet layer 的纯函数。
- Leaflet 图层创建逻辑按 catalog items 构造 `L.tileLayer` 或 `L.layerGroup`。
- 每个 tileLayer 使用后端 sourceId 瓦片接口，不再向前台暴露完整上游 URL。
- 组合图层按照 items 顺序叠加，并应用 opacity、maxZoom、maxNativeZoom、attribution。

### F3. 前台 3D 地图

- Cesium 图层来源从同一 catalog 转换为 `UrlTemplateImageryProvider`。
- 组合图层切换时按顺序添加 imagery layer，并设置 alpha。
- 2D/3D 的 layerId 保持一致，便于 URL 分享和模式切换。
- 若某图层不支持 3D，3D 图层选择器不展示。

### F4. URL 与本地状态

- URL 使用 `layer=<layerId>`。
- localStorage 使用 `last_map_layer_id`；可以在重构时废弃旧的 `last_map_layer`。
- 后台重命名图层不影响用户分享链接。
- 图层不存在时回退默认图层，并可提示“原图层不可用，已切换到默认图层”。

## 非功能需求

- 配置变更必须持久化，服务重启后不丢失。
- 前台 catalog 接口应轻量，只返回前台必要字段，不返回敏感请求头、代理账号密码或管理备注。
- 瓦片请求路径应避免任意 URL 代理，降低 SSRF 风险。
- 代理账号密码和敏感请求头必须只存储在服务端，任何前台公开接口不得返回。
- 代理失败切换必须有最大尝试次数，避免一个瓦片请求放大成无界重试。
- 代理出口健康检查必须有超时和冷却机制，避免持续请求已知不可用出口。
- 外部专业代理工具接入时，本系统只把它视为一个代理出口，不复制其复杂规则。
- 对外 API 必须支持多个发布项，发布项之间不能共享明文 Token。
- 对外 API 不得维护独立瓦片缓存目录；必须复用图源缓存键和缓存元数据。
- 对外 API 日志写入必须异步，不能阻塞瓦片流响应。
- 图源配置错误不能导致整个地图应用白屏；应局部禁用错误图层并展示可恢复提示。
- 图源测试和健康检查应设置超时，避免阻塞管理后台。
- 缓存写入仍然只允许 2xx 且内容类型符合预期的响应。
- 对组合图层的预缓存和清理操作必须可中断、可重试，并保留失败图源明细。
- 图源、图层、代理出口、代理池、对外发布项 CRUD，URL 模板生成、代理策略、缓存策略、预缓存展开、对外发布鉴权应有自动化测试覆盖。

## 验收标准

- 管理后台导航显示“图源管理”，并能进入图源、图层、代理、发布/API 和诊断视图。
- 首次启动后，后台自动出现现有高德和 Google 图源。
- 首次启动后，前台可选择的图层包含现有 6 个图层，默认图层为“高德/卫星”。
- 首次启动后，后台存在默认代理出口和默认代理池；如果原全局代理未配置，则默认代理出口为禁用待配置状态。
- 管理员可以新增一个 XYZ 图源，测试通过后保存。
- 管理员可以新增两个代理出口，并创建包含它们的代理池。
- 管理员可以将 Google 图源关联到指定代理池，高德图源保持直连。
- 管理员可以创建多个对外发布项，分别发布不同系统图源。
- 管理员可以为某个外部客户创建专用图源发布项，该专用图源不出现在前台图层选择器中。
- 管理员可以用两个图源组合出一个新图层，并在前台 2D 地图中选择显示。
- 同一个新图层在 3D 页面可按配置显示，或在不支持 3D 时不出现在 3D 选择器。
- 修改图源代理模式后，瓦片请求按新策略走指定代理出口、代理池或直连。
- 代理池主出口失败时，在配置允许的最大尝试次数内能切换到备用健康出口，并在日志中记录切换原因。
- 代理出口或代理池被图源引用时，后台阻止直接删除并展示引用它的图源列表。
- 关闭图源缓存后，该图源新瓦片请求显示 `BYPASS` 或等价状态，且不写入服务端缓存。
- 预缓存选择组合图层时，估算结果按图源拆分，并能创建任务。
- 缓存页面可以按图源查看缓存体积和数量，并能清理单个图源缓存。
- 对外 API 可以选择已允许发布的图源或专用图源，不再要求管理员填写独立 upstreamUrl。
- 同一图源同时被前台和对外 API 请求时，共用同一缓存条目，不产生入口维度的重复缓存。
- 对外发布项可以显式覆盖代理池，日志中能看到该发布项实际使用的代理出口。
- 禁用某个发布项后，对应外部 URL 返回 403，其他发布项不受影响。
- 重置发布项 Token 后，旧 Token 立即失效，新 Token 可正常访问。
- URL 分享使用 layerId，重命名图层后旧分享链接仍能恢复同一图层。
- 禁用默认图层时，系统要求先选择新的默认图层。
- 删除被引用图源时，后台阻止删除并展示引用它的图层列表。
- 业务代码中没有新增原生阻塞弹窗调用。
- `npm run check`、`npm test`、`npm run build` 通过。

## 风险与对策

| 风险 | 对策 |
| --- | --- |
| 任意 URL 代理导致 SSRF | 前台瓦片请求改用 sourceId；用户图源默认直连；服务端代理只允许系统图源和白名单域名 |
| 代理出口被误配置为内网探测通道 | 代理出口、图源上游模板分别校验；用户图源使用代理必须命中白名单；敏感地址默认禁止 |
| 代理失败切换造成请求放大 | 设置单请求最大切换次数、出口冷却时间和超时；日志记录每次切换 |
| 系统被过度设计成专业代理平台 | 文档明确只做出口目录、代理池、基础轮询和失败切换；复杂路由交给外部代理工具 |
| 对外 API 继续形成独立分叉 | 发布项只保存准入和覆盖策略，实际请求强制委托统一图源服务 |
| 多发布项导致重复缓存 | 缓存键以 sourceId 和瓦片参数为主，publishId 仅作为元数据和筛选维度 |
| 发布项 Token 泄露 | Token 只显示一次，持久化哈希和预览片段，日志必须脱敏 |
| 图源配置错误导致地图不可用 | 保存前测试 URL；前台 catalog 过滤无效图源；默认图层不可禁用 |
| 组合图层预缓存体积超预期 | 估算按图源拆分展示；超阈值只警告或二次确认；任务可暂停和删除缓存 |
| 2D/3D 能力不一致 | 图层模型显式声明 clients；同一 layerId 只在支持客户端展示 |
| 缓存和代理策略分散 | 缓存和代理策略默认从图源读取，外部 API、预缓存和前台瓦片统一调用同一服务方法；发布项覆盖必须显式记录 |
| 服务商密钥泄露 | 敏感请求头和 token 只保存在服务端；前台 catalog 不返回敏感字段 |
