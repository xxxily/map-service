# KML 文件级视口按需加载与调度

状态：已完成（v1，代码已接入，发布前验证中）  
适用版本：map-service 1.5.56 及以后  
最后更新：2026-08-31

## 1. 背景

当前 KML 优化只在“详情已经加载后”过滤要素。账号 KML、个人分享 KML 和公共 KML 的文件详情在首屏会被一次性放入同一批请求；当文件数量达到数十或数百个时，会产生大量并发网络请求、JSON 解析、要素索引和地图图层创建。缩放或平移后，视口外文件仍可能继续参与渲染。

本需求把优化边界前移到“文件详情请求”层，同时保留现有要素级视口过滤和点位聚合。任何优化都不能以静默丢失文件或要素为代价。

## 2. 目标

1. 个人账号 KML、匿名用户本地 KML、公开分享 KML、管理员公共 KML 均使用统一的文件级候选与渲染策略。
2. 新建、导入、更新或发布 KML 时生成可校验的 WGS84 文件边界摘要。
3. 有摘要的文件只在视口或缓冲区内进入详情加载队列；没有摘要的旧文件走兼容队列，但仍受统一并发控制。
4. 文件按“视口内优先、缓冲区内次之、距离视口中心由近到远”加载；请求之间有小间隔，避免同一时刻启动大批任务。
5. 低缩放级别、视口无效或边界摘要无法判断时，最终加载所有启用文件，但以受控队列分批完成。
6. 地图旋转时按屏幕四角形成的地图 footprint 计算候选，并额外保留缓冲区，避免边缘拖动或旋转后出现空白。
7. 同一文件请求去重；视口变化后淘汰尚未开始的过期队列项，已开始的请求允许完成但不得覆盖新会话或错误地图实例。
8. 文件详情加载失败时保留文件摘要、文件名、错误原因和可重试状态，不能把失败误报为空文件。

## 3. 非目标

- 本期不卸载已获取的详情数据，不引入基于内存上限的二次缓存回收；视口外只移除渲染图层。
- 本期不改变 KML 内容格式、坐标纠偏语义、分享权限或配额计算规则。
- 本期不通过固定数量窗口截断文件、要素、媒体或管理列表。
- 不关闭 Leaflet/Cesium 的缩放动画，也不通过禁用 3D 渲染来换取性能。

## 4. 数据摘要契约

### 4.1 字段

个人 KML API、分享 manifest/详情和管理员公共 KML 列表可返回 `bounds`：

```json
{
  "version": 1,
  "status": "ready",
  "bbox": [113.1, 22.1, 113.8, 23.0],
  "crossesAntimeridian": false,
  "featureCount": 123
}
```

- `bbox` 顺序固定为 `[west, south, east, north]`，经纬度为 WGS84 十进制度。
- `bounds` 始终按 WGS84 持久化；客户端进行文件级视口筛选、渲染显隐和摘要定位时，必须按文件的 `coordCorrection` 计算显示坐标边界，再与地图视口比较，不得直接将 WGS84 摘要与 GCJ-02 视口混用。
- `status` 取 `ready`、`empty`、`missing`。`ready` 必须有合法 bbox；`empty` 表示没有有效坐标；`missing` 仅用于兼容旧记录或计算失败。
- `crossesAntimeridian=true` 时允许 `west > east`，表示区间跨越 ±180 度；不得把该区间展开为全球范围。
- `featureCount` 是摘要生成时的要素数量，仅用于诊断，不替代文件列表中的计数。
- 未提供字段或字段校验失败时，客户端按 `missing` 处理，不阻断详情加载。

### 4.2 生成与存储

- 统一遍历 Point、LineString、Polygon、MultiGeometry/嵌套坐标数组，忽略非法坐标。
- 经度使用最小覆盖圆弧算法，正确表示跨日界线文件；纬度限制在 [-90, 90]。
- 账号数据库在 `kml_documents.bounds_json` 保存 JSON 摘要；数据库迁移不得删除既有数据。旧行允许为空，后续更新时自动补齐。
- 管理员公共 KML 的 JSON 文档直接保存 `bounds`；读取旧 JSON 时按缺失兼容。
- 分享发布快照必须复制源文件当时的 `bounds`，不能在公开读取时依赖源文件当前内容。
- 客户端本地 KML 在加载/保存时计算摘要；账号详情摘要由服务端权威返回，客户端不接受用户提交的 bounds 作为写入依据。

## 5. 文件加载生命周期

### 5.1 摘要阶段

1. 先请求文件列表或分享 manifest，只取得文件元数据、计数、状态、边界和可见性。
2. `contentLoaded=false` 的文件不创建要素图层；面板仍显示文件名、计数和“详情待加载”状态。
3. 已在内存中的本地文件视为详情已加载，但仍按摘要决定是否渲染。

### 5.2 候选判定

对每次视口更新构造三个集合：

- `inside`：摘要 bbox 与实际视口 footprint 相交；
- `buffer`：摘要 bbox 与 footprint 扩大后的缓冲区相交；
- `fallback`：无摘要、摘要缺失/非法或视口不可用的文件。

有摘要且完全在缓冲区外的文件暂不请求。低缩放全量模式（默认 `zoom <= 4`，3D 使用等效缩放）把所有启用文件加入队列，仍按距离排序和并发限制执行。

### 5.3 优先级与排序

优先级从高到低：

1. 用户明确操作的文件（展开、显示、定位、导出）；
2. `inside` 文件；
3. `buffer` 文件；
4. 无摘要兼容文件；
5. 低缩放全量模式中的其余文件。

同一优先级按文件 bbox 中心到视口中心的球面近似距离排序，再按目录位置和稳定 ID 排序。排序只影响开始顺序，不影响最终完整性。

### 5.4 并发、延迟、取消和重试

- 默认详情并发上限为 3（单个调度器实例可配置，硬上限 6）。
- 默认相邻请求启动间隔为 40ms；用户明确操作可跳过首个间隔但不能突破并发上限。
- 每次视口更新生成递增 `generation`。队列中旧 generation 项在启动前丢弃；正在执行的请求完成后仅在文件仍属于当前实例时合并结果。
- 同一文件通过 ID 去重，账号详情和分享详情分别复用现有 in-flight 去重。
- 网络失败保留 `loadError`，在当前 generation 下最多自动重试 1 次；再次失败等待用户明确操作或下一次候选更新。
- 地图销毁、账号切换、分享切换时停止调度并清理定时器；不得把旧响应写入新账号/新分享。

## 6. 渲染策略

1. 详情已加载且文件启用时，只有与当前缓冲 footprint 相交的有摘要文件创建图层；无摘要文件保持兼容渲染。
2. 视口变化时移除视口外图层，但保留文件详情内存缓存，重新进入时不重复请求。
3. 现有要素级过滤和全局/分享点位聚合继续生效，聚合只接收当前缓冲 footprint 内已经加载的 Point。
4. 线、面文件按文件 bbox 参与候选，不能因为点位过滤阈值而漏掉线面。
5. 文件详情尚未加载时，面板的展开、显示、定位、导出等明确操作必须调用同一调度器的高优先级请求，并在失败时显示文件名和错误原因。

## 7. 2D 旋转 footprint

- 旋转地图使用地图容器四角的屏幕坐标，以地图中心和 bearing 反投影到经纬度，再取四角轴对齐包围盒；这比直接使用未旋转的 `map.getBounds()` 更保守且兼容 Leaflet Rotate。
- footprint 先按默认比例 1.8 扩大；若容器尺寸或投影不可用，退回 `map.getBounds()` 并进入兼容候选模式。
- 监听 `moveend`、`zoomend`、`rotate`、`resize`，统一 debounce 后更新调度器。

## 8. 3D footprint

- 优先使用 Cesium `camera.computeViewRectangle`，该矩形已经包含 heading/pitch/roll 影响；再按比例扩大。
- 相机矩形不可用时，根据相机高度和纬度估算保守范围，并把所有无摘要文件加入兼容队列。
- 监听 `camera.moveEnd` 和视图尺寸变化；相机高度转换为等效 zoom 用于低缩放全量阈值和排序。

## 9. API 影响

本期不新增详情 URL，扩展现有响应字段：

- `GET /api/v1/kml/files` 列表项增加 `bounds`（不返回 `features`）；
- `GET /api/v1/kml/files/:id` 详情增加 `bounds`；
- `GET /api/v1/public/kml-shares/:publicId` 的 `items[]` 增加 `bounds`；
- `GET /api/v1/public/kml-shares/:publicId/files/:shareItemId` 增加 `bounds`；
- `GET /api/v1/kml/shared` 列表项增加 `bounds`，详情保持兼容并增加 `bounds`。

所有字段均为可选兼容字段；客户端不能因缺失而拒绝整份列表。接口错误继续使用 `jsonErr`，详情失败必须保留原始错误码和中文消息。

## 10. 可观测性

客户端调度器记录以下开发诊断字段（不包含 KML 内容）：

- generation、候选总数、inside/buffer/fallback 数量；
- queue wait、active、completed、failed、retried 数量；
- 每次详情请求的文件 ID、耗时和结果码。

生产日志不得记录坐标全文、Token、密码或媒体请求头。必要时只记录脱敏 ID 和计数。

## 11. 测试与验收

### 11.1 单元测试

- 边界摘要生成：点、线、面、嵌套坐标、空文件、非法坐标、跨日界线。
- bbox 校验、视口/缓冲区相交、经度环绕和中心距离排序。
- 调度器：并发上限、启动间隔、请求去重、generation 淘汰、重试和销毁。
- 旧文件缺失 bounds 时仍进入 fallback 队列。

### 11.2 后端集成测试

- 数据库 v11 -> v12 迁移保留数据并新增字段。
- 创建/更新/导入返回正确 bounds；客户端提交伪造 bounds 不改变服务端计算结果。
- 分享发布快照和 manifest/详情携带发布时 bounds。
- 管理员公共 KML 新建、更新、旧 JSON 读取兼容。

### 11.3 浏览器/回归测试

- 个人账号 100 个文件首屏只请求视口候选，网络并发不超过 3；平移到远处后按中心到边缘补齐。
- 匿名本地 100 个文件不产生网络详情请求，视口外不创建图层，重新进入视口不丢数据。
- 分享链接和管理员公共 KML 采用同样的候选、聚合与显隐行为。
- 旋转 0/45/90 度、连续滚轮缩放、快速跨级缩放、慢网速下无白屏和明显空洞；缓冲区内文件提前加载。
- 缩放到低级别后最终所有启用文件均完成或明确显示失败；不得静默少文件。

### 11.4 性能验收指标

- 首屏详情请求启动峰值不超过并发上限；请求启动间隔的 p95 不小于配置下限（测试桩环境）。
- 视口外有摘要文件不创建其要素图层；已加载文件再次进入视口不重复请求。
- 现有 `npm run check`、`npm test`、`npm run build` 和 `git diff --check` 全部通过。

## 12. 灰度与回滚

- 先发布后端摘要字段（可选字段，旧前端安全忽略），再发布前端调度器。
- 前端若检测到调度器初始化异常，自动退回现有并发详情加载路径，不阻断地图使用。
- 数据库迁移只添加 nullable `bounds_json`，回滚代码不会丢失原始 `features_json`；回滚版本可忽略该字段。
- 上线后观察详情请求峰值、失败率、首屏可见文件完成时间和低缩放全量完成率。
