# 分享、AI 审核、用户资料与留言体验优化需求

> 状态：已实施，待 161 内测验收  
> 版本：v1.0  
> 日期：2026-08-28  
> 计划版本：v1.5.51  
> 适用范围：个人空间、KML 分享创建与管理、公开分享留言、管理后台、Interaction Service

## 1. 背景

现有 KML 分享、AI 审核、用户体系和留言能力已经形成基本闭环，但仍存在以下体验和治理问题：

- 分享 URL 在弹窗中按普通文本渲染，长地址无法换行并可能溢出弹窗。
- 新建分享的聚合与空间范围默认值偏保守，需要用户重复调整才能获得适合大规模 KML 的表现。
- 管理后台只能返回地图，管理员进入个人空间需要多一次中转。
- AI provider 要求管理员理解环境变量引用，提示词只管理版本和摘要，日常维护门槛过高。
- AI 运行配置和用户体系设置按长页面平铺，查找成本高。
- 账号页成功提示位于内容顶部，长列表滚动后不可见。
- 用户只能维护展示名和邮箱，留言无法完整呈现用户头像与身份信息。
- 匿名留言资料不会稳定复用，登录态切换后的身份优先级也缺少明确契约。
- 后台留言详情缺少作者身份、分享、KML 和点位的直观上下文。

本次优化在现有权限、审计、分享快照和 Interaction Service 边界上增量实现，不另建平行账号或留言体系。

## 2. 目标

1. 长分享 URL 在任何常见移动端和桌面宽度内完整可读、可选、可复制。
2. 新建分享默认启用适合大规模点位的聚合与空间保护；历史分享保持原配置。
3. 管理后台、地图和个人空间之间形成直接、可预测的导航闭环。
4. 管理员可直接配置 AI API Key 和默认提示词正文，同时不降低密钥安全、SSRF 防护和审计质量。
5. AI 设置与用户体系设置使用 Tab 分类，降低长页面扫描成本。
6. 全局操作结果统一使用右下角 Toast，滚动位置不影响反馈可见性。
7. 用户可维护昵称、头像和性别；留言使用提交时身份快照稳定展示。
8. 匿名身份资料可在当前浏览器记忆和修改；登录后必须使用账号资料覆盖匿名身份。
9. 后台留言详情能直接识别作者、分享、KML、点位和审核状态。

## 3. 非目标

- 不新增第三方头像代理、任意 URL 抓取或远程图片转存能力。
- 不公开用户邮箱、手机、内部用户 ID、IP、UA、密钥或审核内部原文。
- 不把性别设为必填，也不以性别影响审核或权限。
- 不自动迁移或改写已经存在的分享配置。
- 不改变留言审核状态机、人工审核最终权威或举报处理边界。
- 不在本版本发布到 66 或正式环境；先仅部署 161 内测。

## 4. 分享链接弹窗

### 4.1 展示规则

- 创建分享成功后使用统一 Dialog 展示完整绝对 URL。
- 剪贴板 API 不可用或复制失败时，使用同一 Dialog 展示待复制内容。
- URL 容器必须使用 `overflow-wrap: anywhere`、`word-break: break-word` 和正常换行，不能产生横向溢出。
- URL 内容可通过键盘和触摸选择；弹窗提供明确的“复制链接”按钮。
- 复制成功后关闭弹窗并显示右下角成功 Toast；失败时保持 URL 可选择并给出错误 Toast。
- 弹窗支持 Escape、焦点圈定、关闭后焦点恢复和移动端安全边距。

### 4.2 默认值

仅创建新分享时使用以下默认值；编辑已有分享时按服务端现值回显，不静默覆盖：

| 配置 | 新建默认值 |
| --- | --- |
| 点位聚合 | 开启 |
| 单网格最少聚合点数 `minClusterPoints` | `5` |
| 地图空间范围 `spatialAccess.mode` | `kml_bounds` |
| 范围外底图放宽最大缩放级别 `unrestrictedTileMaxZoom` | `12` |
| 地图模式 | `2d`（空间受限分享既有约束） |

若管理员设置的 `spatialUnrestrictedTileMaxZoom` 小于 `12`，前端默认值取管理员上限；服务端仍是最终校验方。范围无法计算时不得自动退回不受限模式，用户需调整 KML 选择或主动选择其他模式。

## 5. 导航与通知

### 5.1 管理后台导航

- 管理后台顶栏增加“个人空间”入口，直接进入账号页。
- 入口使用稳定路径，不依赖显示名称；保留返回地图、刷新和退出。
- 图标按钮必须有 `aria-label` 和 `title`，键盘可访问。

### 5.2 统一 Toast

- 管理后台和个人空间通过既有 `setNotice` / `setMessage` 状态契约渲染固定右下角 Toast。
- Toast 不属于页面内容流，不随页面滚动离开视口。
- 成功、错误、处理中状态应可区分；错误使用 `role="alert"`，其他使用 `role="status"` 和 `aria-live="polite"`。
- 非处理中 Toast 可关闭；移动端使用左右安全边距并避免覆盖底部关键按钮。
- 需要用户确认、输入或阅读长内容的场景继续使用 Dialog，不能用 Toast 替代。

## 6. AI Provider 与提示词

### 6.1 API Key 输入与存储

- 管理员可直接输入 `apiKey`，不要求理解或创建环境变量引用。
- 新 provider 必须提供可用密钥；编辑时留空表示保持原密钥。
- 服务端使用部署级加密密钥通过带认证加密方式保存 API Key；数据库不得保存明文。
- API 列表和详情只返回 `hasApiKey`、`configured`、`verifiedAt`、`health` 等摘要，不返回密钥明文或密文。
- 修改 endpoint、model、adapter 或 API Key 后，provider 立即回到未验证/不可运行状态，需重新执行健康验证。
- 旧 `secretRef` 配置保持兼容，可继续解析已有环境变量引用；新界面不再要求新增引用。
- 密钥不得进入审计详情、错误信息、日志、测试快照、Outline 或发布记录。

### 6.2 安全边界

- endpoint 继续要求 HTTPS、命中 allowlist，并通过现有 SSRF/内网地址拒绝逻辑。
- 健康验证只发送固定探针，不发送真实留言。
- 调用继续受超时、尝试次数、并发、预算和日志脱敏限制。
- 缺少加密主密钥时，直接保存 API Key 必须失败并返回不泄露实现细节的中文错误；已有环境变量引用仍可工作。

### 6.3 默认提示词

- 后台直接展示当前有效提示词正文，首次部署使用仓库内置的中文审核提示词。
- 管理员可在文本域微调并发布；服务端根据规范化正文生成内容摘要和稳定版本号，客户端不手填 SHA-256。
- AI 审核任务引用发布时的 `promptVersion` 和对应正文，历史决策保留当时版本号。
- 只有具备 `admin.moderation.ai.manage` 的管理配置接口可读取正文；普通列表、审核决策、审计和日志不返回正文。
- 提示词必须明确输出结构、审核等级、风险边界和 `unknown` 回退规则，不允许通过提示词绕过服务端动作白名单。

## 7. 后台 Tab 信息架构

### 7.1 AI 审核与规则

使用同一页面内的可访问 Tab，建议分类：

1. 运行配置
2. Provider
3. 提示词
4. 关键词规则
5. 外部镜像（仅配置或有权限时显示）

Tab 使用 `role="tablist"` / `role="tab"` / `role="tabpanel"`，支持键盘焦点；切换不丢失已加载状态，保存后保持当前 Tab。

### 7.2 用户体系设置

按以下能力分类：

1. 注册与会话
2. KML 与配额
3. 分享与空间
4. 访问统计与限流

各字段、权限、校验和提交接口保持现有契约；Tab 只改善信息组织，不改变设置含义。

## 8. 用户资料

### 8.1 字段

`GET/PUT /api/v1/users/me` 扩展以下字段：

| 字段 | 规则 |
| --- | --- |
| `displayName` | 昵称/展示名，1～50 字符 |
| `email` | 现有可选邮箱规则 |
| `avatar` | 可选受控图片 Data URL，仅允许 PNG、JPEG、WebP；客户端文件最大 140 KiB，服务端编码后字符串最大 200000 字符 |
| `gender` | 空值、`male`、`female`、`other`、`unknown`，默认空值；服务端兼容 `unknown` |

- 禁止保存任意远程头像 URL，避免公开留言页面向第三方发起跟踪请求。
- 前端支持选择本地图片、预览和清除；服务端独立验证 MIME、Base64 和大小。非法选择或读取失败时恢复本次表单打开时的最后有效头像，不会误提交旧的未保存值。
- 会话摘要可返回当前用户的公开资料字段，不能返回其他敏感字段。

### 8.2 留言身份快照

- 登录用户提交留言时，服务端忽略客户端伪造的登录身份字段，读取当前账号资料。
- 留言写入 `displayName`、`avatar` 和 `gender` 快照；用户后续修改资料不改变历史留言。
- 公开留言默认展示昵称和头像；性别不作为公开列表的强调信息。
- 后台详情可展示性别等审核所需的非敏感快照，但不能返回邮箱、手机、内部作者键等敏感字段。
- 历史留言缺少头像或性别时使用默认头像和“未设置”，不得阻断读取。

## 9. 匿名留言资料记忆

- 匿名资料使用独立的版本化 `localStorage` 键，只存当前浏览器需要复用的公开昵称、头像、性别和表单联系方式。
- 首次打开匿名留言表单时加载缓存；用户仍可修改，成功提交后更新缓存。
- 缓存读取需 normalize，字段非法、超长或存储不可用时安全忽略。
- 登录态存在时，界面和提交体优先使用服务器账号资料，不复用或提交匿名身份缓存。
- 从登录态退出后可重新加载匿名缓存；登录和匿名数据不得互相覆盖。
- “记住”仅是本地表单便利功能，不代表账号、已验证身份或跨设备同步。

## 10. 留言展示与后台详情

### 10.1 公开留言

- 留言列表显示头像、昵称、时间和正文；头像缺失时使用昵称首字或默认标记。
- 回复和顶层留言使用同一身份投影。
- 所有文本继续经过转义/安全 Markdown 流程，头像只使用服务端已验证的受控值。

### 10.2 后台详情

留言详情使用结构化 Dialog，至少包含：

- 作者类型、昵称、头像、性别和是否注册用户。
- 留言正文、提交时间、审核状态、内容状态和决策摘要。
- 分享标题、公开 ID 或稳定分享 ID。
- KML 显示名称和 `shareItemId`。
- 点位名称和 `featureId`。

列表中的资源列优先显示人类可读名称，稳定 ID 作为次级信息。详情数据优先使用留言提交时的资源快照，资源后续删除或改名时仍能定位历史上下文。

## 11. API 与数据迁移

- 用户数据库新增资料字段时使用向前兼容迁移，旧记录自动采用空头像和 `unspecified`。
- Interaction 数据库新增身份快照字段时同样兼容旧留言。
- Provider 密钥密文和提示词正文必须使用新的明确字段或配置记录，不复用可能公开返回的 JSON。
- 所有新增/修改接口继续使用 `jsonSuc` / `jsonErr`，错误消息为中文且不泄露密钥、SQL 或文件路径。
- 接口字段和示例同步更新 `docs/api.md` 与 `docs/api-user-system.md`。

## 12. 测试与验收

### 12.1 自动化测试

- 分享创建默认值为聚合开启、最少 5 点、`kml_bounds`、放宽级别 12；编辑旧分享不被覆盖。
- 超长 URL Dialog 不溢出，存在复制动作和可访问语义。
- 管理后台存在个人空间入口；账号/后台 Toast 固定右下角。
- Provider API Key 加密保存、响应脱敏、旧 `secretRef` 兼容、变更后需重新验证。
- 默认提示词可读取、编辑、版本化；日志和普通审计不含正文与密钥。
- AI 和用户体系页存在正确 Tab、tabpanel 和状态保持。
- 用户资料字段校验、头像大小/MIME 拒绝和响应脱敏。
- 登录留言使用账号资料快照；匿名留言使用合法客户端资料；公开列表和后台详情返回安全投影。
- 匿名缓存加载、修改、成功提交后保存，以及登录态优先级。
- 留言详情包含分享、KML 和点位的人类可读定位信息。

### 12.2 工程校验

提交前必须完成：

```bash
npm run check
npm test
npm run build
git diff --check
```

并在桌面及 320/375/390px 视口验证 URL 弹窗、Toast、Tab、资料表单、匿名留言和留言详情无横向溢出或遮挡。

## 13. 发布与回滚

- 版本发布为新的补丁版本，优先部署到 161。
- 发布前备份 161 代码、`.env`、SQLite 一致性快照、容器和镜像信息。
- 发布后验证登录、个人资料、创建/复制分享、公开留言、后台审核、AI 配置读取与健康验证入口。
- 发现数据迁移、登录、分享或留言主流程异常时立即停止推广，通过部署备份回滚；不发布到 66。
