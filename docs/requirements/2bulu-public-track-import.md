# 两步路公开分享轨迹导入需求

> 状态：服务端直连兼容方案；网站入口由[两步路授权浏览器助手与浏览器内导入](./2bulu-authorized-browser-helper.md)替代  
> 更新时间：2026-08-07  
> 关联文档：[用户体系、角色权限、个人空间与多 KML 分享需求](./user-system-rbac-and-multi-kml-sharing.md)、[KML 导入导出](./kml-import-export.md)

> 2026-08-07 实测确认两步路 SafeLine WAF 会拒绝 map-service 服务端读取公开分享页及相关接口。本文保留 URL、服务端安全适配器和未来官方 API provider 的历史设计；当前网站不再直接调用 `/api/v1/kml/import/2bulu`，用户入口和实际流程以浏览器助手需求为准。

> 第二版实现补充：当用户已在可见两步路页面完成登录/验证且页面正常展示轨迹时，Chrome 助手会在浏览器内读取页面实际使用的固定轨迹/标注数据并生成标准 KML；这不是服务端直连能力，也不复制或上传两步路凭据。

## 1. 背景

当前个人 KML 只支持用户先取得本地 `.kml` 文件，再通过“我的 KML”或地图页 KML 数据管理面板上传。对于两步路公开分享轨迹，用户通常需要经历：

1. 打开两步路分享页；
2. 登录两步路并完成其验证码；
3. 在 App 或网页中导出 KML；
4. 将文件传到当前设备；
5. 再上传到本系统。

该流程在移动端和 PC 端均存在明显断点。本需求希望允许已登录且具备个人 KML 写权限的用户粘贴两步路公开分享链接，由服务端在安全边界内读取公开轨迹，并创建为用户自己的 KML。

示例链接：

```text
https://www.2bulu.com/track/t-OavTTmw9VMzp%252FR2KBg5Tzw%253D%253D.htm
```

## 2. 可行性评估

### 2.1 调研结论

截至 2026-08-07，两步路没有可确认的、面向第三方公开承诺稳定性的轨迹导入 API。现网链路具有以下特征：

- 分享页和动态接口可能受 SafeLine WAF 限制，服务端普通 HTTP 客户端可能收到 `468` 或人机校验页面。
- 网页“本地下载”会检查两步路登录态，并要求完成阿里云验证码。
- 当前网页轨迹坐标和标注点接口使用前端签名及加密响应；不得通过复制私有算法、绕过验证码或模拟用户登录来构建生产能力。
- 历史公开页面曾提供无需登录的轨迹坐标 JSON 链路，但该链路没有稳定性承诺，且可能只能得到轨迹线，不能完整还原标注点、媒体和原始 KML 样式。

因此，本需求属于“条件可行”：

- 可以实现严格受控的两步路适配器、登录权限、链接校验、公开数据读取、KML 校验、配额校验和两个产品入口。
- 只能使用无需两步路账号、Cookie、验证码和私有解密的公开响应。
- 当上游要求登录、验证码、返回 WAF 页面、加密响应或接口变更时，系统必须明确提示暂时无法自动导入，不能伪装成功，也不能静默导入残缺数据。
- 若后续获得两步路官方 API、授权合作接口或稳定公开下载协议，可在不改变前端主流程的前提下替换适配器。

### 2.2 第一阶段支持矩阵

| 上游能力 | 第一阶段处理 |
| --- | --- |
| 分享页或官方响应直接提供标准 KML | 完整导入 |
| 历史公开轨迹接口返回明文坐标和标注点 | 转换为 KML 点、线要素后导入 |
| 只能取得轨迹线，无法取得标注点或媒体 | 默认拒绝；用户显式选择“允许仅导入轨迹线”后可导入，并返回醒目警告 |
| 要求两步路登录或验证码 | 拒绝并提示用户改用本地 KML 导入 |
| WAF、人机校验、签名或加密响应 | 拒绝并提示上游暂不可读取 |
| 私密、已删除、失效或不存在的分享 | 拒绝，不创建空 KML |
| KMZ、GPX 或其他格式 | 第一阶段不支持；不得把非 KML 内容按 KML 保存 |

## 3. 目标与非目标

### 3.1 目标

- 登录用户可从“我的 KML”粘贴两步路公开分享链接导入。
- 登录用户可从 2D 地图页 KML 数据管理面板执行同一导入流程。
- 导入结果进入当前账号个人 KML，复用现有归属、配额、同步、分享、回收站和导出能力。
- 未登录用户、只读用户看不到入口，直接调用接口仍会被服务端拒绝。
- 对外部请求实施固定域名、固定路径、DNS 重绑定防护、超时、响应大小、重定向和内容校验。
- 导入失败可解释，且不泄露上游响应正文、Cookie、内部地址或服务端网络细节。

### 3.2 非目标

- 不代替用户登录两步路。
- 不保存或转发用户的两步路账号、密码、Cookie、Token、验证码或设备标识。
- 不绕过 WAF、人机验证、访问频率限制、签名或加密保护。
- 不提供任意 URL 下载、代理或网页抓取能力。
- 不支持批量爬取、定时同步、自动追踪两步路后续更新。
- 第一阶段不保证还原两步路私有样式、海拔曲线、运动统计、评论、点赞、作者私有信息和未公开媒体。
- 第一阶段不扩展到 3D 页面入口；导入后的个人 KML 仍可按现有账号同步在 3D 页面查看。

## 4. 用户与权限

| 用户状态 | 是否显示入口 | 服务端结果 |
| --- | --- | --- |
| 未登录访客 | 隐藏 | `401 AUTH_REQUIRED` |
| 已登录但只有 `kml.own.read` | 隐藏 | `403 PERMISSION_DENIED` |
| 具备 `kml.own.write` | 显示 | 可发起导入 |
| 管理员/超级管理员且具备个人 KML 写权限 | 显示 | 作为其个人 KML 导入，不自动创建公共 KML |

权限判断必须复用现有 `kml.own.write`，不新增含义重叠的权限。

## 5. 用户流程

### 5.1 “我的 KML”入口

1. 用户进入账号中心“我的 KML”。
2. 点击“从两步路导入”。
3. 弹窗填写：
   - 两步路公开分享链接；
   - 坐标纠偏模式，默认 `wgs84-to-gcj02`；
   - 数据不完整策略，默认“必须完整”，可显式选择“允许仅导入轨迹线”。
4. 页面显示“正在读取两步路公开轨迹并导入”。
5. 成功后刷新列表，显示新 KML 的名称、要素数和更新时间。
6. 若只导入轨迹线，成功信息必须同时显示数据不完整警告。

### 5.2 地图页入口

1. 登录用户打开 KML 数据管理面板。
2. 在本地文件导入区下方点击“从两步路公开链接导入”。
3. 填写与账号中心一致的选项。
4. 成功后新 KML 加入个人图层列表、默认展开，并将地图缩放到导入要素范围。
5. 新文档应登记为现有账号同步快照，不得被客户端同步逻辑再次创建成重复副本。

### 5.3 降级流程

当上游要求登录、验证码或无法读取时，提示：

```text
两步路当前不允许服务器直接读取该轨迹。系统不会代替你绕过登录或验证码，请先在两步路导出 KML，再使用“导入 KML”上传。
```

失败时不得创建空文件、半成品文件或保留不可见后台任务。

## 6. 支持的 URL

第一阶段只接受 HTTPS，且主机必须是：

- `www.2bulu.com`
- `2bulu.com`
- `app.2bulu.com`

支持以下稳定页面形态：

```text
/track/t-<稳定分享标识>.htm
/track/track_detail.htm?trackId=<稳定分享标识>
/share/share_track.htm?trackId=<稳定分享标识>
```

规则：

- 允许分享标识中出现 URL 编码的 `+`、`/`、`=`，最多执行两次规范化解码。
- 去除 fragment 和 `jsessionid`，不继承用户提供的额外查询参数。
- 分享标识长度为 1～160，只允许 ASCII 字母、数字、`+`、`/`、`=`、`_`、`-`。
- 不接受 IP 地址、非标准端口、账号密码、协议相对 URL、短链跳转域名或任意子域名。
- URL 中的显示标题不能作为数据库主键；只使用系统生成的 KML ID。

## 7. API 契约

### 7.1 导入两步路公开轨迹

```http
POST /api/v1/kml/import/2bulu
Content-Type: application/json
```

鉴权：用户会话 + CSRF + `kml.own.write`。

请求：

```json
{
  "url": "https://www.2bulu.com/track/t-xxx.htm",
  "coordCorrection": "wgs84-to-gcj02",
  "partialPolicy": "reject",
  "requestId": "2bulu-6c2d6a2d-2fc5-4e55-a193-d93c6ef10bf5"
}
```

字段：

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| `url` | 是 | 1～2048 位，必须符合第 6 节 |
| `coordCorrection` | 否 | `wgs84-to-gcj02` 或 `none`，默认前者 |
| `partialPolicy` | 否 | `reject` 或 `allow-track-only`，默认 `reject` |
| `requestId` | 否 | 1～120 位 ASCII 稳定请求 ID，用于相同请求安全重试 |

成功：

```json
{
  "code": 0,
  "result": {
    "id": "kml_xxx",
    "name": "两步路公开轨迹",
    "featureCount": 3,
    "revision": 1,
    "sourceType": "imported",
    "features": [],
    "importSummary": {
      "provider": "2bulu",
      "sourceUrl": "https://www.2bulu.com/track/t-xxx.htm",
      "completeness": "full",
      "warnings": []
    }
  }
}
```

`completeness`：

- `full`：取得并通过校验的标准 KML，或公开数据包含轨迹线及公开标注点。
- `track-only`：只取得轨迹坐标；仅在 `partialPolicy=allow-track-only` 时允许创建。
- `existing`：相同 `requestId` 的成功请求幂等重放；本次直接返回已创建文档，不重新读取上游。

### 7.2 错误码

| HTTP | code | 说明 |
| --- | --- | --- |
| 400 | `TWO_BULU_URL_INVALID` | URL、主机、路径或分享标识不合法 |
| 401 | `AUTH_REQUIRED` | 未登录 |
| 403 | `PERMISSION_DENIED` | 无个人 KML 写权限 |
| 409 | `TWO_BULU_IMPORT_IN_PROGRESS` | 同一用户已有导入在执行 |
| 413 | `FILE_TOO_LARGE` | 上游响应或生成数据超过限制 |
| 422 | `TWO_BULU_PARTIAL_REJECTED` | 只能取得轨迹线且用户未允许部分导入 |
| 422 | `TWO_BULU_LOGIN_REQUIRED` | 上游要求登录或验证码 |
| 422 | `TWO_BULU_TRACK_EMPTY` | 未找到有效点、线或面 |
| 429 | `TWO_BULU_RATE_LIMITED` | 用户触发导入过于频繁 |
| 502 | `TWO_BULU_UPSTREAM_BLOCKED` | WAF、人机验证、加密响应或拒绝访问 |
| 502 | `TWO_BULU_UPSTREAM_INVALID` | 上游返回 HTML、非法 JSON、非法 KML 或意外内容 |
| 504 | `TWO_BULU_TIMEOUT` | 上游读取超时 |

错误响应只返回中文摘要和稳定错误码，不返回上游响应全文、Cookie、内部 IP、堆栈或下载签名。

## 8. 服务端处理流程

1. 鉴权并检查 `kml.own.write`。
2. 校验请求体、用户级限流和单用户并发锁。
3. 规范化两步路分享 URL 和稳定分享标识。
4. 通过公共 DNS 解析校验和 DNS pinning 发起请求。
5. 按顺序尝试：
   - 分享页直接返回或明确暴露的标准 KML；
   - 无需登录、验证码、签名或私有解密的两步路公开轨迹数据。
6. 校验响应状态、内容类型、字节数和内容特征。
7. 标准 KML 复用现有 `parseKmlText`；公开坐标数据转换为 Point/LineString。
8. 判断完整度；部分数据按 `partialPolicy` 决定拒绝或继续。
9. 复用现有个人 KML normalize、sanitize、配额和持久化逻辑创建文档。
10. 写入审计摘要并返回文档及导入摘要。

## 9. 安全与稳定性

### 9.1 SSRF

- 输入主机和每次重定向目标都必须重新校验。
- 阻断 localhost、内网、link-local、metadata、保留地址、IPv4-mapped IPv6 和 DNS 重绑定。
- 分享页只允许第 6 节主机；文件目标仅允许经过代码固定的两步路下载主机。
- 最多 2 次重定向，禁止协议降级到 HTTP。
- 不允许调用方传请求头、代理、Cookie、认证信息或目标下载 URL。

### 9.2 内容安全

- 分享页最大 2 MB，轨迹/KML 响应最大 10 MB，超限立即中止。
- 单次上游请求超时 8 秒，总流程不超过 20 秒。
- 拒绝 HTML 错误页、SafeLine 页面、登录页、验证码页、ZIP/KMZ 和未知二进制。
- KML 继续拒绝 `DOCTYPE`、`ENTITY`、外部实体和危险富文本。
- 坐标必须为有限数值，且经度 `-180～180`、纬度 `-90～90`。
- 继续执行用户级文件数、单文件字节数、单文件要素数和总要素数配额。

### 9.3 防滥用

- 每用户 10 分钟最多 5 次，两次请求之间至少间隔 2 秒。
- 每用户最多 1 个正在执行的两步路导入。
- 不做后台重试、批量队列和定时抓取。
- 相同 `requestId` 的成功请求返回同一文档，避免响应丢失后重试产生副本。
- 审计只记录用户 ID、结果、耗时、规范化主机、完整度、要素数和错误码，不记录完整上游正文或下载签名。

## 10. 数据转换

### 10.1 标准 KML

复用现有个人 KML 导入规则：

- 支持 Point、LineString、Polygon。
- 保留安全的名称、描述和 `styleUrl`。
- 坐标以 WGS84 保存，显示时按 `coordCorrection` 处理。

### 10.2 公开轨迹 JSON

- 每个有效轨迹分段转换为一个 LineString。
- 公开标注点转换为 Point。
- 标注文本写入名称或描述。
- 媒体 URL 仅接受 `down-files.2bulu.com` 的 HTTPS `/f/d1`、`/f/dn1` 公开端点，禁止账号密码、非标准端口和 fragment；查询参数只能包含非空 `downParams` 公开资源定位值，并通过现有 KML 富媒体安全展示链路渲染。
- 丢弃包含其他查询参数的媒体 URL，不将两步路内部用户 ID、Cookie、Token、`signature`、`captcha`、验证码参数或管理字段写入 KML。
- 所有分段和标注点都生成稳定、无冲突的本次导入内要素 ID。

## 11. 前端要求

- 两个入口使用同一字段、枚举和错误文案。
- 使用 `src/ui/dialog.js`，禁止 `alert`、`confirm`、`prompt`。
- URL 输入支持粘贴完整链接；提交前做轻量格式提示，但以服务端校验为准。
- 请求执行时禁用重复提交，并显示进度。
- 网络结果未知时，相同 URL 与导入选项必须在当前浏览器会话内复用原 `requestId`；确认成功后才释放，避免用户人工重试产生副本。
- 未登录和无写权限时从 DOM 交互层隐藏入口；服务端鉴权仍为最终边界。
- 地图页导入成功后复用服务端文档 ID登记账号同步快照，不能再次上传产生副本。
- 只导入轨迹线时必须展示警告，不得用普通成功提示掩盖数据缺失。

## 12. 测试要求

### 12.1 纯函数和服务测试

- 三种支持 URL 形态及多重编码分享标识。
- 非 HTTPS、错误主机、IP、端口、账号密码、错误路径和超长标识。
- 分享页直接 KML成功。
- 公开 JSON 的多轨迹分段和标注点转换。
- 坐标非法、空轨迹、HTML/WAF、登录/验证码、加密二进制、超时、超限和重定向越界。
- 部分导入默认拒绝，显式允许后成功并返回警告。
- 同用户限流、并发锁和 `requestId` 幂等。
- 文件/要素配额和危险 KML 继续由现有服务拒绝。

### 12.2 API 测试

- 未登录 `401`。
- 只读用户 `403`。
- 合法用户成功并返回 `importSummary`。
- 服务异常映射为稳定中文错误码，且响应不包含上游正文和敏感字段。

### 12.3 前端测试

- “我的 KML”和 2D 地图面板存在入口。
- 入口只在具备个人 KML 写权限时显示。
- 不使用浏览器原生阻塞弹窗。
- 地图导入成功后登记服务端文档，避免同步重复创建。

## 13. 验收标准

- 已登录且具备写权限的用户能从两个入口粘贴合法两步路链接。
- 在上游提供无需登录/验证码的标准 KML 或明文公开轨迹数据时，系统可创建个人 KML。
- 未登录用户看不到入口，直接调用接口也不能触发任何外部请求。
- 对要求登录、验证码、WAF 或加密响应的链接，系统给出明确降级提示且不创建数据。
- 默认不静默导入缺失标注点或媒体的轨迹；显式允许部分导入时返回 `track-only` 和警告。
- 外部请求不存在任意 URL 代理、内网访问、无限重定向、无界响应或敏感信息回传。
- 相关 `node:test`、`npm run check`、`npm test` 和 `npm run build` 通过。

## 14. 后续演进

1. 优先与两步路确认官方 API、授权范围、限流和数据使用条款。
2. 获得官方接口后增加 provider 版本和健康检查，替换历史公开接口。
3. 根据官方格式扩展 GPX/KMZ、海拔、时间序列和媒体完整导入。
4. 在明确授权和稳定契约后再考虑批量导入、更新检测和管理员级适配器开关。
