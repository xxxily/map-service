# KML 多设备编辑冲突合并

## 1. 文档状态

- 状态：已完成
- 适用版本：下一版本
- 范围：登录用户在多个浏览器、设备、SidePanel 或前后端页面中编辑同一账号 KML 的保存、恢复和冲突处理。
- 非目标：不实现实时协同光标、在线锁定、服务端无条件覆盖、无审计的静默丢弃。

## 2. 背景与问题

现有 KML 使用文件级 `revision` 乐观锁。客户端只保存文件指纹，不保存产生指纹时的完整内容；任一设备先保存后，另一设备提交旧 revision 就会收到 `409 KML_REVISION_CONFLICT`。当前处理只能整文件加载服务器版本或整文件另存副本，导致两个设备修改不同点位、不同字段时也被当作不可解冲突，用户被迫丢弃一份数据。

典型场景包括：

1. 设备 A 修改点位名称，设备 B 新增另一个点位。
2. 电脑端修改轨迹描述，SidePanel 修改资源集合中的图片地址。
3. 一台设备调整文件显示配置，另一台设备编辑文件内要素顺序。
4. 网络延迟、页面关闭或会话恢复导致旧草稿再次提交。

## 3. 目标与成功标准

### 3.1 目标

- 保存前保留可用于三方比较的基线：基线、当前本地版本、当前服务器版本。
- 对互不相交的修改自动合并并自动重试一次，用户无需介入。
- 以稳定的 KML 文件 ID、要素 ID、资源项 ID 识别对象，不通过数组下标判断同一对象。
- 只有同一字段、同一要素删除与修改、或同一顺序被两端不同修改时才进入人工处理。
- 人工处理按冲突项提供“保留本地/保留服务器”选择，其他已自动合并的数据保持不变。
- 页面关闭、SidePanel 销毁、会话过期后，草稿仍可重新计算冲突，不因恢复流程再次丢失数据。
- 保留现有 revision、CSRF、权限、事务和分享快照发布规则。

### 3.2 成功标准

- 不相交修改冲突自动合并成功率达到 100%（以自动化场景覆盖为准）。
- 自动合并成功后，使用服务器最新 revision 提交，最多自动重试一轮，不产生无限重试。
- 同字段真正冲突时，服务器版本、本地版本和基线值均可在处理界面识别；取消处理不会丢数据。
- 多文件批次中，一个文件冲突不会改变其他文件的本地草稿；处理后可继续同步。
- 旧版本没有完整基线的草稿继续可恢复，但必须降级为安全的文件级处理并明确提示。

## 4. 数据与合并模型

### 4.1 三方输入

- `base`：客户端最近一次确认保存或加载的完整 KML 内容。
- `local`：当前设备待保存内容。
- `server`：收到 revision 冲突后重新读取的服务器内容。

客户端快照继续保存 `serverId`、`localId`、`revision`、`hash` 和状态，并新增受控的 `base` 内容。完整草稿以 IndexedDB 为主；序列化长度不超过 750000 字符的小草稿允许同步保存包含 `snapshot.base` 的完整 localStorage 副本，超限时 localStorage 只保存代次元数据，完整恢复必须回到 IndexedDB。不得为减小草稿而裁剪基线、Feature 或资源项。

### 4.2 字段合并规则

对任意字段 `F`：

| 条件 | 结果 |
| --- | --- |
| `local == server` | 保留该值 |
| `local == base` | 采用服务器值 |
| `server == base` | 采用本地值 |
| 三者均不同 | 生成一个字段冲突，默认保留本地值等待选择 |

文件级字段包括名称、介绍、默认状态、坐标纠偏、主题、颜色、拖拽锁定、启用状态和实时轨迹状态。坐标数组、富文本和未知扩展按字段整体比较，不进行未经验证的字符或顶点级拼接。

### 4.3 要素和资源集合

- `features` 按稳定 `feature.id` 做集合三方合并。
- 两端各自新增不同 ID 的要素自动保留。
- 一端删除、另一端未修改时按删除处理。
- 一端删除、另一端修改同一要素时生成“删除/修改”冲突，不自动复活或丢弃。
- 同一要素的不同字段修改自动合并；同字段不同值才冲突。
- `resourceCollection.items` 按稳定资源 `id` 使用相同规则合并；集合布局字段 `viewMode` 按普通字段规则处理。
- 同一数组的两端顺序都发生变化且结果不同，生成顺序冲突；只有一端调整顺序时自动采用该顺序。新增项在双方顺序无法推断时按本地新增顺序、服务器新增顺序追加，保证项目不丢失。
- 同 ID 的同时新增且内容不同视为字段冲突，不生成第二个相同 ID。

### 4.4 文件新增、删除和跨文件操作

- 两端新增不同 `clientId` 的文件自动保留。
- 文件本地删除而服务器未修改时继续删除；服务器修改后生成文件删除冲突。
- 跨文件移动/复制以要素 ID 和源/目标文件 ID 识别；源文件删除与目标文件新增不自动互相抵消。
- 默认 KML 的保护规则不变；默认状态冲突进入人工处理，不通过合并绕过服务端校验。
- 切换默认 KML 的同步批次必须先创建或更新新的默认文件，再提交旧默认文件的普通更新，避免中间状态触发默认文件保护。目标文件仍在回收站时先单独恢复，下一批再完成默认切换。
- 服务器已永久删除的文件若选择保留本地，必须以新 ID 创建副本；该文件同时被选择为默认文件时，账号级默认选择必须映射到新副本 ID。

## 5. 保存流程

1. 用户编辑后按现有节流规则写入本地恢复草稿，草稿包含完整工作文件、快照基线、删除墓碑和在途操作。
2. 提交 `/api/v1/kml/sync`，继续携带基线 revision。
3. 服务器返回成功：按现有事务响应更新快照和基线。
4. 服务器返回 `409 KML_REVISION_CONFLICT`：客户端重新读取当前服务器 KML，执行三方合并。
5. 合并无冲突：以服务器最新 revision 生成 update 操作，自动提交一次；成功后清理草稿。
6. 合并有冲突：保留自动合并结果和冲突清单，暂停自动提交，打开统一冲突处理界面。
7. 用户逐项选择后重新计算完整文件并提交；如果期间服务器再次变化，重新读取并从最新基线再合并，不覆盖用户当前选择。
8. 网络错误、401、CSRF 错误或草稿写入失败不触发自动覆盖；沿用当前恢复和会话失效策略。

自动合并最多自动重试一次。再次发生 revision 冲突时保存 `retryExhausted` 状态并进入人工确认；用户可确认再次保存最新合并结果，也可加载服务器版本、另存本地版本或稍后处理。页面刷新后重新读取服务器并重新计算合并，只继承“已自动重试过”的状态，不复用旧冲突结果。

## 6. 冲突处理交互

- 标题显示“已自动合并 X 项，仍有 Y 项需要确认”，其中 X 只统计实际协调的字段、文件、Feature、资源项或顺序变化，不统计未变化对象。
- 冲突按文件分组，再按字段/要素/资源项展示；每项显示简短路径和本地、服务器值。
- 提供“保留本地”“保留服务器”两个明确操作；已自动合并项不可被误覆盖。
- 提供“暂不处理”，保留当前草稿并暂停同步；关闭弹窗不等于丢弃。
- 提供“加载服务器版本”和“本地版本另存为新 KML”作为兜底，不删除原草稿。
- 处理期间禁止使用原生 `alert`、`confirm`、`prompt`，统一使用 `src/ui/dialog.js`。
- 冲突数量、文件名、字段路径和下一步动作使用克制文案，不枚举平台或未来支持清单。

## 7. 兼容、安全与性能

- `/api/v1/kml/sync` 路径、请求格式、鉴权和 revision 语义保持兼容，不降低服务端校验。
- 合并结果仍经过服务端完整 normalize/validate/quota 校验，服务端拒绝时保留草稿。
- 不信任客户端传入的 server 内容；服务器内容只来自同源认证 API。
- 合并只在 revision 冲突或草稿恢复时执行，不影响普通平移、缩放和地图渲染热路径。
- 大文件合并按文件和要素 ID 建立 Map，避免嵌套全量扫描；单次合并设合理对象数量和时间预算，超出时降级为文件级人工处理。
- 合并诊断只记录计数、耗时和结果码，不记录 KML 内容、媒体地址或隐私字段。

## 8. 接口与草稿契约

无需新增公开 API。`KML_REVISION_CONFLICT` 保持原错误码；客户端通过已有 `GET /api/v1/kml/files` 和 `GET /api/v1/kml/files/:id` 读取服务器最新内容。

恢复草稿升级为 v2：旧版 v1 草稿或缺少 `snapshot.base` 的已同步文件不得猜测基线，自动合并标记为不可用并提供加载服务器/另存副本；新草稿保存 `snapshot.base` 和精简的 `retryExhausted` 状态，不持久化可过期的服务器副本或冲突结果。没有 `serverId` 的本地删除墓碑不视为缺少基线。

## 9. 测试与验收

### 9.1 纯函数测试

- 不相交顶层字段、要素、资源项自动合并。
- 同字段不同值生成冲突，选择本地或服务器后结果准确。
- 双方新增、单边删除、删除与修改、同 ID 同时新增。
- 要素和资源项重排：单边重排自动合并，双边不同重排产生顺序冲突。
- 多文件新增/修改/删除与默认文件保护。
- 已有文件、新建文件或回收站恢复文件切换为默认时，同步阶段与操作顺序符合服务端默认保护；永久删除文件另存副本后仍可承接本地默认选择。
- 旧草稿无基线时安全降级。

### 9.2 同步与恢复测试

- 409 后自动重新读取、无冲突自动重试一次并更新 revision。
- 自动重试再次 409 时暂停且只保留一份草稿。
- 冲突处理取消、刷新和会话过期不丢本地内容。
- SidePanel、普通标签页和多设备草稿隔离。
- 批次中多个文件只有部分冲突时，非冲突修改仍保持在草稿中。
